# Migrating to 1.0.0 canonical routes

Router 1.0.0 is a breaking HTTP-surface release. Every endpoint has exactly one
role and one path. Legacy aliases return a local `404` regardless of the
credential supplied; Router never forwards them upstream.

Provider credentials, OAuth sessions, token stores, and subscription
authorizations do not need to be recreated. The migration changes Router URLs
and generated client configuration only. Token stores written before 0.125.4
remain readable.

## Route migration

| Before 1.0.0 | 1.0.0 |
| --- | --- |
| `GET /health` | `GET /api/health` |
| `GET /health/subscriptions` | `GET /api/management/health/subscriptions` |
| `/api/tokens*` | `/api/management/tokens*` |
| `/api/providers*` | `/api/management/providers*` |
| `/api/login*` | `/api/management/login*` |
| `/v1/usage`, `/v1/accounts`, `/metrics` | `/api/management/usage`, `/api/management/accounts`, `/api/management/metrics` |
| `/api/admin/*` | `/api/management/admin/*` |
| `/v1/messages*`, `/api/anthropic/v1/messages*`, `/api/latest/anthropic/v1/messages*` | `/api/services/anthropic/v1/messages*` |
| `/v1/chat/completions` | `/api/services/openai/v1/chat/completions` |
| `/v1/responses` | `/api/services/openai/v1/responses` |
| `/v1/models` | `/api/services/openai/v1/models` |
| `/api/codex/v1/*` | `/api/services/codex/v1/*` |
| `/api/qwen/v1/*` | `/api/services/qwen/v1/*` |
| `/api/gemini/v1beta/*` | `/api/services/gemini/v1beta/*` |
| `/api/vertex/v1/*` | `/api/services/vertex/v1/*` |
| `/api/bedrock/*` | `/api/services/bedrock/*` |
| `/api/github/*`, `/git/*` | `/api/services/github/api/*`, `/api/services/github/git/*` |
| `/activitypub/*` | `/api/services/activitypub/*` |

The configured client bases are now:

| Client/protocol | Base URL |
| --- | --- |
| Claude Code / Anthropic | `<origin>/api/services/anthropic` |
| Codex / Responses | `<origin>/api/services/codex/v1` |
| OpenCode, Agent, Grok / generic OpenAI | `<origin>/api/services/openai/v1` |
| Qwen Code | `<origin>/api/services/qwen/v1` |
| Gemini | `<origin>/api/services/gemini` |

## Upgrade procedure

1. Update health checks, reverse-proxy allowlists, SDK base URLs, automation,
   and management API calls using the table above.
2. Keep saved server selections as an origin such as
   `https://router.example`; command-specific endpoint builders append the
   namespace.
3. Rerun `router configure --all`, or run `router clients setup <client>` for
   each locally managed client. This preserves unrelated settings and does not
   reauthorize a subscription.
4. Inspect ownership with `router clients list` and
   `router clients repair --all --dry-run --json`. Repair individual conflicts
   explicitly; restart Claude Code afterward so it refreshes its gateway
   catalog without deleting the cache.
5. If using separate listeners, expose the service routes only on the public
   inference listener. `/api/management/*` exists only on the admin listener;
   that listener does not serve `/api/services/*`.

Rollback of a client repair uses only the opaque ID returned by the command:

```bash
router clients repair claude --rollback <BACKUP_ID>
```

The rollback refuses to overwrite edits made after repair. Snapshots live
under `$XDG_CONFIG_HOME/link-assistant-router/repairs/` with owner-only
permissions and do not put secret values in their manifests or command output.

## Catalog behavior

Router starts an account catalog empty, discovers every page through the
provider's authenticated non-inference endpoint, preserves unknown metadata,
and persists only successful account-scoped results. Missing, revoked, or
unhealthy credentials fail closed. Each exact model ID has exactly one owner.
If catalogs from different providers advertise the same exact ID, the catalog
merge fails explicitly; Router does not invent or expose provider-qualified
aliases. Without a collision, the unchanged provider model ID is used for
upstream dispatch and audit.

Claude Code 2.1.255 or newer is required for current gateway aliases. Temporary
and managed launches enable live gateway discovery and clear conflicting public
credentials and family pins within their owned scope. Native Anthropic catalogs
leave model selection to Claude Code. For a z.ai-only catalog, current Claude
Code cannot resolve its Default/main-turn and subagent fallback from discovery,
so Router pins only those two boundaries to the first exact live z.ai model; an
explicit z.ai `--model` overrides both. Router never creates provider prefixes or
maps that model onto the Opus, Sonnet, or Haiku family choices.
