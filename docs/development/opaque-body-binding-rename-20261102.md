`proposeOpaquePairedBindingRenameInverse` extends the edit toolbox beyond scalar
and operator cells. It proposes local/parameter identifier changes using a fixed
original whole-project capture, complete Rust source candidates, and fresh actual
original/native-candidate/adopted checks. Both complete authored JS/TS projections
must exactly equal the independently emitted changed native project. It installs
nothing. Full translation/synchronization and all execution remain unfinished.

The fixed API accepts only configuration and complete authored JS/TS with an
explicit authority language. It accepts no capture, verifier, candidate callback,
public success flag or source/type proof. DATA helpers can propose source edits
from caller-built fixtures; they grant no compiler/source/ownership admission.
Only the direct fixed fresh compiler call supplies actual original associations.

## Reusable language and repository rules

The language sequence transports/reparses both whole authored targets as CST,
captures the actual whole original/native/adopted baseline, identifies consistent
binding/reference token changes, prepares original physical Rust token edits,
then independently checks the changed complete graphs. No public name or hash
acts as authority. Genuine type/effect/ownership/caller checks remain the original
compiler's responsibility. Source epochs are shared through WithContext calls;
no stale or nested replacement universe is manufactured.

The repository sequence retains full Rust/JS/TS before/after CST/inverses, physical
paths and exact authored peer agreement. It preserves complete admission/refusal/
method census and the original source universe. The inverse has six actual
project attempts; an independent receiving sampler adds three fresh attempts,
for nine total. Every old numeric/scalar API, source snapshot and case remains.
No new source receipt survives the original operation and no verdict cache exists.

## Supported syntax and explicit refusals

Up to256 consistent binding groups and4096 changed target/native token edits
can use ordinary ASCII identifiers in unique top-level actual emitted functions.
Each target binding must be declared once, every same-spelling binding/reference
must change, and the replacement must be absent. Nested functions/closures,
destructuring, property/shorthand/label/callee-only changes, target/native shadowing,
new-name capture and incomplete references refuse. Full nonidentifier source,
comments, written types and module structure stay exact. Mangled/raw identifiers,
methods and owners lacking an actual checked body-origin relation remain gaps.

The native candidate joins an actual captured owner to one unique original and
adopted top-level Rust function, selects a real original parameter or let binding,
refuses new-name/member/macro ambiguity and emits exact original spans for the
whole binding. Candidates alone are never a semantic theorem. Final independent
whole native checks and exact JS/TS reproduction remain mandatory and may refuse
apparently plausible lexical changes. The current owner association reuses the
numeric origin census, so functions with no scalar/operator origin are explicitly
unsupported. This is not a complete generic alpha-renaming proof.

Parameter edits through authoritative JS additionally need unchanged nonidentifier
comment syntax; emitter JSDoc parameter-name changes may refuse. Authoritative TS
can infer parameter token edits while the separately authored complete JS peer
includes its exact regenerated comments. The fixed production sampler selects
one referenced local, not a parameter, without guessing or skipping a failed
source check. It never fabricates a miniature production fixture.
