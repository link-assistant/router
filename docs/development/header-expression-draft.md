# Shared genuine header equality expression source draft

All new implementation and independent cases are UNRUN. Only source construction
and review occurred. No captor, parser, reader, invocation handler, translator,
preparer, test, experiment, generation, local Rust tool or CI-triggering push ran.

One separate private equality-expression family accepts genuine item,
function-parameter/generic and data-field/variant header receipts. The exact
five-field request retains its domain, original header token, parent token,
options object and selector object. Actual private header readers rejoin each
parent/source/profile/native/CST association. The complete existing positive
header AST must contain an Equality argument with an actual private expression
node in that same parser; a public AST, span or name supplies no permission.

The expression receipt reuses that exact positive AST and preserves original
value spans, comments, complete source and serialized/reparsed physical CST.
No expression is rendered or reparsed from caller-provided output. Every read
retains the original request field identities and rechecks its genuine header
parent, AST/parser identity, native source plan and physical source. Existing
header/function/attribute-expression families stay distinct. Existing combined
source, token, node and depth bounds remain; no source or verdict cache crosses
operations.

Seven complete original attribute invocation-position/input/expression issuer
and reader routines are copied into new private maps. They retain actual
Expr/Ty/Stmts macro positions and original invocation paths and token trees.
Expression capture requires one exact contiguous sequence of those original
tree objects and complete positive expression EOF. A first-tree identity check
avoids needless full comparisons while preserving the original matching and
refusal semantics. This is a structural draft, with no measured speed claim.

These source receipts qualify neither builtin/macro ownership nor native parser
legality, value semantics, visitor confinement, generated import/proc-stub
locality, unchanged enclosing bindings, exports, type or runtime behavior. All
such authority stays false and global macro effects remain pending. The existing
concat/include-str consumers still require their own explicitly adapted receipt
paths and actual owner/context/effect qualifications.

Three complete compiler source equations preserve original issuer/reader
bodies, native owner spans, ordered language/repository substitutions, CST/meta
boundaries and whole inverses. Independent unrun cases cover all header domains,
inner items, method receivers, generic parameters, macro source/argument capture,
all three expansion positions, private family/getter/tree refusal and source
changes. Full production lowering, macro/global closure, parity, reverse/sync,
freshness/CI and receiving qualification remain unfinished.
