# Parked whole-owner source CST grouping draft

`prepare-whole-owner-source-cst-batch.mjs` proposes four separate complete source copies. The first two contain a potential grouping of all8 original derive rows and all3 resolver rows; the others only relocate Core/corpus producer imports. The original8/3/3/6 preparers remain available. **Batch selection is disabled**: each receiving copy calls the exact original preparer before any original input Hash/native work. Comparisons of these copies currently establish fallback behavior only, not execution or qualification of grouped transport.

The audit found a genuine missing boundary. The official Node crypto guard rejects preexisting Hash wrappers, including a wrapper that transiently installs and later restores JSON or TypeScript hooks during original input hashing. It does not close the separately mutable shared TypeScript5.9.3 provider. Native source inspection of the installed9,112,572-byte compiler (SHA256 `3ae902c92cc44dace175c0e69e13a4b0899f6983c6121d76b9ab8dd5795e7675`) shows exported `objectAllocator`, `setObjectAllocator` and mutable factory/allocator callables. Callable identity and a compiler-file hash cannot establish arbitrary prior hidden closure state. No such census is promoted to callback-free proof. There is no retry/replay after entered original input Hash work, no caller flag that grants eligibility, and no claim of arbitrary cold/shared compiler observer equivalence.

The normal `deriveBatchedProofByteAdapterSources()`, `prepareBatchedProofByteSourceCandidate()` and CLI retain the exact currently materialized dispatcher-only5 output equations and5-path provider input census. Normal freshness does **not** require the four draft copies or helper. The authored source can still change as a fresh full input; its generated path list and existing default adapter source bodies remain unchanged.

The upstream proposal is isolated behind `deriveBatchedProofByteUpstreamAdapterDraftSources()` and `prepareBatchedProofByteUpstreamSourceDraft()`. These return explicit DRAFT DATA with `defaultWritesAllowed:false`, `compilerClosureQualified:false` and no source/runtime authority. There is no CLI write route for that upstream profile. Its source history retains the exact dispatcher-only beforeimage and independent native inverse. It is not a mandatory current/default freshness layer.

The parked native source transformation retains the original row property order, native binding result, before/language/after text, original rule IDs, selection metadata and final input Hash loops. Its potential transactions preserve both serialized/reparsed language and repository phases, canonical per-phase inverses and composed full inverse, with groups of at most3 and every existing budget. The old two-entry trace is derived from the checked active phase entries; inactive entries must be empty. No AST/checker, digest, result or verdict is cached across invocations. These source equations alone do not justify enabling execution.

For source/receiving controls only, Root may materialize the four parked copies under its existing shared monitor:

node tools/translation/prepare-whole-owner-source-cst-batch.mjs --check
```

The separate current/default commands continue to check only the existing qualified dispatcher-only producer equations:

```

It compares every field of all8 and all3+nested8 results, native/CST full source and inverse fields, complete RegExp static state, source corruption and nested mutation controls. Independent old/new cold children retain original12500ms/64MiB limits. Additional children install a transient JSON or TypeScript allocator hook from the first input Hash callback, retain the complete callback tape and full result/error, restore the actual descriptor, and compare full wires. A direct visible TypeScript provider replacement also must take the original pipeline. The complete case remains60000ms. New controls and materialization are **unrun**.

That preserves native-row/CST order without replaying native work and would avoid claiming the entire shared compiler is callback-free. It is not implemented or adopted here.
