Two complete original tool constructors now have separate registered-builtin
variants. They retain the original private tool context/certificate issuer,
provisional candidate isolation, complete module/external source inputs, active
ancestor and type-prefix checks, disabled-prelude refusals and exact source
association. Their baseline resolver selects the full written builtin parser,
AST, registry and collector source path. Original tool constructors remain.

The explicit tool-first derive input constructor selects the registered initial
tool context and matching resolver. Its whole-module and requested original item
attribute scans call a fresh written builtin source frame for each requested
candidate; unknown attributes and all original import/binding conflicts remain.
The selected enclosing project uses the registered complete-output tool variant;
the default project and default derive input constructor retain their domains.
A returned source flag or externally supplied tool context cannot select proof.

This composes a root function's independent stability/tool prerequisites with a
child derive input. It does not establish any unproved same-scope tool/derive
cycle, architecture glob/type-prefix export closure or arbitrary producer.
Derived inputs with unsupported extra layout/helper/source attributes still need
their separate actual output rules. Existing private source joins, complete
original bytes, native output owners and generated type/value obligations stay
required. No new across-invocation cache is introduced.

sequences and full CST inverses are retained. Independent original API, root
proof/child derive, complete output, source/view/profile/external changes,
forbidden supplied proof, shadow/glob/unknown/cycle, selected project and native
ordinary tool/derive oracle source cases are drafted and unrun. No compiler,
test, experiment, preparer, translator, generation, Rust tool, push or CI ran.

requirements remain open.
