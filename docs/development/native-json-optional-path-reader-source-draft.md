# Optional JSON reader source adoption draft

The additive `proposeNativeJsonOptionalPathReader` and plural batch API compose
the finite literal path-search proposal with a straight-line optional parser
and required child reads. The actual catalog `resource_error_code` function is
an independent source selection. Its production implementation is unchanged.
All implementation, receiving cases, oracle cases and source equations are
UNRUN. Complete source drafting, original semantic qualification, installation,
forward/reverse freshness, full Router parity and delivery remain OPEN.

The first child pipeline is the existing literal-path transformation. The
second has its own ordered `language` and `repository` phases. Language rules
replace selected `serde_json::from_str(input).ok()` and required literal-key
`.get()` expressions with fresh symbolic intrinsics. Repository rules bind
only the generated identifier call tokens to `translation_core::json_parse`
and `translation_json_fields_core::json_field`. The path rules reuse existing
typed field APIs. No new native core API or native-root history is introduced.

Each original, intermediate language result and complete final module crosses
the serialized and reparsed CST/meta boundary. The two child pipelines retain
their actual chronology and complete original/final source equations. Child
pipeline order is not flattened into a fictitious single language/repository
trace. Prefix coordinates explicitly refer to the original module before tail
expansion; the complete unchanged prefix is checked before applying those
coordinates to the intermediate module. Every source inverse retains comments,
literal spelling, whitespace and unaffected sibling functions.

The current lexical grammar admits one immutable parse local, zero through
sixteen immutable child locals, and one complete tail search using a selected
live root. Parse operands are single identifiers. Child keys are original
bounded string or raw-string literals. The first child borrows the owned JSON
local; subsequent children forward their existing shared JSON references.
Question marks remain in their original statements. Optional results are bool,
u64, i64 or owned text. Returning text borrowed from the local parsed JSON is
refused. Mutation, local shadowing, extra statements, dynamic keys, arbitrary
callbacks, generic parse syntax, attributed functions and opaque producers
remain outside this proposal grammar. This is a deliberate source rule domain,
not a declaration that all valid Rust readers have this shape.

Complete input/output modules keep the existing 2 MiB and fewer-than-1,000-line
bounds. A batch has at most 32 modules, 128 explicit unique selected functions
and 8 MiB total original source. Metadata uses iterative cell/depth/text bounds
of 16 Mi UTF-16 text units per composed proposal and 32 Mi per batch. These are
construction bounds, not measured peak RSS or timing claims. All maps and source
selections are invocation-local; no across-operation cache is introduced.

Names, qualified spellings, descriptor-safe selections, CST spans, source hashes
and retained inverses are DATA. They do not establish original serde namespace
or method identity, type ownership, body equivalence or runtime authority.
Every proposal retains false original-equivalence, installation, receiving and
parity flags and requires whole original semantic reissue. No production caller
may receive a permit merely because a rewrite is constructible.

Independent JS source cases cover four result families, chained borrows, raw
Unicode keys, collisions, complete source batches, refusals, caller descriptor
hazards and implementation source equations. A receiving case takes the actual
proposed complete catalog reader into an explicit root kernel through its own
CST visibility substitution, retains that adaptation's inverse, and requires
JavaScript plus strict TypeScript to match independently written JSON results.
It does not qualify the original parent module or crate. Independent Rust oracle
source compares the actual original catalog reader with paired-core expressions
across priority, empty/whitespace/Unicode/NUL strings, typed fallback, duplicate
keys, numeric extrema, malformed JSON and absent/wrong-shaped parents. Rust
execution remains CI-only after every required same-SHA JavaScript stage passes.

The reusable source preparer is
`prepare-native-json-optional-path-reader-sources.mjs`. Its complete frozen
originals, pinned substitution archive, predecessor composition and unchanged
original preparer APIs retain both source phases and full inverses. Execution
and all freshness checks are deferred until the entire requested bulk draft
exists; the continuing no-local-compilation instruction remains in force.
