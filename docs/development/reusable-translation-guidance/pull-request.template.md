# Pull request description template

Use the repository's required PR template first. Adapt the following fields;
do not copy another repository's publication authorization, case results or SHA.
A draft PR can contain a coherent unfinished source checkpoint. Its description
must state that boundary and preserve the complete original requested objective.

[Concrete problem and resulting behavior in one short paragraph. If useful,
include one actual before/after trigger. Name the original tracked source or
qualified compatibility boundary rather than claiming fixtures are production.]

Current source checkpoint: `[FULL_SHA]`. Branch: `[BRANCH]`.
Linked issues: [original objective and continuation issues; keep open while work
remains]. Phase/activity: [source drafting / authorized verification; active /
explicitly paused and controlling instruction date]. Publication: [UTC time,
sole publisher and exact remote result].

This checkpoint drafts [specific complete narrow families]. The full translation
and complete bulk source draft [remain unfinished / are source-complete with all
linked receipts]. Default domains, unsupported producers/types/owners/platforms,
intentionally untranslated libraries and incomplete adoption remain explicit:
[list concrete limitations]. A source-complete statement requires every actual
source requirement and scope entry to have its complete receipt.

Source changes:

- [Original source/CST → checked serialized/reparsed meta → actual JS/TS/native

  checks and separately declared language/repository rule sequences].
- [Shared operation descriptions/rules and automated caller adoption; retained

- [Independent whole case source, strict target/native oracle source and actual
  receiving/export paths; distinguish authored source from completed runs].
- [Synchronization/conflicts/rollback, authored overwrite protection, fixed
  resource/deadline/platform/exclusive-writer boundaries where applicable].

Requirement tracking: [N/M source receipts, unweighted; exact ledger link].
Open IDs: [complete list or exact committed ledger section]. Scope change:
[none, or explicit additions and denominator change]. No implementation or
coverage percentage follows from the unweighted requirement count.

Validation: [actual completed scopes, exact SHA, commands, installed compiler/
runtime versions and retained raw receipts; keep failures]. Deferred scopes:
[UNRUN commands and reason]. CI feedback: [uninspected when inspection is
prohibited; otherwise complete actual inspected run scope and SHA]. Do not infer
a pass from a source audit, workflow presence, empty failure list or uninspected
CI. Do not query prohibited feedback to populate the description.

All original fixed commands, full files/workloads, matrices and deadlines remain
required. All required JS stages must pass at the same immutable SHA before
native CI, whose failures remain fatal. Record missing/skipped/cancelled work
explicitly. Local-tool prohibitions persist until the receiving user changes
them. Source drafting never implies a local compiler/test permission.

Resources/cleanup: [last disk observation; exact task-owned cleanup and recovered
bytes, or none; retained recovery/diagnostic paths]. Handoff: [exact committed
path/link, local and published SHAs, outstanding owners/sessions, active versus
explicit pause/resume state and concrete next requirement batch].

Merge/release readiness: [actual authorized state and independently completed
coverage/parity/freshness/receiving/performance/CI evidence, or explicitly not
established]. Do not close the original objective at an unfinished checkpoint.
A periodic push, merge, template or handoff is not verified delivery.
