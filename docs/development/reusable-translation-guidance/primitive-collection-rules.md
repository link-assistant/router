## Fixed rule layers and representations

Declare exactly language followed by repository phases; empty rule lists are
valid. Reusable language rules preserve actual source name/type/ownership,
evaluation, integer and error contracts. Repository rules choose application
imports, physical rust/src, js/src and ts/src layouts, names and formatting
without inventing missing semantic permission. Substitutions may operate on
parsed source, checked semantic meta or target syntax; text replacement alone
is not a semantic checker. Keep complete original and target source equations.

Serialize and reparse lossless CST/meta before reconstructed text enters the
independent semantic parser. Keep concrete source, checked semantic programs
and target packaging distinct. Token spans, source hashes, rule IDs, catalog
rows, public flags and preserved source are DATA, not executable admission.
Every edited source receives fresh private whole-function checks in both
Rust-to-JS/TS and JS/TS-to-Rust directions. A canonical inverse must reproduce
the entire authoritative native source after that fresh reissue.

## Paired library boundaries

An intentionally untranslated core can expose equivalent operations in both
languages while native framework internals remain native. Qualify complete
actual source, active module/namespace binding, public ABI, ownership and
successful-resource behavior; an interface spelling proves none of these.
Ordinary dense arrays, frozen owned carriers, copied shared references and
Rust Vec values must not silently become interchangeable source contracts.
Keep fixed primitive widths exact, including bigint representation and index
bounds. A source literal argument cap and a runtime collection limit are
separate bounds and require independent cases.

Literal constructors evaluate each original operand once, left to right, and
produce fresh owned storage. Bulk source migration may explicitly change a
mutable-array or length representation contract, but must retain its original
source/inverse and false equivalence/installation status. A proposal is not
production adoption. Do not count library declarations as translated callers.

## Nested source substitutions

Use templates containing generated strings and explicit retained original
source spans. Compose nested edits only inside retained spans, once each.
Reject crossing or duplicate edits, stale expected bytes, repeated references,
dropped nested edits, invalid UTF16 boundaries, proxies/accessors and excessive
source/text/row/cell/depth budgets. Submit the resulting nonoverlapping edits to
the actual serialized/reparsed CST path and whole private source checker.
This lets one selected initializer or push operand contain another selected
local's length rewrite without hand-editing generated expressions.

## Whole helpers and synchronous loans

An actual signature can select a helper-checking route; it cannot qualify its
body. Rejoin the complete original caller/callee graph, actual native symbols,
entry guards and unchanged source/signatures. Retain bounded acyclic graph,
move, branch, loop, root-loan and emission dependency checks. Keep unsupported
foreign modules, escaping references and callbacks explicit. Do not flip an
old refusal or owner flag to bypass missing prerequisites.

A written shared operand must have its actual original parser borrow, parent
call, resolved parameter slot and checked pointee. A specialized new result
qualifier must independently rejoin those facts while preserving the original
generic API/refusals. Hold earlier argument roots throughout later argument
evaluation and the synchronous call. Reject both moves and writes while held;
restoring availability later does not repair the earlier conflict. Release
loans in finally on success/failure so later legal moves remain possible.

Share raw source/AST work only within one operation. A raw-parent index records
source nodes, never owner/type/verdict permission. Rejoin complete current
sources on every required exit, clear all operation references in finally,
and invalidate caught source failures. Introduce no across-operation source,
hash, owner, verdict, encoded-result or input cache. Keep original workloads,
deadlines, disk/evidence bounds and all required gates unchanged.

Automatic source discovery should reuse the actual substitution constructor,
retain unsupported observations and complete untouched modules, and distinguish
original coordinates from each current step's coordinates. Source-candidate
and proposal counts are not executable coverage. Compose full child pipelines
in their actual chronology; every child retains language then repository rules,
serialized/reparsed CST and complete inverses. Source installation and original
equivalence stay false until whole original semantic qualification exists.

Classify trusted source checks separately from application callbacks. Observed
input failures must invalidate every active source operation despite catch and
restoration, including closing failures hidden by an application primary.
Continue all closing checks while preserving exact primary identity, even for
null, undefined and symbols. Retain legacy API behavior through additive copies
when stronger failure/depth contracts would change the old callback domain.
Document shared aggregate frame limits and defer resource/performance claims
until measured qualification; no across-operation failure cache is allowed.

missing/tampered source, fake metadata and malformed template cases for actual
callers, emitted JS, strict TS, both interpreters, meta/CST reentry and canonical
native inverse. Do not derive expected results from the operation description
that generates the implementation. Add native oracle source through the public
core and reuse test crates when practical; never run Rust locally in this task.
