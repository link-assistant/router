# Cancellation source-unit synchronization draft

The `owned-cancellation` profile connects synchronous cancellation callers to
the existing physical JS, TS and Rust source-unit transaction. All source,
preparation, receiving cases and behavior remain unrun during bulk drafting.
General forward Rust application qualification and async resources remain open.

A complete copy of the original owned source-unit adapter now selects the
private cancellation context, JS/TS source checkers and canonical Rust inverse.
It requires the actual Cancellation native module in addition to every original
native boundary and locked Cargo input. Runtime trees include the full opaque
implementation and declarations, with byte-equal mirrors under both declared
physical runtime roots. Source/Cargo/runtime inputs remain protected from output
replacement. Profile dispatch and both closed manifest readers explicitly list
this profile; all original profiles keep their behavior.

JavaScript with missing input annotations can receive only the actual freshly
checked paired TypeScript borrow domain, expressed through the real is-set
operation's indexed `Parameters`. These annotations remain non-executable
proposals; the complete edited JS body must independently pass move and borrow
checking. Current TS authority removes stale paired JS before checking; current
Rust authority uses the canonical inverse and complete Rust reproduction.
The final return preserves semantic meta and complete signature/source histories.

Planning and application retain the original complete Git/current-source
conflicts, protected native mappings, full source inverses, fresh recomputation,
atomic installation and rollback. The existing runtime-only mode can install
opaque implementation assets without translating an unsupported application.
It does not qualify any caller, resource type, async future or native behavior.
No Rust tool or new CI path is introduced.

Complete original unit and signature adapters remain immutable physical source
snapshots. Ordered language/repository substitutions retain complete native
source selections, CST serialization/reparse and full inverses. The public
compiler facade exports the unit implementation and closes over its actual
source dependencies. Export inclusion remains separate from receiving success.

Independent unrun source exercises JS initialization, Rust-authority operation
edits, subsequent JS and TS control edits, actual opaque runtime identity,
