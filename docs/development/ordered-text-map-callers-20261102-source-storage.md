# Read-only source-profile storage draft

This is a separate source-storage domain. No original production module is changed by this packet. All execution, capacity qualification, compiler/type/body qualification, native parity, SDK composition and full receiving qualification are **UNRUN**.

The resource problem is concrete SCM/file-size DATA: a guaranteed selected compiler/profile/vendor/native subset contains 9,867 files and 222,999,703 raw bytes. Two simultaneously physical copies require 445,999,406 bytes, exceeding the original 402,653,184-byte full receiving bound before Git, vault, SDK or runtime outputs. Profiles account for 181,524,701 bytes in 6,279 files. These are source-size observations, not a compression trial or a claim that the new encoded profile fits.

The new bank retains every logical source as real Git objects and committed paths. All executable compiler code, Rust production inputs and selected native oracles remain physical, with real file identities. Only `tools/translation/source-profiles/` paths use real skip-worktree entries and a read-only compact vault. The current exact-source engine and its actual index127 remain physical. SDK inputs are a separate dependency and must remain physical; this draft does not include or qualify an SDK package.

The store joins its complete logical census to actual Git HEAD, tree, index, mode, blob and skip-worktree state. It rejects untracked profile paths, materialized cold files, symlinks, unknown metadata, missing files and changed/restored source identities. Descriptor, Git controls, compressed parts and ancestors have genuine no-follow FD/identity checks. Selected reads close their compressed parts and selected ancestors. Complete namespace, original file and ancestor checks run at operation boundaries and on failures. Exterior ancestors use stable directory identity; selected source ancestors retain complete clocks/link counts. Falsy and frozen primary errors survive all closers, and caught input failures poison their source scope.

The invocation frame shares immutable encoded model/index/census DATA. It retains no cross-operation verdict. Long-lived source handles retain original physical identity snapshots and source digests, then rejoin them in every fresh operation. The shared custody successor can retain only digest/identity DATA for a complete corpus, reading one source at a time instead of holding all decoded profiles. This is source custody, not parser, namespace, ownership, loan or type permission.

The consumer packet retains thirteen complete original modules, successors, inverses, hashes and two ordered rule sequences. The proposer transports both source sides through serialized/reparsed lossless CST. Seven original byte registries use the explicit byte adapter. Tracked-input discovery joins actual logical Git inputs under the original limits. Original source-operation frames close the compressed scope. Original map standard/ABI readers and shared canonical source custody retain distinct compressed handles instead of synthesized NodeStats. The exact-source engine keeps its current index127 and all original source equations; only its cold profile-image branch changes. All original private parsers and complete body/meta/source checks remain necessary.

The new producer exports the actual complete production compiler closure with tracked layout-aware Rust/Cargo/build inputs and both native oracles. It creates the real fixed-hot bank, proposes all thirteen source equations, installs complete afterimages, commits the actual local source tree as DATA, creates the separate complete profile store and rereads every logical profile. It retains and independently rereads the entire original selected corpus and original HEAD/index through the final outcome. Common protected-writer policy covers the complete fresh subtree, and all owned workspace roots count against the unchanged 384MiB cap. Setup remains bounded by the original sixty seconds; the source-bank operation retains its twenty-second limit. The installed target must start in a fresh process. No target imports occur after source installation in the producer.

The explicit compressed re-export module preserves the complete original physical exporter as its ancestry. Its new source domain reads cold profile bytes from the actual retained vault, checks their original committed blob identities, and closes the complete source scope after independently rereading every exported logical row. Native/code paths retain the original real FD/stat branch. The original exporter API and physical domain are unchanged.

The receiving case source imports the complete existing canonical and unit caller suites, then adds actual full-package, source identity, expiry, poison and replacement cases. Its existence does not schedule or qualify those cases. The reader inventory is lexical DATA only; a path or catalogue entry admits no source or type.

Remaining concrete work: the current SDK/full receiving driver at source baseline03234609d still uses the old all-physical main/unit producers, and its nested re-export workload therefore still refuses a cold compiler root. Its complete fixed workload needs an explicit source successor composing this new producer/re-export route and the complete physical SDK companion under the same all-owned-root cap and deadlines. The new receiver cannot claim complete compiler closure or successful forward/reverse execution until those actual paths are covered. No public flag, hash, source name or DATA descriptor supplies missing semantic authority.
