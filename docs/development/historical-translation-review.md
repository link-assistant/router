# Review a historical compiler baseline

A generated method's original compiler plan can change when the translator gains source support. Revalidating an old plan with current code can therefore reject a legitimate historical output. The draft reviewer keeps current metadata validation intact and uses an independently pinned historical graph only for a matching baseline.

The registered recipe selects the entire 720-entry compiler fingerprint map from generation commit `688bf9b9a1257a1dc58c758b50b6906ecc4eee63`. Those source files come from immutable compiler commit `3653dcfb8f49ac2d85239cadcd3d8e2233f2e57d`. The old reviewer has a separate pinned blob and SHA-256; its version is not inferred from an old report's head field. This canonical recipe supports the historical three primitive Default methods. Other compiler maps and profile inventories continue through existing validation, and unsupported histories can still be refused.

The helper verifies all 720 compiler files, package/profile inputs, 804 original Rust files and both Cargo inputs. It requires every one of the 2,653 canonical baseline outputs to match the immutable generation witness, including Git file kinds. Baseline source text, hashes, counts, body/proof metadata and output paths cannot be replaced by caller-supplied attestations. Historical reports can corroborate these facts, but they cannot authorize a body or bypass revalidation.

A bounded temporary graph contains about 10 MB of historical code and compressed profile sources. A fresh Node child invokes the unmodified old `reviewGeneratedMethods` against complete baseline metadata and privately reissues its actual Host/parser/body/compiler-plan checks. No original Rust is compiled or retranslated. Current metadata still runs current checks. The comparison uses the rows actually returned by historical revalidation, and reports its separate compiler/source/output provenance.

The loader checks exact imported bytes and restricts file imports to the verified graph. The original pinned `extensions/core.mjs` creates three virtual modules by executing its exact vendor substitutions; only imports from that actual core module receive private URL issuance. Caller, nested and foreign virtual imports are refused. Each virtual module's decoded size/hash and URL hash are recorded. Package/profile mutation, symlinks, escaping paths and copied/forged project rows are rejected. Loader/process environment overrides are removed, and child timeout, memory/output and graph byte budgets are finite.

Historical validation preserves `semanticAuthority: false`, `runtimeParity: false` and `rustExecuted: false`. Its three generated methods remain separate from original function and written-method denominators. A historical comparison does not grant a green gate stamp or permit publication.
