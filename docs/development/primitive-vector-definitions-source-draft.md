# Receiving-first primitive vector definition source draft

All code and cases UNRUN. The additive proposeOwnedPrimitiveVectorFunctionInsertion
API drafts JavaScript/strict TypeScript definitions returning bool/fixed-width
Vec values into an actual current empty native module. It is re-exported through
source-synchronization.mjs so reusable compiler exports include the new closure.
No native placeholders or saved native signatures establish the first ABI.

A separate explicit primitiveVectorDefinitions source profile requires both
complete existing primitive definition/operator profiles. It selects a copied
finite definition validator only after the private receiving checker reads the
actual paired or JSDoc return type. Vec integer elements need genuine precise
runtime aliases; a bare bigint array cannot choose a new Rust width. Empty
arrays retain the actual written result domain. Bool/fixed input domains and
all original source/runtime/type checks remain mandatory.

The existing scalar insertion API/validator remain unchanged. The complete
copied vector insertion procedure reissues the actual receiving module,
serializes/reparses source/meta, emits full native functions, checks the exact
new-function census and genuine native ABI, then runs complete native module
refresh and receiving re-entry. Current source/byte fences close the operation.
Outputs stay uninstalled proposals, with receivingExecuted/runtimeParity false.

Vector literals, bounded Boolean branches, immutable result moves, qualified
closed primitive operations and same-file new scalar/vector helpers share the
private checker. Every primitive Vec result is tracked as a move even when a
local callee uses another element width. Complete call graphs distinguish new
Vec definitions from original native Vec functions; cycles, moved reuse,
foreign/missing helpers and mismatched signatures refuse. Parameters cannot be
owned Vec, borrowed aggregate or arbitrary external types in this new family.

language/repository substitution phases, source/CST round trips and inverses.

distinct ownership, mixed scalar/Vec helpers, guarded failures, ten-function
