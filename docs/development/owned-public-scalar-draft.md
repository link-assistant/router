# Owned public scalar interface draft

The additive scalar module profile combines the existing checked owned bodies
with closed public TS string, number and boolean aliases. It copies the entire
existing scalar type implementation, owned public packager, forward/receiving
linkers and canonical inverse. Native source rules preserve every full original
and the separate language/repository CST equations.

Only the actual public scalar alias dependency closure enters the existing
scalar resolver. Unrelated private JSON aliases remain in the independently
checked original body and do not become primitive aliases. TypeScript output
retains the required scalar declarations and public type aliases; JavaScript
publishes value exports. Rust uses qualified String/f64/bool targets so public
alias names cannot redirect their own definitions through lexical shadowing.
Native symbols also rename internal TS aliases while preserving their public
export names, preventing collisions with emitted runtime type imports. Pure
type interfaces reproduce an empty canonical implementation and add no invented
executable functions or coverage.

The inverse reads exact canonical root type declarations alongside the private
implementation module and public function aliases. Both the full inner body and
the complete root, including every scalar declaration, must freshly reproduce
the actual authoritative Rust. Unknown type targets, duplicate aliases, private
or extra root declarations, keywords and unsupported type shapes refuse.

Six complete original source copies and independent public API, changed-type,
whole-root inverse, strict TS consumer, source/refusal and history regressions
are drafted and unrun. The later [project integration draft](owned-scalar-unit-draft.md)
connects closed scalars to JS-authority preservation, Rust type edits and
receiving module trees. Owned, generic and compound public types, full reverse
type identity preservation, receiving
qualification and all other unfinished issue requirements remain open.
