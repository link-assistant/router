# Finite literal JSON path source adoption draft

Three complete source equations draft a reusable source-adoption rule for a
selected Rust function's finite path-table into_iter/find_map/try_fold readers.
It handles bool/u64/i64, borrowed text and owned text allocation through existing
qualified field operations, with path depths one to four and up to 64 paths.
No new native core API is needed. Source spelling selects a proposal only; it
cannot qualify original Iterator/get/str traits, source owners or executable
application behavior. Whole original semantic reissue remains mandatory.

The language sequence retains complete original CST and expands ordered literal
paths to optional field intrinsics. The repository sequence binds only fresh
intrinsic identifier tokens to the actual Router field core. Generated locals
and intrinsic names avoid every original identifier. Key literal source,
priority, Some(false), Some(0), empty strings and unmodified surrounding source
are retained by construction. Serialized/reparsed CST and exact full source
inverses remain in both phases; no regex replaces arbitrary import/key strings.
Attributed or opaque macro functions, dynamic/empty/too-deep paths, other
callback behavior and ambiguous owners refuse instead of acquiring permission.

The batch API accepts explicitly selected complete modules/functions, preserves
untouched input modules and keeps every full source history. Source is bounded
to 2 MiB and fewer than 1,000 lines per module, 32 modules/8 MiB input aggregate,
128 selections and a 200,000-token selection budget. A metadata preflight and
bounded string/cell/depth walks limit retained text to 16 Mi UTF16 units per
proposal and 32 Mi per batch without allocating a whole JSON serialization to
measure it. These are construction bounds, not measured RSS or deadline proof.
All original compiler/case/evidence limits and post-proposal checks remain.

An independent source case selects the actual catalog resource_error_code
reader and its three priority paths. Production source is not installed or
claimed translated. Independent twenty-kind/depth source/CST/hygiene/batch/
malformed/data cases and existing paired-core priority cases are drafted.
The existing native catalog test module adds original-function edge oracles for
conflicts, empty/whitespace/Unicode strings, wrong typed alternatives, duplicate
JSON keys and absent/malformed input, avoiding a separate Rust test crate.
All cases, actual proposed-parent translation, native parity, original body
proof, receiving/freshness/platform/performance and Rust CI are UNRUN/OPEN.
No executable percentage or full synchronization claim follows from a proposal.
