# Bulk native JavaScript body drafts through meta-language

Run `node scripts/regenerate-js-first.mjs` to draft every independently admitted native top-level item and scoped lexical function. The generator discovers every native JavaScript module, retains both complete source censuses in `parity/js-native-portable-draft.json`, serializes each checked program to Links Notation, reparses and checks it, and passes only that decoded program to the TypeScript and Rust emitters. This output generation is reusable through `tools/translation/js-to-rust/native-portable-artifacts.mjs`.

The top-level and scoped programs have separate output trees. Scoped discovery counts additional ArrowFunction, FunctionExpression and FunctionDeclaration bodies. It excludes declarations and variable-initializer forms already represented by a top-level item, as well as method/accessor bodies themselves; nested bodies of the three named forms remain included. Each scoped item retains its exact original source hash, UTF-16 span, enclosing scopes, enclosing owner's admission status and capture diagnostics. Translating a local helper does not translate its enclosing owner. Refusals are retained, and the two percentages are never combined into module or runtime parity.

Every native module receives explicit outputs, including empty programs. A helper that becomes refused therefore loses its previous executable body. Check mode reports differences without writing. Removed modules report stale generated files; write mode removes only recognized files in the two owned draft trees and rejects links or unrecognized files.

Generated TypeScript lives under `packages/typescript/native/portable-draft/` and is included by the existing strict native TypeScript configuration. Each file is an independent module, preserving private declaration visibility and avoiding collisions between unrelated source modules. The full reverse tests and regeneration check remain mandatory.

Rust projections live beside the meta-language files under `tools/translation/js-to-rust/generated/native-portable/` with `.rs.txt` extensions. They contain emitted Rust syntax, remain uncompiled, and are excluded from the original tracked `.rs` corpus so regeneration does not recursively translate its own reverse drafts. They use the fragment's explicit UTF-16 payload and host-qualified projections; their presence establishes neither native Rust equivalence nor runtime parity. No Rust build is required or authorized by generation.

Full-domain helpers and conditional private producer-body drafts have separate census fields. Conditional drafts require unchanged standard producer/callback intrinsics; producer effects and lookup stability remain unproved. Their serialized meta and emitted targets retain this qualification, with enclosing owners and public/unqualified callers refused. Combined draft definition counts do not establish full original-signature or runtime coverage.

Source-bound imported Error construction adds `conditionalConstructors`. The original import, class, constructor/default/assignment order and complete enclosing body are independently reconstructed from the actual producer graph after meta serialization. Known constructor mutation, alias escape, shadowing and reflected use remain refused. Constructor, builtin Error and inherited-prototype lookup stability outside the graph is an explicit unproved condition, with full-domain and conditional top-level counters kept separate.

TypeScript imports the actual native class using the generated module's output path; Rust returns an explicit normal/throw `Result` with a fresh UTF-16 message/own-field projection. It does not implement JavaScript Error prototype, stack or class identity. Receiving-environment IR execution of original constructors requires an explicit source root and module-execution opt-in, verifies source bytes before and after, and imports only the actual constructor owner closure. This does not certify arbitrary module bootstrap effects or dynamic reload convergence.

Conditional imported Error drafts explicitly retain `hostDiagnosticLocationsPreserved: false`: source/interpreter/target callsites have different stack and Bun diagnostic locations. Complete raw descriptor values remain evidence; checked comparisons preserve own-key order, descriptor flags/types, actual class/prototype, message and source-assigned fields. Restricted `throw` line terminators, including comment-contained ones, are rejected by both original-graph validation and the independent body parser.
