# Checked original text predicate inverse draft

`proposeForwardTextPredicateSynchronization` batches method-token substitutions
among existing checked `contains`, `starts_with`, and `ends_with` operations.
Project manifests select `"inverse": "text-predicates"`. All source preparation,
regression cases and behavior remain unrun during the complete drafting phase.

The language sequence reads the complete actual original text emitter, performs
its lossless CST serialization/reparse and native syntax selection, and extracts
the real three-member predicate emission table. It retains all source bytes,
original table spans and source inverses. The method table is candidate data;
it grants no type, trait, borrowed-receiver or source-owner authority.

Each changed original function must still have its actual private checked source
association. The rule joins original checked text operations and native Rust
method tokens to the complete original emitted target's native method calls.
Full source/target multiplicities must match. Only registered method tokens may
change; every operand, type, guard, generated temporary, surrounding expression,
function header and unrelated target byte remains exact. This avoids rebuilding
administrative bindings and preserves left-to-right, once-only evaluation.
Unresolvable nested/overlapping associations remain explicit refusals.

The complete modified Rust is checked again through the original frontend and
serialized/reparsed checked semantic meta. All target function bodies and the
whole executable/refusal census must reproduce the requested edit. A source
span, public operation record, matching spelling or emitter source hash cannot
replace this independent recheck. The separate repository sequence retains full
native and paired JS/TS source equations and inverses. The original guarded
project transaction recomputes the proposal before installation.

One invocation-local native token index serves all changed functions in each
complete original source. No index, source, owner, verdict or result is cached
across proposals. The source preparer derives the new proposal function from its
complete original numeric inverse, with exact function selection, separate
language/repository substitutions, pinned originals and full inverse equations.
All original numeric/floating/body APIs remain unchanged.

Independent unrun JS/strict TS source covers a multi-function/multi-method batch,
repeated operations, retained comments and inline modules, empty patterns,
non-ASCII scalar values and distinct Unicode normalization. Operand changes,
new temporary statements, unknown methods, unchanged targets and unrelated
module changes refuse. Native Rust oracle source, project transaction and export
closure cases are drafted. New text operations, arbitrary property calls, wider
owned/aggregate/async/generic bodies, namespace/bootstrap, production adoption
and parity still need their remaining draft and later independent verification.
