# Whole-owner Core corpus source candidate

This explicit candidate connects the separate enclosing Core producer to the
complete formatting, matches and vector source-proposal stages. Defaults and
all original modules remain unchanged. No candidate source is installed into an
application, and no proposal count establishes executable coverage.

`prepare-whole-owner-core-corpus-candidate.mjs` first requires fresh complete Core
and original template producer equations. It selects the actual original
inspection constructor, attribute and finish calls through TypeScript 5.9.3
import symbols. It copies the complete shared inspector, all three complete
materialized corpus modules, the stage lifecycle and the production stream.
Separate language and repository substitutions retain original sources, native
binding checks, serialized/reparsed whole CSTs and full inverses. Every original
input and current generated prerequisite is rechecked at the final boundary.

The candidate inspector immediately uses the original inspector factory when
callback-free ingress is unavailable. Eligible calls construct a fresh genuine
Core context, complete capture for all original modules synchronously, parse
that primitive JSON DATA and discard the private context reference before any
file inspection. A callback-free TypeError during eager capture selects the
complete original factory, retaining its original constructor and per-file
failure boundaries. Other failures propagate.

The DATA decoder separately pins the actual native `JSON.parse` descriptor;
crypto readiness alone does not establish that property. It rechecks the full
descriptor before decoding and before every later use. A rebound function or
accessor selects the original inspector without invoking that unknown parser.

Captured rows grant no type, namespace, borrow or execution authority. Before
each use, the inspector checks the complete original graph, source/view/profile,
private original module items, source hashes and exact source/span association.
Producer effect rows independently rejoin the genuine original item and item
hash. The ordinary original inspection CST and every original proposal source
remain unchanged; unknown macros, attributes and unsupported owners keep their
existing refusal paths.

Eager capture order does not become reporting order. The original inspector
selects effects only after its per-file macro checks succeed, including effects
selected by child inspection before a later ancestor failure. The candidate
replays those same successful owner visits and original item order, deduplicates
by the same file/module/item key, and returns that complete effects record. It
includes selected items even when their final emitted attribute span list is
empty. Untouched and immediately failed physical files add no selections.

All captured DATA is invocation-local and cleared when inspection finishes.
Each of the three stages creates its own complete fresh graph/context/capture.
The copied production stream calls each materialized stage synchronously,
finishes it, and then writes its bounded stage packets. There are no private
frames across iterator yields and no private proof or context shared between
stages. Existing individual corpus packet APIs remain unchanged.

The inner contract is complete JSON wire equality: original fields, source,
rows, diagnostics, metadata, effects and CST/inverse payloads are retained.
Primitive JSON deliberately does not promise JavaScript prototype identity.
The candidate's outer stream manifest uses the distinct
`router-complete-whole-owner-core-sequence-stream-candidate-v1` schema. Shared
bounded transport quotas, independent packet/CST/source inverse readback and
physical source/Cargo guards remain the original complete implementation.

After materializing the existing Core prerequisites, run:

```sh
node --max-old-space-size=2048 tools/translation/prepare-whole-owner-core-corpus-candidate.mjs --write
node --max-old-space-size=2048 tools/translation/prepare-whole-owner-core-corpus-candidate.mjs --check
node --max-old-space-size=2048 tools/translation/whole-owner-source-backed-core-sequence-stream-candidate.mjs propose --root PHYSICAL_SOURCE_ROOT --output OUTSIDE_DIRECTORY --progress
node --max-old-space-size=2048 tools/translation/whole-owner-source-backed-core-sequence-stream-candidate.mjs review --root PHYSICAL_SOURCE_ROOT --output OUTSIDE_DIRECTORY --progress
```

These are commands for the coordinator's shared resource lease, not permission
for concurrent heavy work. This commit is source-only. Candidate generation,
the complete new six-case Node/Bun receiving file, original receiving files,
strict targets and the complete production proposal/readback are **unrun**.
The related original twelve-case default trial remains performance red under
both Node and Bun; this candidate claims no measured speed improvement.

New callback children each retain one complete three-stage operation. Their
complete Hash-observed outputs must succeed; JSON's original native-CST refusal
is retained and compared as a real refusal. They use the complete framed wire
transport introduced by `bc0321857`, with unchanged child stdout/time bounds
and full decoded payload comparisons. The shared observer transport now drafts
Brotli quality-4 frames with 1 MiB raw leaves, the original 64 MiB per-child
stdout limit, complete decoded byte comparison and only one parsed full record.
Per-child sizes and cumulative sequential totals are diagnostic DATA; sequential
decoded totals are not concurrent-memory or physical-evidence measurements.
The outer physical evidence/resource limits remain unchanged. The
separate Core receiving file retains all original cold/warm/same-context cases.

The next source-only corpus repair leaves that qualified Core transport and all
four original child workloads intact. Its separate indexed-DATA format retains
one invocation-local dictionary of primitive strings and an ordered tree entry
for every key, array occurrence, callback argument and result. Repeated strings
retain every occurrence index; no event, field, source byte or payload is
discarded. Unique strings use bounded 32,768-code-unit pieces, preserving even a
surrogate pair split between pieces. A conservative byte census bounds the
complete representation before its native stringify. The representation then
uses the existing independent 1 MiB Brotli leaves, 384 MiB logical representation
limit and 64 MiB per-child stdout limit. The outer 384 MiB physical evidence cap,
12.5-second child deadlines and 60-second complete-case deadline are unchanged.
Expanded repeated-string volume is explicitly different from representation or
concurrent-memory volume; it is never passed to one native stringify call.

All complete dictionary/tree frame bytes are compared, then the baseline is
fully decoded. A nested actual digest is changed and completely re-encoded with
the same indexed encoder to prove strict comparison. Ordinary/null prototypes
retain the prior JSON wire projection. Buffer leaves retain every byte and
restore the same ordinary `Buffer.toJSON` projection. Additional primitive tags
retain undefined, BigInt, negative zero and nonfinite values without treating
them as source authority. Unknown classes, executable fields, proxies,
accessors, cycles and custom Buffer hooks refuse without invoking them. Object
alias identity and property flags were never part of the original JSON wire.
No dictionary, tree, source, encoded verdict or primitive map crosses calls.

The new complete six-case indexed-wire file covers a tape with over 512 MiB of
repeated primitive strings and all 600 original occurrences, full small JSON
projection/Buffer equality, all primitive tags, silent-hook refusal and validly
framed forged tree data. It also checks the complete authored codec and child
through serialized/reparsed source CST equations. This repair, the new helper
file and the corpus receiving rerun remain **unrun**.
