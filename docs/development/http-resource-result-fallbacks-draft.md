# Complete explicit Result failure fallbacks: source draft

All implementation, receiving cases and native oracle source remain unrun.
Immediate actual Result failure guards may now choose a separately checked
complete fallback instead of propagating the original error. The original
same-Result branch remains intact, including exact cleanup and error-family
checks. Alternative branches must return on every path, satisfy the eventual
whole-function return domain, retain all input roots and clean up every local
resource. A tag spelling cannot admit a successful payload in the error branch.

This composes actual filesystem reads with JSON byte parsing, Option fallbacks,
scalar defaults and owning default strings. The original discarded I/O error
does not become a text or control error. Helper release summaries still join
every success and error exit; partial releases remain unusable by callers.
Captured bindings, nested effects and fallback-local source annotations reuse
the same fresh whole-source checker and original rule budgets.

Native emission retains a complete match with a discarded Err pattern and an
explicit whole fallback block. The original native reader and projection copy
reconstruct that complete branch before fresh JS/meta checking and exact full
Rust reproduction. Forged fallback meta or a source-history flag grants no
source, type, owner, cleanup or executable authority.

Complete originals retain native-selected spans, language then repository
substitutions, serialized/reparsed lossless CST and full inverses. Independent
unrun JS/strict TS/native cases cover filesystem parsing, Some(Null), malformed
UTF8, missing files, cold polling, owning/scalar defaults, returned roots,
all-exit cleanup, incomplete branches, successful-payload misuse and partial
helper releases. General error inspection, outcome-sensitive releases, generic
signatures, namespace/bootstrap, production parity and every other unfinished
requirement remain open.
