# Incremental canonical DATA encoding checkpoint

The optional source lifecycle producer now uses a separate incremental storage
encoder. `prepare-streaming-static-encoding.mjs --emit` copies the complete
actual canonical JSON scanner, core encoder and repository layout encoder, and
extends the actual receiving helper's dependency copy. Its four whole-file
outputs retain native TypeScript 5.9.3 grammar, separately declared language and
repository CST sequences, serialized/reparsed whole sources and complete inverses.
`--check` reproduces every installed output. Existing public encoder functions
and the original source lifecycle producer remain byte-identical.

Canonical records through 262,144 UTF-16 code units use the original native
encoder. Larger records use the copied complete scanner to retain every array
element span, parse and independently serialize each complete node, and retain
the complete canonical metadata and source. Malformed, noncanonical or deeper
inputs decline to the original operation. Every original row, source, coordinate,
dictionary, varint, framing, byte and whole-storage inverse check remains.
Original source/CST passes, limits and independent decoders remain required.
This explicit DATA API permits a different metadata JSON callback schedule.
No source, namespace, type or executable authority is granted.

The new five-case receiving file compares both complete original/new encoders
against the entire actual bank and both complete original decoder inverses.
One original source/CST read, four complete encodings, two full byte comparisons
and two decodes run inside the same original 60,000 ms case. Sequential child
lifetimes share its remaining deadline budget; no work runs outside the case.
The complete intermediate JSON is temporary test DATA, with source authority
false; it is never a compiler verdict or private owner token. Each operation
receives the complete bank, and every old/new encoded byte is retained and
compared. Full worker source, commands, original archive and raw child streams
remain in the task-owned receiving evidence.

That independent new bank case runs first, before unrelated parser allocations.
Native AST/CST source preparation retained every case body and its original
deadline during that ordering change. All five cases and the unchanged legacy
lifecycle cases remain mandatory. Earlier unsuccessful scheduling and encoding
attempts stay retained; no case filter, forced collection or raised bound is used.

The complete current five-file Node group passes all 36 cases in 291.954 seconds,
with 1,614,315,520 bytes sampled peak aggregate RSS. Independent deadline audit
`complete-o2K3Px` has no breaches; the unchanged original two-proposal case takes
58,308.466 ms against 60,000 ms.

The complete current five-file Bun group passes all 36 cases in 228.823 seconds,
with 3,204,530,176 bytes sampled peak aggregate RSS under the unchanged 3 GiB
bound. Native source/name/line/deadline joins and all 2,233 input vectors pass.
That run remains close to the memory bound; it is an observed resource result,
not a promise of a full-corpus speed or memory gain.

The prior Node group had 36 passing assertions but a genuine deadline failure:
the original two-proposal case took 61,839.429 ms against 60,000 ms. Later
pre-scheduling Node groups passed their deadline audits, while several complete
Bun attempts remained RED on memory. Their direct child streams and full source
proposals remain retained under `router-streaming-static-encoding-source-v*`,
`router-static-source-release-source-v*` and `router-layout-check-*encoding*`.
The distinct passing focused and combined observations do not replace failed
or unrun mandatory checks.

Independent final native grammar, CST and inverse review passes. Every legacy
reader/producer/encoder function and original receiving case body is retained;
only the explicit allocation variant selects the new encoder. All 867 tracked
Rust/Cargo originals still equal their complete Git and physical bytes, and all
132 installed TypeScript source inputs remain unchanged. Full review is retained
in `router-streaming-static-encoding-source-v3/final-complete-current-review-v10`.

Application executable coverage has not increased. The current compiler export,
canonical and three-profile regeneration, reverse freshness, original receiving
codec/export suites, remaining performance and namespace frontiers, strict
native parity, complete JavaScript gate and same-SHA CI remain unfinished.
Rust remains CI-only after all eight JavaScript stages pass for the same SHA;
Rust failures remain fatal. Issue #759 and the continuation draft remain open.
