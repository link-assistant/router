# Canonical owned Rust inverse and source-unit draft

These sources are drafted and unverified. No test, translator experiment,
preparer, regeneration, compiler diagnostic or Rust tool has been executed.
The complete requirement ledger remains open.

`js-to-rust/owned-rust.mjs` adds a Rust-authoritative inverse for the normal
form emitted by the owned state profile. It transports the complete original
Rust through serialized/reparsed CST, requires all original support helpers,
reads bounded function syntax and applies catalog-driven state/iteration and
explicit JSON constructor/reader/control substitutions. The resulting JS is a
proposal: the existing private owned source checker, checked meta codec and
emitter must freshly reproduce the complete original Rust token sequence.
Missing or altered guards, attributes, support bodies and extra effects refuse.
Comments and trivia retain their exact original CST/source inverse.

The native reader and proposal AST grant no type, loan, effect or callable
permission. Temporary chains retain the original depth/node bounds. Original
private issuers, whole current source contexts, dependency checks and finite
runtime domains remain required. Paired JS can propose identifier spelling;
its old body cannot authorize the new Rust behavior. Unsupported native ABI or
general Rust constructs still refuse. This is no full production sync claim.

The `owned-state` source-unit profile binds explicit physical native inputs to
their logical library paths. Its descriptor adds `nativeSources` entries with
`path` and `sourcePath`; required inputs are exported as
`OWNED_STATE_NATIVE_INPUTS` by `owned-state-unit.mjs`. Complete current Cargo,
Rust library/module and materialized runtime files are captured as inputs to
every proposal. Runtime mirrors for separate `js` and `ts` roots must be exact.
Current profile paths use matching suffixes under the JS/TS source roots and
matching runtime directory names; unsupported layouts refuse explicitly.

The runtime source list is provided by `ownedStateUnitRuntimeSources(unit)`.
Materialize and review those ordinary files before synchronizing an initial
unit; runtime copying establishes no receiving qualification or runtime parity.
The synchronizer refuses missing or changed materialized inputs rather than
substituting generated text for an actual source capture.

JS, TS and Rust authority retain the existing full Git baseline conflict
handling and proposal/apply transaction. A JS edit can propose missing public
input annotations from the actual, independently checked prior TypeScript
signature. Native function spans select annotation additions, complete prior
typed and edited JS sources remain in the inverse, and the edited JS body is
freshly checked. The authoritative JS file stays intact. Stale paired target
bodies never substitute for that check. TypeScript authority keeps its complete
original annotation projection and written-type checks.

Source review also repairs the final source-unit packaging rule so its semantic
metadata survives alongside target equations. The separate current/prior
source family is preserved by `prepare-owned-state-unit-sources.mjs`; the prior
five-file state producer composes that successor instead of losing its original
source. Every native-selected edit and both ordered rule sequences remain in
the complete compressed archive. No preparer has been run during drafting.

Independent regression source covers state/iteration interpretation, real Rust
body edits, complete support/guard/attribute refusals, source contexts, the
JS-to-Rust-to-JS-to-TS unit cycle, signature proposals, runtime/native changes,
concurrent edits and forged application plans. All remain unrun. Standard
iterator adoption, general mutation, persistent state, async/HTTP/streaming,
broader TS APIs, production coverage and the complete CI repair set remain open.
