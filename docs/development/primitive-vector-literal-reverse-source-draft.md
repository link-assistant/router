# Primitive literal bidirectional caller source draft

Twelve complete source equations connect the paired literal runtime to both
owned source lanes. The actual imported symbol and complete current receiving
runtime/declaration/core bytes are required. ReturnType and bounded Parameters
rest-element witnesses map to the exact primitive and owned Vec domains.
Ordinary individual call arguments, up to 64, are checked left to right as Copy
scalars. Spread, optional/generic/callback calls and mismatched domains refuse.
The parent source checker retains complete caller, move/loan and CST/meta reissue.

Rust emission uses the existing qualified from_slice(&[...]) operation with no
new native API. TypeScript uses the actual paired wrapper import; both existing
independent interpreters invoke its source-qualified runtime module. Runtime
preparation closes synchronous whole source operations before asynchronous
imports and rechecks the whole program afterward. Within-operation source
sharing retains full closing fences and adds no across-operation cache.

The canonical Rust projection observes only the exact from_slice shared array
shape to propose a literal call. Whole fresh private JS checking and reproduction
of the complete authoritative Rust remain mandatory. Source/name/shape/catalog
observations cannot establish original native namespace or owner authority.

Independent source cases cover all eleven domains in both lanes, JS/strict TS,
both interpreters, empty/one/pair/64 operands, nested helpers and rebindings,
length/Option copies, source/meta/CST/typed reentry and canonical Rust inverse.
Additional cases cover wrong widths, mutable-array arguments, consumed moves,
spread/arity/import refusals, missing/tampered pairs and source preparation.
All cases, compiler/freshness/receiving/performance checks and Rust CI are UNRUN.

The caller integration is source drafted in both directions. Broad production
adoption, original global namespace/producer closure, portable full compiler
export, whole repository synchronization and complete parity remain OPEN.
Raw JavaScript mutable arrays still require an explicit migration proposal;
this runtime constructor does not claim original arbitrary array equivalence.
