# Native-parsed canonical CST construction

`prepare-native-parsed-cst.mjs` copies the complete original private compiler
through native TypeScript selections. It appends the copy and selects it only
inside the private module. Every original function and complete module prefix
remains byte exact. The copied compiler retains the registered packet, imports,
executed rule order, source authentication and existing compiled-module cache;
it changes one private workflow binding. No new cache spans invocations.

The workflow consumes objects created by its captured native JSON parser. It
keeps the original header/source/language checks, independently rebuilds the
complete CST, and compares the whole canonical wire. A mismatch or failed
rebuild uses the original complete validator. Both independent builds and
serialize/reparse boundaries remain required. Public concrete validators keep
their full original implementations. This source-fidelity representation grants
no type, owner or executable authority.

Full source proposals include both ordered rule sequences, complete CSTs,
native bindings and exact inverses. `prepareNativeParsedCst` also requires
physical files to match their complete known originals or successors. The
separate source-text preflight returns only before/after equality data with
`fullCstAndNativeReview: false`. It grants no review flag or permission; actual
proposals and recorded source-history equations still perform the complete CST
and native reviews before installation or use as reviewed source evidence.

`prepare-native-parsed-cst-history.mjs` derives the current source joins and
fixture repairs. The existing three runtime inputs and one later history layer
keep their original counts. That layer explicitly records both complete native
constructor source equations and the additional producer/archive inputs, which
its final verifier checks. Unknown sources and genuine Hash callback mutations
remain refused; a fresh physical-byte check precedes successor construction.

The copied equation factory's existing `checked()` calls now have a genuine
host-guard binding in its source-preparation module. Its function body remains
exact; copying it into the private module still resolves the original private
guard there.

Fixture construction copies all five previously missing history inputs.
The early-core fixture derives its static import count from the complete native
grammar instead of a stale literal four. It still checks every occurrence and
the full source inverse, including the fifth private equation import. The
original hook cases, callback assertions, refusals and deadlines stay in place.
Only the fixture dependency array and import-count setup are adapted.

The complete original files must pass in Node and Bun under their original
deadlines. Constructor controls alone establish neither a whole-workload speed
gain nor current compiler/export freshness, application coverage or runtime
parity. Rust remains confined to CI after the complete same-SHA JavaScript gate.
