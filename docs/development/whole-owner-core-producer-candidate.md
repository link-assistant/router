# Explicit whole-owner Core producer source candidate

`prepare-whole-owner-core-producer-candidate.mjs` drafts three separate complete
source copies. The enclosing context imports the actual whole-owner footprint
issuers; its resolver imports that same enclosing private issuer; the copied Core
publisher records that issuer's original effect functions. Public certificate
fields, closed-source flags and supplied effect metadata grant no authority.
Every old Core export and original source body remains available in the copy.
Default production imports remain unchanged.

The additive creator opens a fresh synchronous binding operation for complete
enclosing construction and another fresh operation for the complete resolver.
`captureWholeOwnerCoreAdoptionAttributeData` opens a third fresh operation for
the complete requested genuine module list. It serializes every selected
original source, source digest, exact attribute span and full producer-effects
record before closing. Its result is primitive JSON DATA, not a private proof or
semantic admission. A caller may decode the complete data before yielding
packets; a live operation must never span an iterator yield.

New capture selection rows are invocation-local and discarded in `finally`.
Source programs, canonical binding bytes, digests and guard verdicts do not cross
calls. Existing Core context data and legacy selection behavior keep their old
contracts. Unknown carriers, hooks or intrinsics select the original complete
pipeline; all source and private-owner checks remain in that pipeline. Each
eligible operation independently captures the complete original source graph,
reissues its binding program and performs the existing final source/intrinsic
boundary before returning any data.

The producer selects actual native TypeScript 5.9.3 declaration/import symbols,
retains complete original sources, applies separately declared language and
repository CST sequences, serializes/reparses the complete result and verifies
the whole inverse. `--write` materializes the three explicit copies; `--check`
compares their fresh equations. It first requires the complete current bulk and
resolver source closures. Never hand-edit those generated copies.

This commit is source-only. Materialization, the new complete six-case receiving
file, original receiving files, strict targets, Node/Bun original twelve-case
workloads and production packet integration are **unrun** for this Core
candidate. No executable coverage, performance improvement or production
qualification is claimed. The related three-overlay original twelve-case trial
remains performance red: Node case 10 took 78,502.476333 ms and Bun took
62,202.13 ms against the unchanged 60,000 ms deadline. A separate real-library
diagnostic found the existing resolver admission predicate true for all 396
genuine modules; it does not justify broadening that guard.

Root subsequently materialized all three Core source equations and qualified
the first five new Core cases, alongside all seven packet and seven stage-stream
cases, with no case deadline breach. The sixth Core observer case failed its
