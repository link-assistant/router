# Independent source lifetime refusals

The project translator collects independently attributable failures in each
complete signature and body lifetime phase. It discards the failed program,
removes the original failed declarations, and checks every surviving caller
again. Standalone checker calls retain their existing first-error behavior.

The collector accepts only genuine original declaration entries and private
project or method source ranges. An unrelated exception, generated declaration,
changed entry or escaping error span retains the ordinary failure path. Dynamic
selection is cleared when the synchronous invocation exits; no source, owner,
hash, encoded result or checked-program cache survives an invocation.

`node tools/translation/prepare-source-lifetime-refusal-batches.mjs --check`
reconstructs all three complete checker/project source equations with the
lockfile-installed TypeScript 5.9.3 parser, native binding checks and serialized,
reparsed CST inverses. The reusable `language` sequence changes the collector and
lifetime loops; the `repository` sequence selects it in the project driver.
`--write` accepts only the exact complete original or generated files.

The original vector birth producer remains unchanged. Its current consumer
explicitly joins the subsequent lifetime and owned-matches equations at their
exact complete source boundaries. Historical inputs and inverses remain
available. These source preparations grant no semantic admission by themselves.

The initial Node receiving run passed all 22 complete cases in the new lifetime
batch suite and both existing project refusal suites, without deadline changes.
This includes 128 independent late borrow failures, ambiguous signatures,
transitive callers, nested source owners and fresh source replacement. The
affected nine-file Node cohort subsequently passed all 73 cases with TypeScript
5.9.3. All 23 complete shared-adoption, reverse-vector, checked-source and lifetime
cases passed under Bun 1.4.3. Whole-project speed, canonical/profile freshness and
the full JavaScript gate still require verification; no production coverage gain
follows from these receiving results.

The historical three-file `prepareSourceLifetimeRefusalBatches()` result remains
unchanged. `prepareCurrentSourceLifetimeRefusalBatches()` and the CLI explicitly
compose the later executable checked-source accessor onto the exact complete
project output. The current vector source check composes vector → lifetime
batch → checked source → matches. Each layer retains its own original input,
serialized/reparsed CST and complete inverse; matching current bytes does not
replace any historical source equation.
