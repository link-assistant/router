# Owned JSON collection caller draft

`owned-collections.mjs` adds an explicit reverse profile for the existing paired
Rust and JavaScript `json_map` and `json_filter_map` compatibility-core APIs.
Their native library implementations remain intentionally untranslated. The
profile carries actual immutable JSON-list inputs, fresh owned list results and
inline synchronous callbacks. It does not grant arbitrary iterator, mutation,
trait, Drop or async behavior.

`prepare-owned-collections.mjs` retains four complete original implementations:
the private source checker, emitter/interpreters, full source document codec and
paired TypeScript source reader. Native-selected language substitutions extend
their closed semantic domain. Repository substitutions relocate their private
imports and select a distinct document profile. Complete originals, source
recipes, serialized/reparsed CST and both full inverses remain inspectable.
The old core/vector/portable entrypoints and private issuers remain separate.

Every fresh source context rechecks the actual complete Rust facade and
collection leaf, their CST and exact public edges, the original locked JSON
profile and complete registered JavaScript/declaration closure. Calls resolve
through actual native import symbols. The copied checker alone issues caller
items; detached metadata and operation names issue nothing. Reading meta and
emitting a target reconstruct the complete original source and callback again.

Callback checking reuses the complete original expression, branch, local type,
loan and return checker. Map requires an owned canonical Json on every path;
filter-map requires the closed owned Option<Json> constructors on every path.
Fresh paired native callback selection retains written parameter, local and
return constraints. Owned Option locals require a future affine-flow rule and
currently refuse. Native base64 Result captures, escaping callables, async or
nested callbacks, callback mutation, borrowed callback results and unknown
effects remain refused. General iteration and mutation remain open.

Rust emission evaluates the receiver once, validates original input domains,
calls the actual qualified compatibility operation, and validates the complete
result with its aggregate JSON bound. Sequential uses preserve independent
owned storage; Rust helper internals stay native. TypeScript uses the actual
registered imports and contextually checked callbacks. Both independent copied
interpreters use the existing runtime, preserving order and early errors.
The immutable-array ABI, existing 4096-node/depth32 JSON domain and all original
resource/workload limits remain unchanged.

The TypeScript entrypoint selects only actual native type-only imports and
annotation spans. It retains the complete original CST and inverse, creates a
fresh JavaScript projection, then checks every written domain through the
paired original reader. Existing different paired JavaScript source refuses as
a conflict. Annotation removal alone is never counted as executable support.

Independent source covers map/filter-map, order, empty inputs, sequential
callers, Unicode, strict original/generated TypeScript, written callback types,
source inverses, forged meta/runtime/native leaf, capture/loan/effect refusals,
and TypeScript projection/conflicts. Four Rust integration oracle cases call
the actual native operations. All sources are drafted and unrun; no Rust tool,
test, compiler diagnostic or translator qualification has executed in this
phase. Current source-bank/export freshness, production adoption, complete
forward/reverse synchronization and every remaining ledger row remain open.
