# Chronological integer aliases source draft

The implementation and independent regression/oracle sources are unrun. This
draft establishes no new executable coverage, native parity, strict TypeScript
result, source-history freshness or complete synchronization.

A complete copy of the chronological base64 alias selector now supplies native
primitive alias DATA. It follows simple immutable identifier initializers,
explicitly suffixed bounded decimal literals and actual primitive MIN/MAX paths.
The selector installs each fact only after its original semicolon and removes
bindings at the end of their lexical block. Native literal bounds are compared
as bounded decimal text through the existing shared domain reader. Unsuffixed
inference, annotations, arbitrary expressions and shadowing remain unproved.

Both existing integer adopters use the same original-source selector. A fully
selected method returning a primitive can populate its whole direct initializer,
so later saturating/wrapping/min/max/clamp calls can use its concrete domain.
Option results remain Option; they cannot acquire a numeric receiver. The
shared alias reader recognizes all ten fixed-width primitive domains, while
the existing adoption contracts still select only supported u64/i64 methods.
Failed new local censuses preserve the original parameter-only selection path.

Every receipt is source-selection DATA with false authority flags. Current
source/module/producer/type/ownership checks still have to qualify the entire
adopted function. The complete original declaration and evaluation order remain
in source. No initializer is duplicated or inlined, and no trait permission,
move/lifetime proof or executable admission follows from a lexical alias.

The new selector retains 200000 token/source-selection-cell bounds, 4096 local
bindings and 256 lexical frames. State lives within one actual source selection;
there are no cross-operation source/hash/owner/verdict/result caches. Both
adopters now place neutral compatibility calls in language substitutions and
rebase only the introduced prefix in repository substitutions, preserving
serialized/reparsed CST and whole original-source inverses.

Five complete source equations retain original modules, native owners and both
rule phases. Written cases cover source timing/scope/spans, literal boundaries,
selected results, both actual adopters, the fixed bulk stage, whole receiving
JavaScript and strict TypeScript behavior, unknown/Option/refusal controls and
independent Rust boundaries. Every case and remaining source/native/production/
sync/freshness/parity/delivery obligation remains unverified.
