# Connected source-bound adoption sequences

All implementation and regression source in this batch is drafted and unrun.
No test, experiment, diagnostic, translator, regeneration, Rust tool, push or CI
was run. Every unfinished [ledger requirement](bulk-draft-requirements.md)
remains open, including actual application adoption and executable parity.

The explicit source-bound sequence copies the complete existing formatting,
`matches!` and vector source producers, their shared original-source inspector,
in-memory sequence, physical repository wrapper and independent readback flow.
Only the selected context/support imports and complete inspection replay change.
Older producers and sequence APIs retain their implementations and requirements.
The synchronization API exports separately named source-bound entry points.

The new inspector uses the same original private source/derive/tool issuer as
the source-bound primitive and base64 producers. Its original-file entry exposes
the complete retained inspection with no executable permission. Tool attributes
are projected only for source inspection, with the entire inverse retained;
every output application proposal preserves original attributes. Stability
metadata is never projected through namespace passivity.

Readback rebuilds the actual complete graph and freshly recreates each retained
original-file inspection. It compares the complete inspection and final private
producer effects, checks unique actual paths, requires inspections for proposed
files and their original ancestors, and retains every original Cargo, full CST,
source census, function coordinate, mapping, phase history and inverse check.
A no-derive mode flag, copied context, public digest or source-only declaration
cannot replace those fresh joins. Existing whole Cargo joining is still required
by the sequence, even when its narrower source inspector has no derives.

The physical wrapper continues to capture and rejoin actual production source
and Cargo inputs at `rust/src`, without installing application code. It keeps
original byte/object/file limits. No across-invocation source, owner, verdict or
result cache is added. Eight complete original source equations retain ordered
language/repository substitutions, native owners, complete CST history and full
inverses. Independent unrun cases cover all three real producers, tool metadata
preservation, altered/omitted inspection facts, shadow and unknown-producer
refusals, no-derive inspection, physical changes and native boundary behavior.
Architecture export/producer bootstrap, wider executable constructs/effects,
production adoption/parity and every original receiving/CI/freshness gate remain
unfinished. A source inverse is not an executed reverse translation.
