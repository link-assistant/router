# Owned project transaction draft

The additive `sync-router-owned-project-units.mjs` entrypoint accepts existing
unit profiles and the new `owned-project` profile. It is included in the shared
compiler export entrypoint list. The synchronizer, runtime-only planner and CLI
are complete original source copies with native-selected substitutions and
separate language/repository source equations. Existing entrypoints are intact.

An owned project declares one packaged Rust path, mirrored JavaScript/TypeScript
entry paths, and complete per-language dependency arrays. JS uses `.mjs`; TS
uses `.ts`. Module identities must form a complete bijection beneath the two
declared source roots. The native/Cargo mappings and physical runtime mirrors
use the existing owned outcome contracts. Additional native boundary modules
remain explicitly declared and captured when their operations are used.

Automatic authority selection includes dependency-only edits. Conflicting
edits in multiple languages refuse. Initial generated targets may be missing;
the authoritative module tree must be complete. Rust authority reconstructs
the source tree from actual current source modules, checks the whole packaged
input, restores bodies and aliases, and independently rechecks every generated
JS/TS tree. Native symbols select all calls, type imports and runtime edges.
Relocation uses byte-equal actual runtime mirrors and then fresh semantic checks.

Every target module enters the original complete proposal byte budget and the
existing atomic replacement/readback/rollback transaction. Apply recomputes the
entire proposal from fresh Git, source, native, Cargo and runtime bytes. Saved
maps, metadata and plans provide no source or semantic authority. Complete
before-images and CST inverses remain in the proposal. Runtime-only mode still
avoids application translation. There is no persisted result cache or Rust tool.

The entire family, independent multi-language/dependency/conflict/forgery and
runtime-only regressions, and exported receiving CLI remain unrun. Later source
drafts add [paired module signatures](owned-project-signatures-draft.md) and
[module alias integration](owned-module-alias-draft.md). General
syntax, arbitrary native module
layout, production adoption, receiving qualification, full parity and the
remaining issue requirements stay open. No CI or freshness result is claimed.
