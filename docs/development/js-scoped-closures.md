# Source-bound scoped closure body drafts

The reverse compiler can represent a scoped function body with captured, unchanged enclosing parameters as a `closure` IR declaration. It issues its lexical environment from complete original JavaScript text, a precise UTF-16 function span and a source path. A fresh TypeScript syntax tree and symbol checker establish each capture's unique parameter declaration, enclosing owner, ancestor scopes and reference spans. No caller can provide a capture map, AST or narrower input type.

This prerequisite currently adds **zero native bodies**. All 52 original modules retain their separate 788 top-level items (73 admitted) and 705 scoped bodies (52 full-domain and nine conditional drafts admitted). The `accounts.mjs` filter captures a reassigned `selected` local, and `client-files.mjs` captures a computed `prefix`; both remain refused. The closure representation does not admit their parents or closure creation effects.

The environment accepts only simple enclosing parameter bindings whose complete original module contains no assignment to those symbols, arguments alias, dynamic scope or unproved prototype/global capability. Destructuring assignments, loop writes and writes in sibling nested bodies are checked against the same original symbols. Destructured, rest, defaulted and async owner parameters remain refused. Captured objects retain identity; this binding check does not prove their contents immutable or permit property reads. Unknown-vs-unknown equality, including arbitrary BigInts, remains unsupported.

Serialized metadata retains the exact original UTF-16 source, its UTF-16LE hash, source path, function and ancestor spans, parameter bindings and reference spans. This text is evidence for reissuing the environment and reparsing the original body; it is never emitted as executable source. Both the meta checker and each closure emitter reconstruct the checked body from that source and compare the entire canonical declaration. Altered body, signature, type contract, binding or provenance is refused. Closure identity includes the UTF-16 hash, distinguishing malformed strings that have equal UTF-8 encodings. The source path is an identity label, not permission to read a file or a claim of tracked-source provenance.

The TypeScript target emits an explicit factory whose capture parameters remain `unknown`. Each factory call returns a fresh callable with the original isolated body's parameters. Calling that function preserves opaque payload identity, null and undefined, UTF-16 strings and fresh checked aggregate allocations. Factories are a draft environment boundary; they do not translate or invoke the original parent.

The Rust target emits a named environment with private `JsPayload<'env>` fields and a `call<'a>` method. The `'env: 'a` bound explicitly requires captured borrowed payloads to outlive returned payloads. Call arguments retain their independent `'a` lifetime. Generated arrays and records allocate freshly through the existing `Rc<RefCell<...>>` contracts; arbitrary argument containers remain opaque borrowed references. Rust output remains uncompiled and `runtimeParity: false`. There is no Rust runtime verification claim.

The independent fixtures execute original JavaScript, the reparsed IR evaluator and strict compiled TypeScript across primitive values, signed zeros, NaN, lone surrogates, boxed values, huge BigInts, symbols, functions and revoked proxies. They preserve all original native censuses and serialized programs. Unsupported operations and unqualified ordinary calls into a closure factory remain refused.
