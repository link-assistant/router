## Shared language rules

The [substitution implementation](../../tools/translation/copy-scalar-helper-substitution-20261103.mjs)
handles checked scalar identity, conditional selection, Boolean logic, equality,
ordered fixed-integer comparisons and fixed-domain constants. Complete pure
`if/else` return trees become conditional expressions. It uses the existing native
integer catalog and literal bounds; no per-width translator is manually copied.
Each branch must contain only its complete return tree. Locals, captures,
arithmetic/bitwise operations, host/source calls, ownership carriers and effects
need separate rules and remain refused.

Arguments are actual lexical scalar identifiers, Boolean literals or bounded
native BigInt literals. A signed literal may have an original unary minus.
The caller joins its actual imported helper declaration through the same private
TypeScript Program and checked aliased symbol, then checks the entire helper
body through the original private function checker. Actual parameter/return
domains must be Boolean or one of the genuine fixed-width roles. Operands must
match those domains exactly; a raw `bigint`, legacy `usize`, number, text or JSON
carrier is not permission to select an integer width. Duplication or omission of
these inert primitive reads does not duplicate argument effects.

Literal helpers read a numeric domain from the actual original written return
declaration or its genuine TypeScript pair before checking their return
expressions. Original native declaration/import/type checks and exact literal
bounds still decide admission. Public names, metadata rows, width flags, saved
ASTs/checkers and helper markers grant no native facts.

The proposed helper module grammar additionally permits named **type-only**
native scalar imports. Each import goes through `originalOwnedCoreImport` in a
same-Program private traversal and must resolve the actual canonical primitive
runtime/declaration and genuine native scalar alias. Value imports, defaults,
attributes, competing aliases and top-level evaluation remain outside this
grammar. Both direct TypeScript aliases and JavaScript JSDoc import types are
covered by receiving source.

The separate constructor requires the complete existing primitive-operator
context and stores grammar selection only in private context state. Original
constructors, the Boolean helper grammar and its argument-refusal order are
retained. A new invocation-local WeakSet identifies substituted expression roots
so a helper call is not mislabeled as an original identifier `Copy` history row.
Fresh reanalysis reconstructs helper-call provenance instead. No new source,
checked-body, owner, verdict or result cache survives an operation. All expanded
expression/return-tree work charges the caller's original100000/depth160 budget.

## Documents and both translation directions

The [source proposal](../../tools/translation/copy-scalar-helper-20261103-profile.mjs)
retains both complete reader originals and successors. It derives four complete
copies of the current implementations: both helper document readers/writers,
the source/concrete-meta profile and the canonical Rust inverse. Every source
copy has separately declared language and repository sequences, complete
intermediate CST serialization/reparse and exact inverses. Existing Boolean
documents/APIs are not redirected.

The new document profile retains `copyHelperCalls` with actual parameter/return
roles, complete import links, helper declaration source/spans and any actual
paired declaration source/spans. These become bounded source references and
separate required original CST rows. Standalone meta reading constructs a fresh
Copy grammar context and invokes the original private item checker again.
Original32MiB/4096 document limits and every full source/type/body check remain.

The copied Rust inverse accepts canonical Boolean/fixed-integer signatures,
uses the original complete Rust function reader and projection implementation,
and freshly checks both JavaScript and TypeScript targets. It restores original
helper networks when their rechecked Rust matches. For edited Rust, the original
primitive-definition checker qualifies a canonical caller proposal, which must
reproduce the entire authoritative Rust. Shared helper files remain unchanged,
and ambiguous decomposition returns an explicit reconciliation record. This
does not yet implement general helper-network edit reconciliation or full Router
synchronization.

The proposed Copy source operation preserves the existing Boolean source fence
and adds six complete fixed inputs: the new substitution, native scalar catalog,
both copied document modules, copied profile and copied Rust inverse. Every
source is checked at entry and exit with the original source-failure/closing
protocol. Caught/restored failures poison enclosing operations; exact callback
primaries and original source/resource limits remain. Archive and source hashes
restrict source inputs and never confer compiler authority.
