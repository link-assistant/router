# Paired TypeScript API source draft

Rust scalar envelopes do not encode TypeScript's written optional marker or
scalar alias spelling. Rust-authoritative portable synchronization therefore
uses the complete captured current TypeScript source as a formatting proposal.
That source must pass fresh native/CST and typed analysis. Only signatures whose
actual names and scalar domains match the newly checked program contribute
their parameter/return annotations and optional markers. Accepted scalar alias
declarations retain their complete original source. Body behavior and defaults
come from the authoritative Rust translation.

Language substitutions replace native-selected annotation spans. Repository
substitutions preserve alias declarations and the original optional/required
API choice. Both complete target stages keep serialized/reparsed CST equations
and inverses. The final TypeScript is independently checked again and must
emit the authoritative complete Rust syntax. Public proposal program fields,
old meta documents and the paired body provide no semantic permission.

A type-only paired file can qualify its alias graph through a separate
reversible scalar witness. The witness never becomes application output or an
original function premise. Invalid or unsupported nonempty paired APIs refuse
before synchronization writes anything. Native/runtime failures are not hidden.
Every source is freshly captured and checked; there is no new persisted source,
hash, owner, verdict or encoded-result cache.

`prepare-paired-typescript-api.mjs` retains the entire original synchronizer and
native-selected integration rules. The prior Rust-inverse producer composes
this explicit successor. Synchronization metadata comes from the final
repository-stage result so it retains both authoritative Rust and paired API
histories. All helper, strict consumer, forged-proposal and complete baseline/
Rust-edit integration regression sources are drafted and unrun. General
TypeScript interfaces/classes/modules and full Router sync remain open.

The complete Rust syntax check uses bounded invocation-local token cells and
direct type/text comparisons, with the existing native host guards. Helper
selection and paired target rechecks share that implementation. Complete prior
inverse/API sources and both CST stages are retained by
`prepare-rust-syntax-cells.mjs`. No source hash or encoded-result cache supplies
an admission premise. This source-review change has not been measured or run.
