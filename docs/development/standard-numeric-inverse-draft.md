# Original fixed-runtime numeric inverse draft

`proposeForwardStandardNumericBodySynchronization` adds numeric runtime calls to
the established whole-body inverse. Project manifests select
`"inverse": "standard-numeric-bodies"`. The older formats keep their behavior.
All implementation, source preparation and independent regressions are unrun.

The reusable language sequence joins the original native target's named
`createFixedIntegerRuntime` import, exact canonical runtime path, immutable
factory instantiation and actual registered contract. It reads the real
`fixedIntegerContracts` catalog for all supported fixed widths plus distinct
`usize` and `isize` encodings. The complete original object literal must contain
only the expected kind, width and signedness; member names, factory calls and
helper identifiers must match their actual contract. No runtime object is
executed and no caller-provided registry is accepted.

Receiver calls use the actual original source expression and inherent method.
The fresh original Rust frontend must resolve the real primitive, operands,
source namespace, trait/const obligations and result type. Its complete modified
target must reproduce the requested body, static types, parameter guards,
unchanged surrounding module and executable/refusal census. Runtime width data
or a matching method spelling grants no ownership/type permission. Full source
and CST equations/inverses remain required. Pointer-sized encodings stay distinct;
unsupported pointer wrapping is not invented.

Saturating add/subtract/multiply, wrapping add/subtract, primitive min/max/clamp
and registered checked arithmetic all have call candidates. This does not add
aggregate Option signatures or Option destructuring; those still need their
own rules before such bodies can be accepted. Existing imported floating calls
compose in the same format with unchanged original refinement requirements.
Only already present original global helpers are available; adding a helper or
changing an import needs a separate source-preserving closure rule.

The native shadow census includes parameters, future variables, destructuring,
nested named functions/classes and binding patterns. Ambiguous imports,
non-constant or modified instantiations, optional/spread/generic calls, wrong
arities, missing helpers and unsupported expressions remain explicit refusals.
All associations live only during the current proposal. No persistent
source/owner/hash/verdict cache is introduced.

Three complete actual original functions are selected by the reusable native
syntax source producer and substituted into a small separate inverse module.
The original module, exact substitutions and repository support imports are
retained in pinned compressed recipes. The project planner and public facade
also retain their complete predecessor sources and ordered rules. Existing
source preparers compose this successor; no original API or deadline is removed.

Independent unrun source batches every numeric method for each supported fixed
and pointer primitive under both JS and strict TS proposals. Boundary expectations
cover signed/unsigned overflow, underflow, signed minima, exact values beyond
binary64 precision, wrapping, equal/reversed clamp bounds and native Rust
oracles. Source/import/factory/shadow/arity/operand refusals, project transactions
and export closure are included. This draft does not establish production
coverage, full parity, generation freshness or CI success. All other open bulk
requirements remain open.
