# Contingent complete-project storage adoption

`prepare-owned-field-gate-adoption.mjs` is a source-only proposal to select the
separate `translate-router-owned-field-meta.mjs` CLI in the mandatory canonical
and profile checks. It does not install sources. Root's complete unchanged-heap
canonical run must qualify the storage path before this proposal is adopted.
The source proposal's `fullForwardQualified:false` is deliberate: source
freshness cannot establish a runtime result or an eight-stage green gate.

The proposed six files are the reusable JavaScript gate YAML, local gate,
workflow auditor, nested deterministic parity checker and both original gate
test files. Only two run scalars change in the YAML. Native source rules select
the corresponding local/auditor command literals and the actual parity `exec`
argv. Existing workflow test expectations follow those commands, preserving
their install-order and independent-profile refusal workloads. One additional
local test compares the entire translation command array. The language sequence
routes complete checks; the repository sequence updates mandatory contracts and
receiving expectations. Every phase retains full native source spans, fresh
native inverse nodes, serialized/reparsed complete CST and whole inverses.
YAML uses its actual installed native parser/CST rather than a JavaScript lexer.

The old `scripts/translate-router.mjs`, all original bulk/retained/matrix modules,
source producer equations, owned-definitions commands, synchronization CLI and
budget source stay unchanged. In particular, no edit to the old CLI can stale
the qualified storage producer's `literalRoutes` input. Canonical parity retains
its 1,200,000 ms nested comparison; translation/profile jobs keep 60 minutes;
worker heap literals, strict TypeScript, reverse checks, deadline audits and all
fatal downstream Rust guards remain mandatory. All actual caller YAML files and
protected source files are captured and rechecked as complete physical inputs.

The proposed selected commands are:

```sh
node scripts/translate-router-owned-field-meta.mjs --check
node scripts/translate-router-owned-field-meta.mjs --profile-matrix --check
```

The existing owned-definitions commands continue to use the original CLI with
`--retain-output-text --owned-core-definitions`, including its profile variant.
The original complete CLI and synchronization routes remain available under
their original observer contract. This proposal changes neither that contract
nor their defaults, and it does not silently make a legacy command field-wise.

Root's receiving order after the complete forward run qualifies:

```sh
node tools/translation/prepare-owned-field-bulk.mjs --check
node scripts/prepare-owned-field-gate-adoption.mjs --emit /private/tmp/router-owned-field-gate-source-v1
# Review the complete six afterimages and install only those exact sources.

# Run those whole files under Bun too; keep every original case/deadline.

```

The last command still runs every original mandatory stage and strict check; it
is not a receiving-test shortcut. Source changes require fresh output generation
and the complete same-SHA gate before any Rust check. No timeout, heap, storage
or task bound is raised. No executable coverage gain is asserted.

The separate fixed-nine draft-supplement policy is not a prerequisite. Its
runtime auditor can compose with these two required-command changes. Its source
proposer separately preserves a complete unchanged gate beforeimage; if both
policies are adopted, that proposer needs an explicit known gate-command history
composition. Do not weaken its whole-file identity fence or describe skips as
observed greens. This proposal preserves whichever actual caller policy Root
supplies and records all original caller bytes without changing them.

Worker checks are limited to source review, bounded source inventory and
`git diff --check`. No engines, native generation, full forward run, receiving
tests, installation, gate success, remote write or Rust execution ran here.
