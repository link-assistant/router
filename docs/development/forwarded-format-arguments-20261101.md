# Forwarded literal formatting argument custody

All implementation, source equations, independent cases and native oracle are
SOURCE ONLY and UNRUN. No implementation, parser, preparer, translator, compiler,
tests, CI or native oracle ran. There is no output execution, semantic reverse,
Arguments ABI, original macro equivalence or measured coverage claim.

The additive engine is a complete copy of the original attributed declarative
engine. All original matching, opacity, follow rules, budgets, private original
input, forwarding, nested occurrence, header and renderer checks remain. The only
changes are the factory name, private source-failure/closing imports and an added
observer inside the SAME private definitions/expansions/nested occurrence tables.
The existing nonempty bounded owner validation remains exact. The wrapper passes
`['crate', ...definitionRootView.modulePath]` from the actual complete declaration
file root view as an untrusted syntactic owner; fixtures explicitly pass
`['crate']`. This neither identifies the external application module nor resolves
a binding, and ownerVerified remains false. No existing engine, fragment API,
public hub or predecessor file changed.

The observer requires its exact original root proof and input and its own exact
nested occurrence. A copied proof, a separate engine's same-spelling input, or a
foreign nested occurrence cannot rejoin those private records. Original caller
leaves are identified by the SAME raw token objects; original definition leaves
are identified separately from that proof's genuine original declaration tree.
No caller-supplied origin array, spelling, digest, source span or flag grants
custody. Public rows report DATA only. Introduced bare `format_args` remains an
unresolved mixed-site binding and is not assumed to denote the builtin.

The supported input is empty or one complete original string literal captured
through tt. Definition-only literals and separators remain definition DATA.
One caller literal must occur exactly once and in its original complete interval.
Duplicate, omitted, reordered, noncontiguous, opaque/non-tt, mixed expression,
foreign/generated and dollar-crate owner cases retain refusals. A nested whole
bang input may retain its own definition-origin path and recursively forwarded
literal, but this does not resolve its macro owner or execute the nested macro.
The original renderer remains unchanged and still refuses unknown nested macros.

The wrapper requires a genuine original Host parser and complete original source
bytes, a unique actual function/raw invocation membership from genuine source
module views, the matching original parser module, and unqualified original
invocation syntax. Attributed/conditional callers and definitions, public or
non-macro_rules declarations, changed sources and parser methods refuse. The
original fragment API parses only the unchanged contiguous original caller literal
at its actual original interval. It never parses an introduced template using a
synthetic caller span. Templates containing braces refuse pending actual format
parser/capture semantics. A data clone of the literal AST is returned; the genuine
fragment context/capture remains private and expires with the operation.

Both engine and wrapper requests expire after one synchronous callback. Async
callbacks are rejected before invocation, including at the direct engine API.
Every successfully captured original is rechecked on every exit, including setup,
read, source/CST and callback failures. Every closer runs and the original primary
error wins. Shared source-input validation poisons enclosing original operations
when private source failure is caught and original text later restored. Ordinary
callback errors remain distinct. There is no cross-operation verdict cache.

The language rule joins the actual original leaf/AST custody and full whole-owner
Rust CST serialization/reparse equations. The repository rule retains original
function/owners and explicitly unsupported owner, mixed-site hygiene, implicit
capture, evaluation order, Arguments construction, borrow/lifetime and transport
states. Complete returned DATA, all repeated aliases, full CST/equations and trace
are bounded by UTF16/UTF8/cell/depth occurrence accounting before return.

The complete frozen original/current engine snapshots live under the standard
source profile originals directory. The additive recipe selects the actual whole
SourceFile after its unchanged leading comment and retains the complete original
and current files, fixed language/repository phases, native source selection,
serialized/reparsed CST and full inverse. The repository phase is an identity
quality layer; no older source history is overwritten or reordered. Original
source snapshots are data, not semantic permission.

Independent source cases use actual Host parsers, not mocks. They cover zero and
literal custody, exact raw original spans, definition/caller distinction, private
expiry/clone/foreign-engine rejection, duplicate/missing/reordered/noncontiguous/
mixed/opaque captures, parser/source changes, implicit template/qualified refusal,
caught source failure/restoration, async refusal and primary-error preservation.
The actual production-bound case retains complete original lib.rs,
operation_output.rs, auth_remote.rs and auth_import.rs via the earlier immutable
scoped-output owner profile, then joins the original
`println!("Paste authorization code:")` in its whole auth_remote owner. It gains
literal custody only. The zero-input arm is present in actual operation_output;
no zero-argument production call is asserted by this batch.

Paired target execution, checked-program meta and native semantic inverse are
explicitly unsupported for this custody-only API. Physical Rust CST inverses are
not semantic translation. The CI-only Rust oracle independently exercises the
immediate zero/nested literal format_args shape using native std::fmt::write; it
is an oracle prerequisite, not the Router transport implementation or receiving
parity evidence. Real Arguments construction and lifetime/effects, macro/builtin
identity and full scoped transport remain open. In particular launcher capture,
redaction, FILE_DIAGNOSTICS logging, task-local OperationContext capture, locks,
quiet stderr, recursion avoidance and ignored fmt/io errors cannot be replaced
with console output or an owned String formatter.

Coordinator integration may export the four additive custody APIs/factory and the
source recipe and register their independent source cases. Existing default APIs
and their refusals remain unchanged. No exporter selector exception is needed.
