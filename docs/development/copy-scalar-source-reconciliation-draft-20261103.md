# Scalar Rust edits over original source

The [reconciliation adapter](../../tools/translation/js-to-rust/copy-scalar-rust-source-reconciliation-20261103.mjs)
continues the [scalar source adoption](copy-scalar-helper-adoption-20261103.md).
Its source is installed as a separate API around the existing complete inverse;
no existing reader, document, source fence or default behavior is changed.
All receiving, runtime, native, compiler, translator and CI feedback inspection
remain UNRUN. Counts stay12/70 DRAFTED,58 OPEN; coverage is UNKNOWN.

The complete existing inverse first qualifies authoritative canonical Rust,
fresh JavaScript/semantic meta and whole Rust reproduction. Unchanged Rust keeps
the existing exact original helper-network restoration. For changed Rust, the
adapter independently rechecks the original source too. It compares all function
names/order, visibility, parameter names/types and return types against the fresh
canonical proposal. Additional imports, interface changes or absent original
source retain the qualified canonical proposal and an explicit refusal to claim
minimal reconciliation. No missing namespace or interface proof is waived.

For unchanged interfaces, complete old/current Rust function syntax identifies
the changed functions. Genuine source-derived declaration/body spans locate
corresponding original JavaScript and actual paired TypeScript bodies. These AST
observations only propose edits; they do not grant source, type or owner facts.
The existing concrete rule registry composes all body replacements over the
immutable original spans. A language rule replaces only changed bodies, followed
by a repository rule retaining imports, signatures, comments and helper modules.
Whole sources and every intermediate stage retain serialized/reparsed CST and
exact inverses. There is no line matching, arbitrary source overwrite or edited
saved checker.

The composed sources replace only their corresponding source rows in the actual
issued canonical projection context. Existing primitive-definition and Copy
checking independently checks that complete candidate and its semantic meta
again. All unchanged helper calls resolve through their original private import,
declaration and body checks. The final result must reproduce the entire
authoritative Rust syntax. No source changes are applied by this API.

The result retains the actual minimal source plan, changed/retained function
names, original Rust and JavaScript histories, canonical projection history and
false runtime/whole-synchronization claims. Shared helpers remain unchanged.
Edited callers still have an explicit helper-decomposition/adoption record;
this adapter does not invent a unique inverse helper graph. There is no new
cross-operation source, type, owner or result cache.
