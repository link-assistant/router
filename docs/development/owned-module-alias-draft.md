# Owned module alias integration draft

The alias-aware module and receiving linkers are complete source copies of the
existing owned linkers. They select actual type alias declarations and imported
type symbols through the existing native module graph. The linked TypeScript
then passes the alias source rules and full private owned checker/meta boundary.
Generic runtime functions remain outside this alias-only profile.

Project transactions, paired signature proposals and Rust restoration use this
path. Complete alias CST histories travel with actual module histories and
semantic meta. TypeScript redistribution retains existing module aliases and
type-only imports/exports as source proposals. Generated names avoid identifiers
in both the receiving bundle and retained actual modules. Every reconstructed
tree must freshly check and reproduce the entire authoritative Rust again.

Public type aliases in dependency modules can remain available to their TS
consumers. Public root type packaging, generic native Rust type aliases and
changes to type declarations under Rust authority still need their own complete
meta/source rules. The current root packager refuses those unsupported exports.
There is no inferred public type API from a spelling or saved history.

Eight complete original implementations, ordered language/repository recipes,
full source inverses and independent cross-module, Rust-edit, strict TS consumer,
constraint/cycle/body/refusal regressions are drafted and unrun. No tests,
translation, compiler or regeneration have been executed during bulk drafting.
Public root types, runtime generics/records/effects, production coverage and the
remaining requirements stay open.
