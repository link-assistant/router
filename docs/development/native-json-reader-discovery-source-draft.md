# Automatic optional JSON reader source proposals

`proposeNativeJsonOptionalPathReaderDiscovery` is a source-only orchestration
draft over the existing optional JSON reader rules. It enumerates ordinary
top-level functions from complete supplied modules and selects lexical parse,
`find_map` and `try_fold` call shapes. It calls the same complete composed CST
proposal for each candidate, retaining supported proposals and explicit ordinary
unsupported-source observations. It never installs source or grants original
namespace, type, body equivalence or runtime authority. All cases are UNRUN.

This removes hand-maintained function/path lists for this source family. The
actual catalog reader is a source case at an arbitrary supplied module path;
the constructor contains no catalog-specific spelling. Comments and literals
do not select functions. Candidate counts, source proposals and refusals are
distinct and never presented as executable coverage. Functions outside this
lexical discovery envelope remain outside the candidate set, not translated.

Source order is module order followed by original item order. Each successful
proposal becomes the complete next module input, so later functions use fresh
coordinates. Observations retain original supplied-module spans separately
from each current step's input spans. Every original module, including modules
with no proposals, keeps its entire source and inverse. Every child proposal
keeps its own ordered language/repository pipelines. The outer orchestration
also declares both fixed phases rather than flattening their chronology.

Only explicit unsupported-source errors from the two actual constructors are
reportable refusals. Malformed CST/parser input, host mutations, resource and
metadata bounds, failed inverses/censuses and unrelated exceptions remain fatal.
The constructor accepts no caller-supplied proposal callback. Caller source rows
and arrays undergo descriptor/proxy/hole/path/size preflight before discovery.
No arbitrary object coercion or accessor invocation is permitted. Refusal
observations cannot authorize a later source change or suppress failed evidence.

The complete batch retains at most 32 modules, 8 MiB original source, 4,096
original items and 128 attempted candidates. Each module retains the underlying
2 MiB and fewer-than-1,000-line bounds. Existing child metadata bounds remain
mandatory; the batch retains at most 32 Mi UTF-16 metadata text units with cell
and depth limits. No source/owner/result/input/failure cache persists between
calls. These bounds are source contracts, not RSS or performance measurements.

Three complete frozen-source equations, a pinned substitution archive and the
additive `prepare-native-json-reader-discovery-sources.mjs` successor preserve
all previous preparer APIs and complete original histories. Independent source
cases cover supported and unsupported mixtures, multiple functions/modules,
the actual catalog, coordinates after earlier edits, untouched source, duplicate
definitions, attributes, extra effects, string/comment false positives, malformed
source, budgets, descriptor hazards and fresh subsequent operations. No case,
translator, preparer, compiler or CI feedback has been executed or inspected.

Original semantic qualification, production adoption, whole Router coverage,
forward/reverse freshness, independent receiving parity and final delivery stay
OPEN. This source discovery layer does not resolve the separate original
macro/attribute/namespace producer prerequisites and cannot unlock Rust CI.
