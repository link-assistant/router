# Independent bounded tracked-source reader

All new source, original regression workloads, fault cases, CST/native binding
checks and platform behavior are **UNRUN**. This child does not qualify forward
regeneration, freshness, owned reconciliation, publication or full Windows APIs.

`source-corpus.mjs` retains its actual original WeakMap issuer and all existing
capture/path/text/selection APIs, source/Cargo limits and opaque-handle refusals.
Only `trackedSourceBytes` delegates to the new independent Node DATA reader.
The complete original and authored corpus source are retained byte for byte.
The child history reconstructs that exact one-function/import substitution,
checks both actual modules against complete authored snapshots, and records full
before/after CSTs, language then repository sequences and complete inverses.
Source identity hashes identify these fixed sources; they grant no semantic,
namespace, dependency or output-overwrite permission.

Every physical read opens the actual file, bounds each read and total allocation
by the caller's original `maxBytes`, and closes initial/path/fstat/ancestor
identities (precise bigint device/inode and nanosecond clocks) and exact length. POSIX opens require both `O_NOFOLLOW` and
`O_NONBLOCK`, so a regular-file to FIFO replacement cannot hang the open.
An ordinary deleted file stays missing; only an exact skip-worktree input may
read the full immutable blob from its captured HEAD, with HEAD/skip/absence
closing. Git state is local, replacement/lazy fetch and inherited Git overrides
are disabled, and no Git hook or compiler is invoked by this reader.

Ordinary Windows reads use available flags plus full Node-visible link/reparse,
realpath, initial/fstat/path and byte closing under cooperating/frozen source
paths. Node exposes neither every opaque reparse tag nor an atomic no-reparse
open on every Windows host. Hostile replacement, Windows FIFO/reparse-race
resistance and full Windows qualification remain OPEN; missing POSIX flags are
not presented as Windows guarantees or unconditional Windows API refusal.

The optional synchronous `withBoundedTrackedSourceOperation` keeps invocation
local read records through a pure read/compile/stream operation. A caught source, root-resolution
or observer failure invalidates the operation, even after restored bytes or a
restored root alias. Original root spelling and canonical identity both close.
Operation/read options use own data descriptors without getters/proxy traps.
An actually thrown callback primary wins unchanged, including `false`,
`undefined`, nonextensible values and frozen objects. Every closing attempt
still runs. Records expire on return; they are not a saved translation verdict.
Nested same-root frames share a private baseline only after a fresh complete
read comparison. Returned buffers and observer events are detached; observers
receive no private buffer, frame or issuer. Thenables, async/proxy observers and
recursive observer reads refuse. Nesting is bounded at 256 live frames.

Aggregate buckets are explicit: `{limits:{paths,bytes}}`. There is no default
20,000-path or 64MiB corpus restriction on the generic direct reader. A caller
that actually selects the original corpus domain can select 20,003 paths and
88MiB (64MiB native plus at most three 8MiB Cargo files). A direct forward caller
must retain its own actual per-file/module/output bounds and complete consumed
input set; it cannot infer those corpus limits from a filename or callback.
Without explicit buckets the new long operation has no aggregate retention
ceiling, so it does not establish a global RSS/disk bound for arbitrary direct
callbacks. The existing per-read limit still applies. Full direct-source bank
accounting is work in the separate, uncommitted ownership batch.

The long frame is for read-only producer work. Materialization must happen after
its full closing fence; creating output directories inside it correctly changes
its root/ancestor clocks and refuses. The later installer needs its own exact
observed-source guard and private producer reissue. Neither an observer event
nor a successful DATA read can admit a type, source owner or translation.

The complete original corpus test file stays unchanged and mandatory through
the existing Node/Bun forward globs, without a duplicate import. The independent
new case file adds real physical/sparse reads, FD closure, growth/max-plus-one allocation,
FIFO replacement, directory/link replacement, nested/private-buffer and caught
failure cases. It also retains explicit greater-than-corpus-count/byte positive
DATA cases and finite nesting refusals. Those new resource cases use 120-second
deadlines; all existing original workloads and deadlines remain unchanged.
