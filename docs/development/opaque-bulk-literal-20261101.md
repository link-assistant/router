`proposeOpaqueCorpusBulkLiteralInverse(configuration, {language, source})`
receives one complete edited JavaScript or TypeScript target. Its language
rules capture the actual complete native/adopted project, parse both complete
targets with the installed original parser and compare literal skeletons.
Each of 1–4096 changed semantic string/BigInt tokens must independently join to
a genuine constant cell or literal index origin, then to a unique physical Rust
token. All other target bytes must agree with the actual baseline, including
imports, identifiers, function signatures, statements and type syntax.

Different target occurrences may select one native token only when they propose
the same replacement. Conflicting proposals for that token refuse. Per-file
native edits compose against original spans; overlapping edits, stale preimages,
ambiguous declarations and transformed/computed source slots refuse. All edits
enter one fresh complete source-candidate translation. The selected complete
target must reproduce exactly and actual executable/refusal/method census
identities must remain unchanged.

The repository rule retains complete physical Rust histories for every changed
file and both complete paired target histories. Every source travels through
serialized/reparsed CST and full inverse checks. The result installs no files
and grants no parser/type/ownership/semantic authority. Public origin records
remain DATA; private semantic issuers and closing frames reissue independently.
