# Expression documentation consumer source draft

This implementation and every new regression and native oracle are UNRUN.
Source construction and review only were used. Tests, experiments, translators,
preparers, generation, compiler diagnostics, local Rust tools and CI-triggering
pushes remain deferred until every remaining source requirement is drafted.

The new explicit documentation operation copies the complete structured-doc and
architecture metadata consumers and full project entry point. It adds genuine
equality-expression captures for unqualified outer documentation attributes and
complete original module inner-attribute items. The general outer-attribute API
keeps its original domain. Each capture retains the actual original module,
item, member index, profile and spans, whole physical CST roundtrip, native
parser source plan, positive private AST, EOF and original combined bounds.
Documentation frames remain distinct from private function frames.

Impl and trait attributes are located through the original member boundary
reader. A data candidate may select its actual leading metadata and declaration
header; it cannot impersonate a genuine source item. Captures always receive the
real enclosing source item and explicit member index. Unsupported members and
source bounds remain refused. The shared builtin consumer now observes actual
member metadata inside this explicit operation rather than treating a method
attribute as an attribute of its enclosing impl or trait.

Each nonliteral expression joins the whole original builtin registry/parser
premises and fresh native attribute/walker/collector/fragment source inputs.
These remain conditional source premises. Argument macro ownership, visitor
dispatch, value semantics and global exports remain unqualified. Macro-valued
inner documentation raises local and crate-root macro uncertainty before an
inner builtin can be consumed. The conservative classifier handles both header
tokens and full cfg attribute tokens; literal/list metadata keeps its old path.

Private requests are retained only inside the bounded synchronous operation,
keyed by actual module object, source item and attribute start. Every use and
finish rechecks current source associations and native sources. Finish clears
the requests. No source/hash/owner/verdict/result cache spans operations. The
restoring operation keeps its original nesting, cell and byte bounds and refuses
Promises, proxies, asynchronous callbacks and own thenables/accessors.

The copied project retains five original source domains, language/repository
substitution sequences, serialized/reparsed CST equations, physical inverses,
current input checks and the existing checked semantic frontend. It does not
read an include file, expand an argument macro, infer ownership from spelling,
or certify original-source equivalence. Eight complete compiler source
equations retain full original implementations and native owner spans.

Independent unrun cases cover root/inner/member source associations, private
frame separation, legacy scope restoration, unknown macro effects, full cfg
tokens, independent JS/strict TS behavior and stable native module/trait docs.
Actual owner/global/type-prefix closure, wider attributes and language domains,
production translation/parity, reverse freshness, receiving qualification and
all other open ledger requirements remain unfinished.
