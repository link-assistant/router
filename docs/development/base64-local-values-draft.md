# Base64 immutable-local and borrowed-value source draft

This implementation and every new case are source drafted, unrun. It establishes
no current application coverage, trait/namespace closure, whole-function
qualification, strict TS pass, generation freshness, parity or green gate.

Both existing base64 source adopters now share the original concrete argument
selector and a bounded immutable-local census. A local-bearing function can
retain ordinary distinct immutable local identifiers while base64 calls still
consume actual concrete parameters or original ordinary string literals. Local
bindings cannot shadow a parameter, prior binder or protected namespace. Mutable,
reference/destructuring binders and new local-bearing match/for scopes refuse.
The original no-let lane keeps its prior selection/refusal scope.

Known concrete inputs also select exact borrowed views: as_bytes on original
text/String parameters, as_str on original owned String, and as_slice on original
owned Vec<u8>. Each complete original argument, including internal comments,
remains byte-for-byte in the emitted call and evaluates once. No bridge is
executed, erased or duplicated. Unproved temporaries, arbitrary methods, generic
as_ref or local aliases are not inferred as a concrete ABI. Actual type/owner,
borrow, complete function and remaining native method obligations still require
the existing independent compiler checks.

The language sequence now substitutes the checked candidate call into a neutral
compatibility-core source path. The repository sequence binds only those created
spans to Router's actual facade, with offsets rebased after every prior language
edit. Both complete sources pass the ordinary serialized/reparsed CST path and
retain their whole original inverse. The neutral path is proposal DATA, never
an installed dependency or semantic permit. Original trivia and untouched source
remain intact; receiver/UFCS comments that a replacement would remove still
refuse. Original source/file/total/recipe bounds remain unchanged.

The existing ordinary API and fixed source-bound bulk base64 stage use these
rules directly. Their complete Cargo/package, active native facade/root,
producer, method-candidate and end-of-operation checks remain. Original Engine
imports are retained, and originalTraitPermission/executableAdmission remain
false: this new compatibility-boundary proposal does not close an unresolved
legacy trait namespace or claim that a whole production caller is executable.

Four complete source equations retain both complete original adopters and the
shared selector copy, native owners, both language/repository phases and full
inverses. Independent written cases cover locals, borrowed arguments, comments
and Unicode span rebasing, both APIs and bulk routing, original/migrated native
boundaries, exact encodings/errors, namespace/shadow/pattern/refusal controls,
and a fresh whole-project JS/strict TS receiving caller. Native oracle source
is written for later gated CI. Every new case and remaining source/native/
production/sync/freshness/parity/delivery obligation remains unverified.
