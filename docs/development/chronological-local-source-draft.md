# Shared chronological source selection draft

The implementation, complete source equations and all independent cases are
drafted and unrun. There is no new measured coverage, native or target parity,
source-history qualification, freshness or complete synchronization claim.

One complete copy of the primitive alias engine now provides invocation-local
source-order selection to both base64 and integer families. Each existing
family retains its original census, operand reader, accepted result domains,
receipt tags and no-local behavior. The shared engine handles lexical frames,
unknown declarations, real initializer spans, delayed semicolon visibility and
bounded source selection. A bounded family-specific initializer selector is
available for later explicitly checked annotation grammars.

These are candidate DATA rules. A family callback cannot issue native source,
type, owner, trait, move, lifetime or executable authority. Actual adopters still
select calls from current complete source and require their normal independent
whole-function checks. Publicly fabricated source DATA remains untrusted.

Original 200000 token/cell and 256 frame bounds remain. Family counts remain
4096 where applicable; each initializer candidate also consumes the same cell
budget. No source/hash/owner/verdict/result state survives an operation. Complete
base64/integer adoption, receiving JS/strict TS, refusal and native-oracle source
cases remain in their separate family files and are all unrun.

Four complete source equations retain the original primitive module used for
the shared copy, both adapters and the preceding source-history edge. New
independent source cases cover isolation between families/invocations, delayed
results, unknown operations and complete source inverses. Wider text/collection/
namespace/production/sync/freshness/parity/delivery requirements remain open.
