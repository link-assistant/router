# Original Rust String-vector caller source draft

This continues the [caller draft](owned-text-vector-callers-source-draft.md).
All implementation, receiving, strict target, ownership, resource and Rust
oracle cases remain **UNRUN**. No local parser, translator, preparer, test,
compiler, Rust tool or CI/review feedback was executed or inspected.

The new forward domain copies the complete original primitive-vector active
module and parser guards, then substitutes the actual String-vector module and
its eight original paired operations. It retains the complete root declaration,
actual resolved type namespace binding and source/declaration spans, active
compilation profile, genuine source-module views, unchanged parser cursor and
original facade checks. The String core has no primitive-sequence native
dependency; that unrelated dependency is not manufactured for this family.

A fresh native source join independently compares the whole actual receiving
root and native leaf against the paired JS/strict-declaration/transitive source
closure. Public ABI observations and catalog rows retain false caller/type/
namespace authority. Actual private original caller checking remains mandatory.
The native checker requires the original checker methods, actual standard owned
String, actual owned Vec or single shared Vec reference, shared String slice,
native u64 indexes and the actual standard Option layout. Shared reference Copy
identity does not make its String element Copy. Lookup clones an independent
String and returns no loan into the original vector.

The private parent parser/checker/emission dispatch retains its original maps,
complete source frames, declaration associations, dependency snapshots, layouts
and complete function fingerprints. New calls use the original private issuer;
copied compatibility metadata cannot issue a call. Mutable core and helper
initializers and explicit shared helper operands have additive checking paths.
Every path still requires complete subsequent ownership flow and dependency
rechecks. The old primitive mutable/helper APIs retain their original domains.

An additive full ownership-flow copy introduces distinct `text-vector`,
`text-vector-ref` and `text-slice` domains. It retains the original String and
optional-String moves, branch exits, loop fixed points, live input roots,
lexical loans and argument-duration loans. Leading actual truncate/len/from_slice
results qualify public owned/shared/slice inputs. Complete same-module helper
bodies, signatures and input guards are rejoined before traversal, afterwards
and at emission. Later arguments cannot move or replace an earlier borrowed
vector even if a replacement would restore availability before the call ends.
Lookup results contain no source loan and can outlive consumption of the vector.
State copies are charged against the analysis allowance before allocation.

The original flow API remains unchanged. A bounded candidate traversal selects
the new complete checker for actual privately issued family calls or helper
candidates. Candidate/type summaries alone admit nothing; the selected checker
must still establish actual source, type, private call and callee membership.
The existing operation-local raw borrow-parent index is reused. No new source,
owner, hash, input or result cache survives an operation.

Native JS/TS emission has an explicit paired runtime import and complete frozen
carrier/strict declaration dependencies in both host packages. The additive
project entry points wrap the complete ordinary or flat-enclosing translation
in one fresh String-vector source scope. Nested operations share only that
scope and its original closing/failure checks. Existing project entry points
retain their APIs; the new bulk entry points avoid repeated fresh ingress.

Independent original Rust cases draft all eight operations, Unicode and NUL,
actual JS/strict TypeScript execution, owned/shared/slice inputs, helper outputs,
mutable helper initialization, branches, loop accumulation, cloned lookup
lifetime, moved String/vector refusals, nested argument loans and source/private
metadata refusals. An additive complete typed-target harness retains the
original strictness, process deadlines and cleanup, selecting the new full
paired declaration assets while preserving the original artifact writers.
Independent Rust helper and loop oracle source uses the actual public crate
edge and is CI-only. Full source equations and predecessor/inverse composition
are drafted without executing any implementation.

Production adoption, owned String literal arrays/variadic wrappers, broader
captures/aggregates/references, all original namespace/type owners, full exported
receiving qualification, platform/profile freshness, resource/performance
evidence and every remaining delivery requirement stay OPEN. These source
rules and cases do not establish executable coverage, complete original Rust
qualification, runtime parity or full bidirectional synchronization.
