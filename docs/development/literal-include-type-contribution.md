# Literal include type contribution source proposal

This source-only batch adds an explicit, narrow ordinary `include!` Bang
source contract and a private enclosing-type contribution proof. It changes no
default binder, project graph, existing source input, test or deadline. No
generation, receiving engine, native TypeScript parse or Rust tool was run by
the worker. The application coverage remains the last receiving measurement;
the historical 54 first-refusal functions are prospective work, not gains.

The complete retained Rust 1.89 sources already in the repository provide the
core declaration and std reexport, actual `register_bang` definition and whole
registration invocation, original `expand_include`, `make_items`, `make_expr`,
string-argument helpers and `resolve_path`. The new manifest pins the existing
archives and original MIT/Apache notices; it downloads or repins nothing.
The program loader retains full sources and their complete serialized/reparsed
Rust CST. It expands the actual registration macro and selects the one emitted
`LegacyBang` callback. This is a source-library ABI interpretation; it does not
observe rustc invocation flags, installed metadata, sysroot conformance or native
compiler execution. The existing AttrLike provider enum and APIs are unchanged.

`createOriginalLiteralIncludeTypeContext` captures actual original module views,
an explicit tracked path set and an explicit source reader. It checks complete
module strings afresh on every proof operation. The reader supplies the declared
source universe, as in the project reader; this is not a claim that an arbitrary
callback proves operating-system filesystem or compiler invocation identity.

`captureOriginalLiteralIncludeTypeCandidate` selects the exact original item
identity and original token trees. Its language rule parses every retained child
function with the genuine private NamespaceParser function-frame issuer. Its
repository rule selects a tracked portable sibling from the physical source
callsite parent, retaining the compiler `resolve_path` source. It does not use
the module directory. Computed paths, absolute paths, traversal, unknown cfg,
attributes, further includes, imports, type declarations, inline modules in the
child, unsupported complete function grammar and untracked children refuse.
An inactive child item may be absent only through the existing explicit cfg
profile; no host test/OS/feature is guessed.

Each child file crosses the full Rust CST boundary, and each returned function
retains its whole original source, physical file, coordinates, source hash,
private function frame and original visibility syntax. The child is a physical
syntax fragment; it is never added as a second project module with the same
namespace path. A candidate alone is conditional on the actual builtin owner.
Its copied public fields cannot issue an effect or owner token.

`proveOriginalLiteralIncludeBangOwner` implements a distinct positive owner
domain. It requires a single include in a complete original module family of
ordinary producer-free functions and genuine inline module views. It refuses
every other import/declaration/Bang producer, unknown configuration, root
prelude-changing attribute, competing std/core module prefix, nested attribute,
macro definition/import and documentation attribute without a separate owner
proof. Complete child functions must meet the same producer-free condition.
This is conservative: a source candidate can retain opaque body Bang traffic,
but such traffic cannot be used to authenticate this first owner domain.

Only the private owner token can join `proveOriginalLiteralIncludeTypeContribution`.
That effect proves an empty enclosing type-prefix contribution. It explicitly
retains value, bang, attribute, body and whole-namespace obligations. It provides
no type identity, trait behavior, ownership, dispatch, ABI execution or body
permission. All genuine source inputs and private frame associations are
rechecked after source/Hash callbacks, including a final child/source join.
Changed native reflection, parser ingress, JSON or traversal operations refuse.
No source/hash/verdict/encoded cache is introduced.

`prepare-literal-include-type-contribution.mjs` retains full authored source
archives and the exact current complete binder beforeimage. Native TypeScript
5.9.3 bindings select the original module/item loops and header statement. The
language phase adds the optional private context to that original resolver and
handles only a genuine proved contribution. It retains the actual included
function declarations as unresolved value bindings with original child origins;
all original macro/attribute uncertainty stays true. The repository phase adds
the explicit helper import and receiving API alias. Native span inverses and
both complete serialized/reparsed CST phase inverses recover the entire original
binder. The existing default wrapper and enclosing resolver bodies stay exact.
The copied binder also associates each genuine scope array with its private
include effect tokens. Both private-brand and original-origin consumption
recheck those tokens and fresh child inputs; changing a child after scope
issuance cannot reuse the earlier result. This is a proof-origin association,
not an owner/verdict cache: all original source/Hash/frame checks still run.
Qualified captured native WeakMap reads touch no original scope callbacks on
the ordinary path. A missing qualified receiving bootstrap refuses the new
include lane. The batch does not claim whole cold-bootstrap callback parity.

The separate receiving copy is for qualification. The plan also includes a
complete **same physical file** adoption proposal for `module-bindings.mjs`.
Future adoption must use that original module and its existing private scope
issuer; a parallel binder's private scopes cannot silently feed original
consumers. Such default integration still needs a genuine include context from
the project reader and complete receiving/source-history qualification. The
current CLI never installs the same-file proposal.
