# Removed inline native scope lifecycle source draft

SOURCE ONLY. Every implementation, source equation, API and physical transaction
case is UNRUN. Whole drafting and complete qualification remain OPEN.

The empty-module lifecycle now also drafts removed inline scopes while their
original physical Rust file remains present. A fresh complete native project
must provide one closest actual parent scope with the same full source digest
and an active original private module view. Its original items must contain no
retained next module component, imports, opaque expansions or attribute tokens.
Current descendant scopes and declarations must also be absent. Unknown parent
source retains a refusal rather than being treated as proof of absence.

This uses actual native project module coordinates; no external-module prefix
is guessed from a filename and no route flag establishes availability. Parent
items and all source views remain under their original byte, item and depth
bounds. Exact empty receiving AST/CST pairs and fresh independent complete
original/proposed native censuses keep the existing source and resource fences.

Both API and physical Rust refresh retain the removed module's route, so the
next operation can independently repeat or restore new native functions there.
No Rust source is deleted by the planner. Deleted physical native files, new
unrecorded module adoption and JavaScript/TypeScript insertion into an empty
unit remain separate OPEN requirements.

Three complete source equations preserve full originals and inverses under
language then repository phases. Independent unrun cases cover root and nested
scope removal, closest-parent joins, repeat/restore, physical manifests, stale
installation, concurrent edits and import/macro/attribute refusals. This explicit
rule supersedes the earlier removed-inline-scope refusal only in its stated
source domain. Coverage, parity, freshness, resources, platforms, receiving and
CI remain OPEN. Fatal Rust remains CI-only after eight same-SHA JS stages.
