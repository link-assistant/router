# Bulk immutable slice input migration proposals

The implementation and all cases are UNRUN. Full source drafting, complete
translation and every runtime, receiving and CI qualification remain OPEN.

`proposeOwnedWideSliceInputBoundaries` drafts the complete source module in one
operation for outcome or cancellation source families. Explicit readonly input
types identify candidates for the eight additional fixed-width slice domains.
Direct import types, named type imports/aliases and namespace type imports can
select a candidate. Those syntax hints grant no admission: the complete proposed
module must pass the existing actual private source issuer in a fresh context,
including its genuine imports, parameter types, body, effects and libraries.

Language rules insert all parameter guards through the lossless CST/meta
boundary; repository rules add a collision-free import from the existing owned
primitive runtime. Existing complete guards are retained, partial/different
prefixes refuse reconciliation, and old Base64 input prefixes retain their
leading position. The entire candidate is serialized/reparsed and checked again
through the existing JavaScript or TypeScript translation entry point. No
generated output is hand edited, no source is installed, and native source stays
unchanged. Whole originals and exact inverses remain in the returned proposal.

This API intentionally proposes a public input-contract change. Adding a guard
sets `inputEnvelopeChanged: true` and `originalInputContractEquivalent: false`.
It does not certify that arbitrary mutable readonly arrays had the same previous
input behavior. Already guarded complete source is reissued without duplicate
edits and records no input-envelope change. Source installation, production
selection, native freshness, application coverage and parity remain separate.

All original context/source closing checks are attempted on success and failure,
with the original error preserved and private scratch references cleared. The
two issuer families retain distinct private contexts. No source/hash/owner/
input/verdict/result cache crosses operations. Whole source size, syntax depth,
node count, function count, parameter count and fresh import name search are
bounded. Hashbang/BOM prefixes remain ahead of the new import.

Three complete compiler source equations retain their whole originals, exact
inverses and language then repository phases. Independent unrun cases cover both
families, all new widths together, unchanged original inputs, idempotence, source
refusal before migration, typed aliases/multiple parameters, import-name
collisions, wrong/missing runtime/type bindings, unsupported effects, partial
prefixes, malformed requests and the complete source plans.

Actual application adoption and input-envelope acceptance, mixed Base64 receiving,
strict emitted TypeScript/runtime execution, await/cancellation interaction,
performance, current compiler export receiving, canonical/platform/reverse
freshness and full parity remain unqualified. No tests, parser, compiler,
preparer, translator, generator or Rust tool ran. CI feedback is uninspected.
