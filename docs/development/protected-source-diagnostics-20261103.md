# Bounded source diagnostics — source proposal

This bounded handoff contains twelve complete parent pairs, a separate empty-source/full-after CST equation for the new caller-owned diagnostic collector/emitter, five independent case sources and a partial sink inventory. Active parents are unchanged. The unit beforeimage is the exact composed read-byte/stream epoch d88a590b8c558714dd3ace5bf88b260b74cf2e1b; other beforeimages retain their exact SCM origins. Every frozen earlier image remains immutable. All project verification is UNRUN.

The collector is invocation/caller-owned DATA with256 records and1MiB retained-byte accounting, including192KiB reserved for each pending route's at-most-three error observations. Message/error fields have explicit truncation and overflow/late counters. Recovery paths have a separate explicit bounded projection within the same byte accounting. Private class branding admits the real collector without invoking a fake run getter. There is no global diagnostic queue, source/hash/owner/verdict cache, error-label permission or restored primary synthesized from DATA. Exact original falsy/frozen values remain the actual thrown primaries.

The emitter records before attempting output, borrows descriptor2 and requires a genuine active native source route containing its own fixed executable-module root. The Node factories retain this additional root together with helper/script/selected roots, coalescing canonical duplicates (at most four explicit roots). The async route reuses the actual private invocation lease, including its original captured synchronous roots; the synchronous route captures actual current frames. Every current/captured root independently vetoes and closes its observations. Additional actual policy callbacks can only add vetoes; they cannot replace those roots. Their callbacks must finish synchronously, with proxies/thenables/accessors refused without invoking a then getter.

A private lexical recursion bit retains nested diagnostic-on-veto observations instead of writing stderr again. All applicable guard/closing attempts still run after an earlier refusal. Unsafe/unverifiable/expired routes retain DATA and do not write. An ordinary stderr write failure remains ordinary to healthy source policy. The separate first-level writer rethrows the exact actual route/write failure, including falsy values; secondary helpers keep the existing fatal primary. No borrowed stderr FD is closed. Idempotent native lease retirement removes its private diagnostic association, so an expired invocation cannot borrow a later frame.

Actual sync, async, direct/staged alias, common-policy and recovery fallback helpers route their secondary observations through this mechanism when an additive collector exists. Existing mutable-primary attachments are retained, with caller DATA observed before attachment. The common unit retains the real policy as an additional veto, preserving the original rollback/recovery bytes, modes and owned paths. Its composed byte-reader lineage is preserved. Finite whole-source successors extend stream, stream-join, Node-forward and resource-current providers; historical after remains historical, currentAfter follows the exact diagnostic successor. The resource terminal explicitly supplies laterHistories:[] and the prior join case retains its whole before/after successor.

Actual Node public option fields/defaults and original payloads remain. Additive runAuditedNodeTestsWithDiagnostics and deadlineReporterWithDiagnostics accept a caller-owned collector without reading a new field on old option objects. The fixed CLI and default reporter create invocation collectors; fatal exit behavior and original raw/audit/receipt serialization remain. Diagnostic DATA is not inserted into the original128MiB receipt, preventing a near-boundary valid receipt from being rejected or losing its original audit fields. Callers needing observations after an exception use the additive collector entry. If policy or stderr is unsafe, there is no forced durable output bypass: retained invocation DATA is the defined fallback, not a claim that it crossed a process boundary.

The new stream family now uses identity-only dev/ino/mode/uid/gid stamps for every actual FD kind, allowing legitimate regular peer append traffic. Protected endpoint/source snapshots stay complete; the old regular descriptor API retains its complete size/clock stamp. Independent cases use actual FileStats, real peer append, actual FD rebind, protected aliases, a child stderr file and a child pipe; no fake FileStats claim to prove safety. Other cases cover exact falsy/frozen failures, caller-brand/getter refusal, overflow/expiry, owned recovery DATA and no-child old-argument admission. These case sources are unexecuted.
