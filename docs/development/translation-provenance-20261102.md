## Actual fixed export route

`exportProvenanceTranslatorBundle` preflights the real source index and physically
reads every declared source/notice under the existing precise selected-source
operation. A declared missing/changed file, duplicate path, unmerged index,
unknown new vendor file or mismatched exact byte image refuses before the fixed
exporter creates a destination. No caller-supplied exporter/checker is accepted.
Both storage choices directly invoke existing fixed original implementations:

- `compact`: actual committed compact source vault, including every declared
  source/notice/catalogue as an explicit required input. This is the default;
  original encoded/logical/count limits and all independent source closers remain.
- `physical`: the original paired-core complete raw compiler exporter, retaining
  its own64MiB source/count/file/partition domain. It remains unsuitable for a
  cohort exceeding that original bound; this wrapper never raises it.

The source index and complete declared originals rejoin after export, and the
outer original reader closes actual file bytes/identities, source-root spellings
and Git/index epoch. A failure remains fatal even after an output bank was made;
unknown output/recovery data is not automatically deleted by this wrapper. The
physical manifest is returned from the actual fixed producer, not caller data.
Existing original exporter signatures, CLIs, output formats, limits and checks
remain unchanged. This additive CLI lives inside the compiler source tree and
is copied by its normal complete compiler selection:

```sh
node tools/translation/export-provenance-20261102.mjs --root SOURCE_ROOT --output NEW_DIRECTORY
```

This command is deferred until execution is authorized. A compact bank does not
by itself bootstrap a receiving compiler. Storage/resource fit, full hot/cold
source-reader integration, actual receiving translation and synchronization are
separate E01/E03/E05 obligations.

`withTranslationProvenanceData` uses one bounded snapshot/index per invocation,
with O(1) expected-path lookup and fresh hashing of every actual byte image.
It does not repeatedly clone the whole catalogue per copied file. Its scope
expires on return, clears references and cannot recover after a caught mismatch.
Standalone helpers use the same implementation. These DATA indexes are neither
persistent source/hash/verdict caches nor namespace/type/executable permits.
The catalogue is bounded by1MiB strings/keys,200k cells/depth32/8192 entries,
4MiB per declared source and32MiB aggregate declared source. The actual enclosing
source operation retains8192 paths/32MiB. This is a finite source-transfer
profile, not measured RSS, elapsed-time or source coverage qualification.
