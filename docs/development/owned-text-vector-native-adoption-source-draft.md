# Native String-vector source adoption draft

`proposeNativeOwnedTextVector` and its bounded batch API add original Rust
source adoption to the existing actual paired String-vector forward path.
Explicit function/local selections are data. The language sequence selects
straight-line local empty constructors, list `vec!` macros of at most 64
operands, discarded single-operand pushes and zero-argument lengths. Nested
length edits remain inside retained original push-operand spans. A fresh local
evaluates each push operand once before the receiver moves. The repository
sequence binds fresh intrinsic call tokens to actual `vec_text_*` core exports.
Both sequences use serialized/reparsed lossless Rust CST and complete module
source equations/inverses; comments and unchanged batch modules are retained.

Inputs are bounded to 32 modules, 128 explicit selections, 8 MiB aggregate
source, 2 MiB per module, fewer than 1,000 lines per source, delimiter depth 160
and the existing bounded CST/metadata limits. Runtime vector capacity is 4,096.
Repeated selection, getters, proxies, holes, invalid paths and unsupported uses
refuse. There is no persistent source, owner, input, result or failure cache.
Existing native JSON adoption and primitive/String caller APIs stay unchanged.

This is syntax adoption DATA. Apparent standard names and annotations cannot
resolve original namespaces or prove the element domain. Repeat macros, aliases,
indexing, selected-local shadowing, consumed push results, branches and nested
binding scopes require additional rules. Whole original semantic/ownership
reissue, two-phase borrow equivalence, after-source native caller acceptance,
receiving qualification and installation remain open. List lowering explicitly
adds String clones; bounded capacity changes the resource envelope; length
returns u64 instead of platform usize. No equivalence or executable coverage
claim follows from changed-expression, selected-local or proposal counts.

Independent complete-source CST/inverse, comment, Unicode/NUL, nested operand,
evaluate-once ordering, collision, batch, namespace non-authority, refusal and
resource case sources are drafted, along with independent CI-only Rust oracle
source. All are UNRUN. No tests, compiler, parser, translator, preparer or trial
regeneration were executed locally, and CI feedback was not inspected.

## Automatic native discovery

`proposeNativeOwnedTextVectorDiscovery` copies the complete existing native JSON
reader discovery guards, whole-module chronology, CST inverses and fatal source
failure policy. It scans ordinary function-local constructor tokens in supplied
modules, composes the fixed native vector proposer and retains unsupported
structural observations. Exactly enumerated structural refusals are reportable;
unknown, host, parser, inverse, census and resource failures stay fatal. Original
and current-step coordinates remain distinct. Limits are 32 complete modules,
128 constructor candidates, 4,096 original items, 200,000 census token visits,
8 MiB aggregate source and 32 MiB retained metadata. Counts are syntax inventory,
not executable coverage. Independent census, composition, unchanged-module,
refusal, domain non-authority, bounds and descriptor cases are drafted, all UNRUN.
