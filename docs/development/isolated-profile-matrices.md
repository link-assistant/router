# Sequential profile process lifetime

The profile CLI uses source-derived copies of the existing matrix producers.
Each complete profile runs in a fresh process, sequentially. Existing private
proof registries can retain complete checking contexts; worker exit bounds
their lifetime without clearing those registries or changing their authority.
The original matrix library APIs and private planners remain unchanged.

Reproduce the four copied producers and CLI branch with:

```sh
node tools/translation/prepare-isolated-matrix.mjs --emit /tmp/FRESH_PROPOSAL
node tools/translation/prepare-isolated-matrix.mjs --check
```

The actual producer applies ordered `language` then `repository` rules to each
complete original module. Proposals retain complete original and resulting
source, serialized/reparsed CST documents, native syntax validation and full
substitution inverses. Independently review the complete proposal before
installation. Canonical CLI generation keeps its original branches.

Each worker receives every selected original Rust and Cargo file in a private
temporary mirror, preserving complete contents and relative paths. A read-only
Git directory reference preserves tracked-source identity without another
clone. The real original planner performs all CST/meta, source, owner, type and
body checks, validates its private plan, and writes only inside the mirror.
The next profile starts after that worker exits. No Rust tool runs locally.

The parent receives complete generated byte plans. It freshly rejoins original
source, compiler, source-profile, installed TypeScript and Git inputs, every
staged file and hash, and the complete output census before writing profiles to
the receiving repository. These byte descriptors grant no application or
private-planner authority. Missing, stale and unexpected output checks retain
their original behavior. Canonical outputs remain separate.

This is an explicit stock-process CLI contract. Progress records keep their
original bounded scalar values and arrive after the corresponding worker
finishes; it does not claim the original in-process observer schedule. All
original library entry points retain their original behavior. No source,
owner, hash, syntax verdict or encoded-result cache is added.

The complete matrix retains its 60-minute and 1 GiB output bounds. Each worker
receives a 2048 MiB Node heap. Verification monitors the parent and descendants
together under the existing 3 GiB RSS limit, 3 GiB starting-space requirement
and 2 GiB reserve. Temporary generated storage retains the original 512 MiB
per-profile bound and is distinct from compressed diagnostic evidence. The
session removes its own mirror on success or ordinary failure. After a forced
interruption, identify its ownership record and confirm the owning process has
ended before removing task-owned staging storage.

The complete two-file receiving cohort passes under Node and fresh sequential
Bun: 16 cases per engine, complete output-byte equality for all four variants,
strict TypeScript behavior, missing/stale/extra outputs, changed original
inputs, damaged staging and a later worker failure. The independent Node audit
reports no deadline breaches. The unchanged 30-second CLI case took 20.183
seconds in Node and 6.957 seconds in the qualified Bun rerun. All fourteen
finite source deadlines pass; two original cases retain their default timeout.
All fourteen complete receiving source files remained unchanged between engines.

Preserve the complete failed receiving evidence: the untracked-input guard,
the exact required inventory path, and the earlier 33.580-second CLI deadline
breach. Consolidating redundant parent scans keeps one fresh current-input
check before each worker and another inside the complete final publication
call. Every original worker check remains. That final call validates every
staged file before writing and independently checks each file at its write
boundary. It accepts only the complete, correctly ordered, privately issued
profile set. Native host fences remain fresh; no source verdict is remembered.
The Bun harness's incorrect finite-timeout assumption is retained separately;
the original whole file was rerun with its source and default limits intact.

Full-corpus matrix generation, strict profile TypeScript, current generated
freshness and the complete JavaScript gate remain open. New compiler source
files require regeneration. This work adds no native application coverage and
does not establish complete synchronization or full runtime parity.
