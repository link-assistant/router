# String-vector join lowering source draft

Actual Router callers join instruction text with two newlines and other text
with spaces, empty separators or line breaks. The additive joining native
proposer/batch/discovery and JS/TS proposer lower selected original `join`
expressions into a complete same-module helper. Existing scoped and earlier
APIs keep their domains and refusals. Both directions use existing eight-op
String-vector and text compatibility cores; no new native ABI/root is added.

The helper checks the shared vector length and separator bytes, creates empty
owned text, reads/clones each selected String through actual get, and appends
separator/value text into an owned accumulator. The shared vector is retained.
Native moves preserve the accumulator allocation; each selected String clone
is explicit. JS/TS represents the same fold with actual imports and strict
Parameters/ReturnType witnesses. Source templates in all three languages cross
serialized/reparsed lossless CST. Fresh generated identifiers avoid the complete
original identifier census, including same-module helper collisions. Original
module CST, nested expression spans, comments and inverses are retained.

The JS/TS full API independently rechecks the entire changed module and helper,
reissues private semantic/meta IR and emits Rust/TS candidates. It never accepts
public helper metadata as type or caller authority. Native source proposals
still require the complete original namespace/type/effect/ownership and helper
checks. Missing/multiple native separators refuse; JS zero-argument join uses
an explicit comma. Ordinary Array coercion, original method ownership and body
equivalence remain unqualified. Inputs must be actual bounded String vectors
and scalar text; this draft does not silently coerce arbitrary JS elements or
separators. Capacity is 4,096 and text input/final output UTF8 is at most 1 MiB,
including a checked separator for empty vectors. Those resource and cloned
allocation differences are explicit. Empty get branches are unreachable for a
stable bounded vector; the full semantic proof remains an independent duty.

Independent native whole-source/helper/discovery/CST/collision/comment/refusal
cases, both owned JS/strict TS/interpreter/meta/canonical-inverse/full target
cases and a complete native standard-library oracle source are drafted. All
are UNRUN. No tests, parser, translator, preparer, compiler or experiments ran
locally, and CI/review feedback remains uninspected. Complete source equations
include the old native scoped/discovery implementations and every new source.
All broader production, owner, parity, freshness, performance and receiving
qualification remains OPEN. Ordinary-array construction/adoption composition
and wider vector operations still require source work.

Performance qualification is explicitly OPEN. The portable helper composes
existing get and append interfaces; those JS interfaces can revalidate a shared
vector or accumulated text on repeated calls. No linear-runtime claim follows
from the helper's single loop. A whole 4,096-element / 1 MiB output case retains
its original 60-second deadline, raw synchronous elapsed evidence and full
boundary/refusal cases in both interpreters. It is source only and UNRUN.
A future optimized runtime path must preserve fresh whole-source/private caller
checks, the independent fold result, all bounds and the no persistent-cache rule.
