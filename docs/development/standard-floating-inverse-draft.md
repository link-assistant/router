# Source-bound standard floating calls and shared inverse machinery draft

`proposeForwardStandardFloatingBodySynchronization` extends the explicit f64
body format with actual original imported standard runtime calls. Project mode
`"inverse": "standard-floating-bodies"` selects it. Every established module API
keeps its original behavior; the new small module shares copied source mechanics.
All implementation and independent regression source remain unrun.

The candidate table joins the original compiler's actual named import from its
canonical `runtime/float-runtime.mjs` path with the real frozen `FLOAT_CONTRACTS`
registry. Aliases retain their exact imported/local names and source spans. A
matching identifier alone, an import from another module or a caller-provided
record grants no owner/type permission. The whole changed function is censused
for parameter and lexical shadowing, including future declarations, before any
candidate call is lowered. Arity and all existing expression restrictions remain.

Native proposals use the actual f64 inherent method path. The original checked
Rust frontend must independently reissue the actual primitive owner, argument
types, const eligibility and sign-refinement obligations. Moving a sign call
outside its supported checked zero branch remains refused. Floor, finite/NaN
classification and supported zero sign cases retain their matching runtime code,
complete target equation and independent native oracle obligations. No Math or
Number reflection/call fallback is introduced.

The shared support file is a complete original implementation copy with source
histories. A reusable derived-module producer selects three actual original
function declarations through the lockfile TypeScript syntax tree, checks their
complete before bytes, applies the explicit function substitutions, then adds
shared support imports in the separate repository sequence. It serializes and
reparses both complete source equations, verifies final native binding closure
and rechecks every original/recipe/current source. Full original modules and
recipes remain pinned; no guessed function boundary or module-wide source-owner
waiver is used. This keeps future rule families below the repository file limit
without repeatedly growing copies of every old API.

Source preparation is data construction, with `sourceAuthority: false`,
`semanticAuthority: false` and `receivingExecuted: false`. It introduces no
alternate semantic checker or persistent source/owner/verdict cache. All actual
translation still recompiles the complete modified source through the original
JavaScript Rust frontend and retains the full census, types, guards, paired CST
inverses and guarded project transaction. Native Rust tools remain CI-only after
all same-SHA JavaScript stages pass.

Independent source covers JS/strict TS floor/IEEE classes, NaN and zero sign
truth tables, actual import aliases, wrong modules, shadow/future declarations,
arity/argument/refinement refusals, older API behavior, complete source extraction,
project/export integration and native Rust oracles. All are unrun. Broader
standard/owned/slice/generic/recursive/async domains, namespace bootstrap,
production adoption/parity and every other incomplete requirement remain open.
