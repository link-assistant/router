# HTTP/control callers through transparent named module exports: source draft

All new implementation, receiving, strict TypeScript and native inverse case
source is **UNRUN**. No compiler, parser, translator, preparer, tests, CI status/
logs/reviews, installs or builds were executed during drafting. No executable
coverage or parity claim is made.

`tools/translation/network-control-bulk-20261101.mjs` adds a concrete shared
syntax prerequisite: complete HTTP/control callers may import existing qualified
operations through a closed graph of actual transparent named-value reexports.
The existing HTTP source checker requires direct imports from registered runtime
modules; it previously refuses these caller modules at the import boundary.
The new adapter resolves complete actual barrel sources, proposes direct imports
and then runs the same original whole-body/private source check. It neither
invents a network ABI nor weakens the original checker domain.

Each transparent application module must contain only nonempty named value
reexports from ordinary relative `.mjs` modules. All exports, including unused
ones, are resolved. Unknown/missing symbols, wrong runtime owners, side effects,
star/default/type exports, import attributes, ambiguous duplicate exports and
cycles refuse. Graph depth/count, syntax cells, individual/aggregate dependency
retention and original complete source/CST limits remain bounded. Resolution is
local to one synchronous operation; no input, binding or verdict cache survives.

The adapter preserves the complete depth-first dependency loading order of each
erased transparent graph, including modules supplying unselected exports. It
emits checked unused named imports for those dependencies before the actual caller
bindings. Fresh local names avoid every original native identifier; actual local
aliases and all JSDoc/typed body references retain their original meaning. The
full original import source, spans and trivia remain in complete CST/source
inverse equations. The emitted source is a reviewable canonical direct-import
proposal. Nothing is installed automatically.

The actual ordered pipeline has exactly `language`, then `repository` phases.
Original caller and complete barrel files cross serialized/reparsed CST before
native import/export selection. The canonical whole caller enters the original
HTTP checker, semantic meta is independently read/reissued, both JS/TS target
bodies enter fresh original checks, and the complete canonical Rust source enters
the original native inverse with whole Rust reproduction. The original complete
forwarding graph is resolved again before return. All native/runtime/declaration/
Cargo/type/move/loan/effect/Result/cleanup checks remain the existing issuers'
obligations. Public source names, tables and source hashes grant no authority.
The shared source-failure protocol revokes enclosing operations on observed
private validation failures. Complete original HTTP-input and owned-core closing
validators both run on success and failure, preserving the primary thrown value.

The additive receiving harness pins the physical repository lockfile compiler to
TypeScript 5.9.3 via `--version`, preserves the complete strict NodeNext/ES2022
command and 20-second process bounds, records original diagnostics/results and
cleans temporary files in `finally`. Independent source cases compare original
forwarded JS, canonical JS/strict TS and native-inverse outputs against real
loopback HTTP behavior: buffered Unicode text, one owned stream chunk, explicit
stream/client cleanup, malformed requests, deadline Timeout and parent
cancellation. They also retain formerly refused import and source/ownership/
cleanup/cycle/side-effect refusal cases. All remain UNRUN.

## Actual production relationship and remaining integration

Source review included `rust/src/subscription_usage.rs::bounded_response_bytes`
and `rust/src/provider_proxy_relay.rs::settled_relay_stream`. The first consumes
reqwest chunks with content-length/aggregate limits and explicit read errors;
the latter includes per-frame accounting, stream identity rewriting and terminal
settlement. These are actual production requirements, not qualified callers of
the narrow compatibility core. This source batch does not translate those whole
functions or equate their 2 MiB/storage/settlement domains with the existing
transport core's distinct bounds. The separate JSON state contracts were also
reviewed; no state ownership or behavior is inferred from network spelling.

The concrete new supported source shape is transparent operation forwarding for
otherwise fully checked HTTP/control callers. Production barrel adoption,
function-body migration, actual runtime source materialization, whole-tree
synchronization, public dispatch/source profiles and CI case inventories remain
coordinator integration work. The paired outputs use canonical direct imports;
reverse Rust regeneration cannot recover original barrel spelling without the
retained complete source equation. This is an explicit source proposal boundary,
not a claim that canonical Rust alone reproduces arbitrary application layout.

Inputs remain complete source snapshots under the existing private source
context. The adapter does not claim independent physical closure of application
barrel paths or arbitrary Node module-resolution/package/conditional-export
behavior. Registered runtime/native source checks remain mandatory. External
packages, initialization side effects in erased barrels, namespaces, default or
star exports and cyclic forwarding are outside this profile. Broader streaming
backpressure, settlement, request retries, target/platform matrices, complete
production graph/dependency/configuration admission, real application coverage,
performance measurements and all receiving/full same-SHA gates remain OPEN.
This supplies additional source receipts toward F03/V03/O04/T04 only; it does
not close those broad rows or authorize local execution/Rust tools.

The independent CI-only oracle source
`rust/tests/network_control_bulk_20261101.rs` exercises matching direct native
buffered/first-chunk Unicode behavior, explicit stream/client cleanup and nested
deadline/cancellation distinctions against a bounded loopback server. It is also
UNRUN and does not establish equivalence of transparent module initialization;
that source transformation is covered separately by original/canonical receiving
cases and retained full dependency-order evidence.


Complete return accounting uses the existing additive
`accountPrimitiveVectorIteratorBulkData` helper with independent 16 MiB UTF16-unit
and UTF8-byte caps, 2,000,000 occurrence cells and depth 160. The complete final
object is checked after adding its trace, including every duplicated forwarding
module/dependency/CST/equation/checked-meta/program/paired/native/reverse/source
field. Shared aliases count once per retained path; no persistent seen/cache
reduces accounting. Intermediate complete forwarding proposals also pass this
bound before replay comparison. Replay compares explicit bounded records and
full primitive sources, without whole-result `JSON.stringify`. Oversized complete
results refuse; the input budget does not grant a larger output allowance.

Source review of the original HTTP import checker confirms that it rejects
competing local bindings and checks each operation's exact runtime owner. It
permits the same actual export under distinct unique local aliases. Dependency
retention uses those ordinary rules unchanged; the original whole checker still
processes every inserted import. Independent UNRUN source cases include direct
original-checker reentry, duplicate-local refusal and complete UTF8/repeated-path
output accounting.
