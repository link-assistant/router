# ASCII base asset source schedule

The new ASCII source profile still needs the complete original base runtime
closure. Its JSON declaration contains the full named data aliases: it cannot be
replaced by handwritten primitive declarations or a guessed byte/hash record.
`prepare-core-ascii-base-assets.mjs` derives the 33 selected rows from the original
base function's native root literals and the native import/export fixed point of
fresh complete outputs of `hostRuntimeAssetsNamedDataAliases`. Notices remain
selected, including the source-derived retention dependency closure.

The new producer copies the actual HostChecker/program, types/aliases,
namedAliases and private files declarations. It copies each selected original
set statement and file-loop body, retaining the selected original literal nodes.
The JSON declaration family keeps its complete original body and actual original
`json` literal. Its HostChecker, hostData, HOST_CONTRACTS, typeScriptAliases,
typeScriptType and retention dependencies keep their actual native import and
lexical bindings. No runtime body, declaration, alias or Rust type is handwritten.

This is an explicit new I/O and declaration-generation schedule. It still executes
the full actual HostChecker/hostData and aliases computation and the JSON family
builder. It omits unrelated asset reads and the time/integer/float declaration
builders. It does not claim their callback or side-effect schedule is preserved.
The two old full asset builders and the public `ownedCoreRuntimeSources` function
stay unchanged. Contexts without the explicitly installed canonical ASCII runtime
keep their existing source selection and callback path.

The generated helper freshly reads and compares/hashes its complete source and
the complete original host and retention producers. Every call computes the
selected assets again and compares/hashes all 33 complete strings, including the
dynamically generated JSON declarations, against the source proposal's fixed
complete originals. Fixed primitive source data is not a cached validation or
issuer. New native guards surround copied statement/iteration boundaries; private
native get/size operations protect the final full output comparison. The ordinary
source context still hashes every supplied complete input and proves its actual
Rust facade/dependency ABI. No public metadata, source spelling or extra flag
grants dispatch, owner or native/runtime parity authority.

The new three-file base layer follows the original three-file ASCII asset layer.
Every historical source equation, native AST copy and full CST inverse remains.
All five current wrappers, vector refresh and current reverse assertions consume
the final source mapping. The old asset CLI now materializes/checks its five-file
current composition; its birth API stays exact. The new base-only CLI is
`node tools/translation/prepare-core-ascii-base-assets.mjs --write|--check`.

`router-core-ascii-base-assets.test.mjs` has four complete 60-second cases. They
retain all native/CST source equations and tampered predecessor refusal, compare
all 33 outputs and paired paths with the independent old public builder, parse
every complete selected JS/declaration, diagnose omitted unrelated reads, reject
each changed selected input, and observe fresh complete hash inputs and native
refusals. The original reverse ASCII semantic case and deadline are unchanged.
This source draft makes no timing claim. Runtime, generation and Rust qualification
remain receiving obligations.
