## Batch agreement and repair of the original bulk draft

Source review found an omission in the original bulk draft: one generated native
write could change another child's captured dependency while the second child
retained a stale peer. Each child now retains a complete invocation-local input
byte map and its actual output rows. Bookkeeping no-op children retain their
watched input bytes too. The new shared DATA helper,
`paired-sync-dispatch-20261101-after-agreement.mjs`, requires every child that
consumes a changed output path to independently propose the exact same complete
before bytes, after bytes and mode. A differing/missing proposal refuses the
entire operation before installation.

Both the original bulk implementation and additive dispatch copy call this
same helper. The original bulk change is fail-closed only: it adds no planner
kind, authority override or semantic admission. All earlier original-bulk cases
remain byte-for-byte intact; two independent cases are appended for a stale
no-op consumer refusal and agreement by two real single-authority producers.

Complete identical output rows merge once. Different complete outputs for one
path refuse, even if someone could manually merge their disjoint spans.
Independently authored source paths are protected across all units, including
units processed later. The bulk and child manifests remain protected outputs.
No-op observations cannot authorize a dependency write. Shared whole-native
universes therefore require all affected children to agree on the entire changed
native files; speculative merges across partial source maps are not attempted.

A concrete supported batch has two project manifests with the same native entry
and common Git baseline, distinct physical paired targets and distinct metadata
outputs. Both authored pairs make the same canonical edit. Each independently
checks against the unchanged native source, both propose the same complete native
after bytes, that native output merges once, both reviews remain distinct and
all four authored target files stay exact. If either pair requests a different
native result, or one unchanged pair consumes the source without independently
agreeing to its after bytes, the complete batch refuses without writing.
