# Bulk and physical receiving unit adoption source draft

SOURCE ONLY. Bulk/physical implementation, strict paired and independent
behavior, lifecycle, source-history and refusal cases are UNRUN. Whole drafting
and all qualification remain OPEN.

A new receiving request explicitly selects newNativeModule true with an
unrecorded JS/TS path pair, complete authoritative source and an actual direct
inline module route. The source-driven adoption API privately checks the full
new namespace and every emitted function. Bulk composition rejoins its actual
original parent and exact insertion boundary. Multiple independently checked
append fragments at a shared source boundary compose in deterministic request
order. Ordinary retained body changes, checked function additions/removals and
new sibling modules retain the same full proposed-project membership and body
checks. Public dispatch fields and module equations grant no semantic authority.

Physical bulk manifests may now record an empty-binding new source unit with
adoption set exactly to new-inline-module and a nonempty nativeRoute. Only
explicit JavaScript or TypeScript authority can select this request. The
authoritative file must physically exist; its companion must actually be
absent. Both current source bytes and null companion absence are physical
closing/installer inputs. Every runtime/declaration dependency remains required.

The ordinary bulk planner writes complete new native module bodies and paired
sources, then replaces the transient adoption marker with complete ordinary
bindings in that unit's descriptor. Existing index and source-unit APIs retain
their contracts; the bulk CLI uses the explicit checked manifest without new
hidden mode or altered worker limits. Repeated synchronization uses the ordinary
recorded binding path. Complete Git authority checks, private source reissue,
closing fences, fresh installer reconstruction and rollback remain mandatory.
A newly created companion, changed native file or altered marker refuses.

Three complete source equations retain all original implementations and source
inverses under language then repository. Independent unrun cases draft two new
modules at one parent boundary, retained sibling updates, both languages,
already-present authoritative files, null absent outputs, full ordinary repeat,
invalid ownership/dispatch/namespace requests, physical descriptor transitions
and stale application. Source companions use js/src and ts/src through explicit
manifest paths. New external native files, missing parent module chains,
cross-unit dependencies, broader source families and full translation remain
OPEN. Coverage, parity, freshness, resources, receiving export, platforms and CI
remain OPEN. Fatal Rust remains CI-only after eight same-SHA JavaScript gates.
