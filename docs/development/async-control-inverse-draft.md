# Canonical async resource Rust inverse draft

The new explicit inverse copies the complete original canonical Rust reader and
filesystem inverse consumer using native class/function/import substitutions.
It adds tuple bindings, mutable borrows and dereferences, unit values, standalone
effects and move/async/move closure observations. Every such observation remains
source data; no parsed node grants a loan, move, future or executable permission.
The original reader and consumer keep their existing contracts. All new source
and independent cases remain unrun during bulk drafting.

The inverse proposes JS imports, operation-derived resource input types, guarded
Result bindings, complete disposal branches, cold wrappers and deadline tail
callbacks. Compiler capture temporaries may propose their actual original
operand. Fresh source checking then reissues the complete control program,
serializes/reparses its semantic meta and emits native source. The original full
Rust input must reproduce token for token, apart from preserved trivia. An erased
borrow or temporary is never accepted merely because a projection was possible.

Original and projected CST are serialized/reparsed and retained with the complete
Rust source, JS projection, paired outputs and full inverses. Every actual native,
runtime, declaration and original cold-helper source remains required. A changed
borrow, await, cleanup branch, closure move, attribute or unrelated item refuses
unless complete fresh checking and authoritative source reproduction agree.

Independent unrun source covers handwritten native wrappers for sleep, nested
deadlines, channel send/receive and explicit receiver cleanup, exclusive callback
reborrows, JS and strict TypeScript behavior, all three source directions, full
inverses and refusal controls. The native behavior oracle remains gated CI only.
The result truthfully retains false native-grammar, Rust-execution, receiving,
parity and whole-Router flags. General Rust syntax, arbitrary futures/callbacks,
pending future storage, source-unit installation, broader numeric and HTTP
resource boundaries, namespace bootstrap and production adoption remain open.
