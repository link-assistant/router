# Complete source vector adoption DATA

The vector corpus adapter drafts explicit `crate::translation_core::vec!`
adoptions from complete original Rust sources. It copies the actual formatting
corpus, detached packet, bounded filesystem writer and independent readback
machinery through native TypeScript AST selections and serialized/reparsed CST
language/repository substitutions. The original formatting APIs and their
storage bounds remain intact. Every vector layer has its own exact schema.

The physical CLI considers every source discovered by the existing Rust layout
and bounded census. Selection currently covers free functions in a unique
active physical module's top-level body. Inline modules, implementation members,
unresolved/inactive modules and ambiguous repeated physical origins retain
their original source and explicit status. A complete corpus draft does not
mean every function has a supported adoption or executable translation.

```sh
node tools/translation/prepare-source-backed-vectors.mjs --check
node tools/translation/propose-source-backed-vector.mjs \
  --root /absolute/source/checkout --output /fresh/outside/packets \
  --packet-storage gzip
node tools/translation/propose-source-backed-vector.mjs --review /fresh/outside/packets
```

The materialized `proposeSourceBackedCoreVectorCorpus` API and detached
`iterateSourceBackedCoreVectorCorpusPackets` API resolve the complete actual
module graph and instantiate a fresh private original-producer inspection
context. The graph's complete actual compilation profile is forwarded into
the vector adopter rather than replaced by its standalone default. Only
genuinely closed producer attributes and proven inactive items
are blanked in temporary inspection DATA at identical source offsets. All
original attributes, comments, inactive items and other source bytes remain in
the emitted proposal. The only adoption edits qualify actual bare vector API
tokens. The vector adopter retains its conservative local-item and other-macro
barriers, including nested opaque macro bodies.

Archives retain complete original source rows, module/ancestor/macro-producer
origins, all optional package/lock/workspace Cargo inputs, inspection CST and
inverses, complete per-file proposal CST/mappings/inverses, graph edges and
diagnostics, and every changed after-source. The writer rechecks the physical
source and Cargo census before publication. The independent reader consumes
every listed compressed packet and checks original source associations,
partitions, inverses, exact vector schemas and summaries. Storage integrity
does not recreate a private compiler context or grant executable authority.

`inspectVectorProposalData` independently joins selected function names and
spans to complete original items and verifies that their edits form disjoint
sets of actual bare vector tokens. Thus several macro calls in one function
count once; equal function names in different physical modules remain distinct.
Neither repeated physical contexts nor overlapping diagnostic categories add
function gains. Archive summaries count distinct proposed functions, not fresh
semantic admission or production coverage.

A later formatting-to-vector sequence must pass the complete edited source map
into a new vector invocation, creating a new real graph and private inspection.
Coordinates from the original phase cannot be reused after length-changing
formatting edits. Both phases' complete source/CST/inverses must be retained;
the standalone vector command does not install or implicitly compose stages.

The seven-case receiving source covers source-generation equations and quotas,
full materialized/stream/archive equality, complete derived/inactive Unicode
source and strict JavaScript/TypeScript targets, ancestor/body producer refusals,
distinct function counts, mutated/copy source controls, CLI/transport corruption,
and final package/lock/workspace rechecks. All six generated source outputs
and their complete native TypeScript/CST equations passed under a bounded
source-only run in 17.30 seconds with 504,053,760 bytes peak aggregate RSS.
Complete source inputs, before/after CST, serialized inverses and the earlier
pre-profile-forwarding and pre-trivia-cleanup source receipts are retained.
Only native whitespace trivia outside literals/comments is removed in the
repository source-generation phase; complete actual template bytes remain in
the source inputs and inverses. The focused receiving run
and actual complete physical production draft remain unrun; the coordinator
will qualify those separately. The historical 31
`vec!` first refusals and 155/2567 executable functions remain historical hints,
with no new production coverage claimed by this DATA machinery.

Every CST inverse proves exact source fidelity only. The owned-core reverse
expression dispatcher currently lacks generic vector literals and registered
vector operations; this corpus draft does not establish executable reverse
translation or bidirectional coverage.
