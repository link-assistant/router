# Standard JSON loop adoption source draft

The separate loop adopter copies the complete iterator adopter, bounded packet
producer and fresh checked installation transaction. Source rules select a
closed shared-JSON slice loop with one mutable canonical accumulator, one
assignment per iteration and its final accumulator tail. Direct slice and
explicit `.iter()` forms are supported. The target uses the existing native
owned `json_fold` interface and its matching canonical runtime.

The original initializer and update expressions remain complete source. Closed
owned-core operations and known iteration/accumulator JSON clone sites have
source substitutions. General control, unknown calls/effects, mutable slices,
generic bodies, source producers and competing names remain unchanged. This
is an explicit API adoption candidate: old Iterator/Clone dispatch and Drop
timing are unproved, and no candidate is executable permission.

`proposeCoreJsonLoopCorpus` emits complete source/CST proposals. The separate
packet module adds `json-loops`. `planCheckedJsonLoopAdoption` recomputes actual
physical/Cargo/Git inputs and requires every selected complete replacement
function to freshly translate through the existing private forward compiler.
Apply retains its original source protection, byte limits, transaction and
rollback behavior. Full original source and inverse equations remain reviewable.

Three complete original implementations, ordered language/repository rules and
independent actual Rust loop, strict target, refusal, packet and installation
regression source are drafted and unrun. Production application, general
forward loops, broader control/effects, native parity and the remaining full
requirement ledger remain open.
