# Mutable native Vec helper initializer source draft

Three complete source equations add a separate source checking route for an
actual parsed mutable let whose ordinary same-module helper returns a primitive
owned Vec. Original let membership and parser origin, the unchanged whole
original function, original checker identity, actual function lookup/signature,
checked call target, owned primitive return and source closing joins are required.
The original core-initializer API, owns flag and prior refusals remain unchanged.

This route is temporary checking permission. The complete typed call still
selects the existing helper graph lane, which must rejoin every complete
current caller/callee body and validate argument domains, bounded owned/shared
entry guards, moves, loops, loans, acyclicity and all dependencies before any
projection/emission is issued. A public name, signature or return candidate
does not qualify a body. No private completion verdict or across-operation
source/owner/result cache is added.

It covers helper-created mutable accumulation, helper-only move/rebinding,
shared slice copy helpers and bounded owned helper inputs. Foreign modules,
recursive/unsupported helpers, unguarded owned inputs, duplicate/moved vectors
and inconsistent loop paths retain refusal. Both reverse lanes already support
mutable Vec local calls and canonical Rust let bindings; no native library API
or root/history step is added.

Independent eleven-domain native/JS/strict TS source cases cover those callers,
source extrema, frozen/fresh outputs, nested helper graphs and refusals. Full
source/CST inverses and original two-phase preparation cases are drafted.
An independent public-core Rust oracle also covers helper-created mutable
accumulation, extrema, bounded moves and copied index/length results in all
eleven domains. Every case, freshness/parity/performance/receiving check and
Rust CI is UNRUN.
Original global namespace/producer closure, broader collection adoption and
whole repository synchronization remain OPEN.
