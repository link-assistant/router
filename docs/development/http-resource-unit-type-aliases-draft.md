# Paired TypeScript alias retention draft

Resource source units now preserve original type-only declarations after a
JavaScript or Rust authority edit. The complete old TypeScript source is checked
afresh. Native syntax selects each alias and its real imported operation query;
only actual query identifiers are rewritten when an import would collide with
a new binding. Matching real bindings are reused to avoid accumulating imports.
All original declarations and comments remain in the proposal.

The complete new TypeScript target then re-enters the original translator and
must reproduce the authoritative Rust syntax. Type data grants no ownership,
source or executable permit. Language then repository rules retain full old
and generated targets, original query spans, complete serialized/reparsed CST
equations and both inverses. Existing physical capture, Git conflicts, fresh
proposal comparison, atomic installation and rollback remain in force.

Independent unrun source covers successive TypeScript, JavaScript and Rust
edits, exported declarations, comments, changed native behavior, import-name
collisions, unsupported old aliases and forged physical plans. The complete
source-unit/caller originals and native-selected substitutions are retained.
No translator, preparer, runtime or CI has executed for this draft. Generic and
method domains, namespace/bootstrap, production parity and all other unfinished
bulk requirements remain open.
