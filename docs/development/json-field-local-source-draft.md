# Shared JSON field and index local source draft

All implementation, source histories and independent cases are drafted and
unrun. No current executable coverage, target/native parity, source freshness
or complete translation/synchronization result is claimed.

Both existing JSON field adapters now use the shared chronological engine for
immutable shared-Json receiver aliases, text key aliases, owned String.as_str
views and usize index aliases. Direct explicit owned-text views and native
usize arguments remain whole once-only argument expressions; indices receive
an explicit as-u64 bridge to the existing paired core. Literal native counts
retain the bounded common profile domain. Typed, unknown, future and ended-scope
locals remain unproved rather than acquiring a role from an annotation.

Original source-captured shadowing, callback/match binder checks, unknown
producer refusals and complete native core/module/dependency/currentness checks
remain. A new local's own unique declaration is not treated as shadowing itself;
callback binders that replace that local still invalidate its candidate role.
Distinct parameter names are checked in one source pass. Shared source DATA
does not issue ownership, lifetime, trait-dispatch or executable permission.
Every complete adopted function still has to qualify independently.

The field/index/scalar-reader catalog and paired native/JS/TS/reverse contracts
stay in use. Both adapters now use real shared neutral language call rules and
repository prefix substitutions; eighteen existing adapters share that planner.
Source/cell/token/frame/binder bounds, phase names, fixed stage membership and
full serialized/reparsed CST/source inverses remain. No cross-operation source,
hash, owner, verdict or result cache is introduced.

Five complete source equations retain original implementations and native
owners. Independent unrun source covers seven actual lookup forms, owned/key/
receiver scopes, shadow/refusal controls, null/false/empty/Unicode/missing/proto
keys and index boundaries, both APIs, the fixed bulk stage, fresh receiving JS
and strict TS, native borrowed field identity and complete source histories.
Every wider source/native/production/sync/freshness/parity/delivery requirement
remains unfinished.
