# Increase translation progress per development cycle

Continue [#772](https://github.com/link-assistant/router/issues/772) and
[#759](https://github.com/link-assistant/router/issues/759). Optimize for newly
executable production functions and complete synchronization, rather than lines
generated, proposed substitutions or the number of small tests passing.

## Change shared contracts, then regenerate the whole family

Use the smallest checked application language that can express Router's logic.
Keep native framework and library internals behind matching Rust, JavaScript
and TypeScript compatibility-core APIs. Translating Axum, Tokio, serde and every
standard-library implementation is not a prerequisite for translating callers
of explicitly qualified, behaviorally equivalent owned operations. Their native
internals and unsupported uses remain listed separately.

For each operation family, carry its actual Rust source binding, types, effects,
ownership and error contract through the language rules. Repository rules bind
the qualified facade and target imports. Use one operation description to drive
the corresponding forward and reverse rule registrations, target declarations
and source-adoption proposals. Derive implementations from actual existing
implementations through CST substitutions where applicable. Independent shared
behavioral fixtures and Rust oracle source must remain independent of that
description; generating both expectations and implementation from one table
would miss a shared mistake.

An operation is complete only when actual production callers translate, emitted
JavaScript and strict TypeScript execute, reverse regeneration retains the
contract, and gated Rust CI verifies the Rust projection. A registered spelling,
an opaque preserved body or a successful source rewrite proves none of these.

## Keep each feedback cycle short and honest

Draft the complete known family batch before receiving: language and repository
rules, matching compatibility implementations, applicable reverse mappings and
independent cases. Review shared causes and repair the batch together. Do not
alternate a small rule edit with expensive whole-corpus regeneration. When a
check discovers another prerequisite, add it to the coordinated batch rather
than counting the partial draft as completed behavior.

Implement a family through separately declared language and repository
substitution sequences, preserving serialized/reparsed CST and checked semantic
boundaries in both directions. Test actual original bodies alongside small
independent boundary cases. Run complete focused Node and Bun files and strict
TypeScript before expensive corpus regeneration. Preserve all callbacks,
refusals and original case deadlines; a late synchronous TAP pass remains red.

Keep source-preparation changes behind narrow modules where possible. Preserve
immutable historical source and golden evidence; regenerate current artifacts
with the actual producer. Repair shared fixture loaders in bulk rather than
manually changing expected hashes or creating one special case per test. A new
source fingerprint requires a fresh complete current compiler/export check.

Run one expensive workload at a time. Profile slow paths before retrying them.
Within one genuine invocation, share existing authenticated contexts and avoid
retaining duplicate strings and metadata. A storage or process-lifetime change
must preserve all original complete checks and output bytes. Do not introduce
across-invocation source, hash, owner, verdict or encoded-result caches, or
increase heap, case, disk or evidence limits to hide a failure.

After a published head finishes, collect every job and full failed/cancelled
stream once, group failures by shared cause, and draft one coordinated repair
batch. Keep independent source work moving while CI runs. Commit coherent
checkpoints at least every six hours during active work; publish only through
the sole coordinator with accurate failed/unrun evidence. Continue alone under
the user's current instruction and never invoke a local Rust tool.
