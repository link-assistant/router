# Original numeric Option and Result ingress guards

Public signed primitive Option and textual-error Result parameters now require
a complete original successful-payload guard at the actual entry. The source
rule requires the exact Some/Ok discriminant, the same parameter's `field0`, a
BigInt check, both original integer bounds and the complete canonical invalid
payload throw. It cannot qualify an omitted, weaker, inverted, other-parameter,
late or duplicated check. Guard records and written types must retain the same
actual native domain. Existing scalar entry guards remain intact.

The constructor and payload are checked independently of an annotation or copied
record. None/Err do not evaluate the successful numeric payload check. The whole
body still controls moves, Result/Option propagation, cleanup and every returned
root. Concrete generic forwarding preserves that complete owning container.
The existing public u64-container admission is retained; an explicit canonical
u64 payload guard can use the same source rule. Broader nested containers and
other error-family numeric guards remain separate obligations.

Canonical native inversion derives the real parameter domain, emits its complete
matching guard and reproposes the genuine current operation-derived type. Full
JS/meta checking must reproduce the complete original Rust tokens. The five
previous implementations, ordered language/repository substitutions and whole
CST/source inverses are retained. No generated application output was edited.

Independent JS, strict TS, native inverse, signed/unsigned boundaries, inactive
constructors, forged-meta and refusal cases plus a native range/constructor
oracle are drafted and unrun. No compiler, test, experiment, preparer, translator,
generation, local Rust tool or CI ran. Recursive containers, broader numeric/
language domains, namespace/bootstrap, production parity and every unfinished
bulk requirement remain open.
