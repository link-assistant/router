# Original derive helper namespaces

The private original derive context now recognizes exact nested `serde` and
`default` attributes through their actual source registrations. Locked
`serde_derive` declares `attributes(serde)` for Serialize and Deserialize. The
pinned core Default declaration registers `attributes(default)`; the existing
Default input proof retains its actual selected plain unit variant.

Recognition joins the genuine source dependency, original invocation, complete
module/view/profile identity and exact attribute span. Active original ancestor
attribute footprints, relevant bindings and tracked module bodies remain
required. Public certificate copies, fresh-process serialized metadata,
changed views or source, unresolved imports, shadows, unknown attributes and
conditional/inactive declarations cannot supply ownership. A fresh process can
reconstruct a new proof from the complete unchanged original sources.

This proves that the specific registered helper is inert. It does not prove
generated bang output, complete namespaces, trait execution, Copy, no-Drop,
callback execution or const eligibility. Serde callback paths remain retained
source syntax. The namespace-only Serde facade projection does not participate.

The matches context also consumes the existing independent derive bang output
context. Every actual output owner must still be proved before the unchanged
active type/bang/attribute scope guard permits an original matches invocation.
Ordinary checked expansions execute through the existing source-derived match
IR in JavaScript and strict TypeScript; const matches remain refused.

For unchanged whole `src/model_contract.rs`, the four nested registered helpers
are recognized. Its six production declarations still have 46 derive owners,
16 selected outputs and 30 residual owners after the independent
[Eq data namespace stage](builtin-eq-data-namespaces.md), which adds two original
Eq owner closures to this helper stage's 14/32 observation. The module's bang scope stays
unresolved, `ModelSelectorKind.permits_resolution` stays refused, and its
independent const, Deserialize, ownership and upstream-method obligations are
preserved. This change does not claim an original whole-module executable gain.
