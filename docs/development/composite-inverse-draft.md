# Deterministic complete-batch inverse composition draft

`proposeForwardCompositeSynchronization` composes existing source substitution
formats in one complete proposal. Project manifests select
`"inverse": "composite-bodies"`. Implementation, source preparation and all
regression cases remain unrun during the complete bulk drafting phase.

One actual original project compile supplies the target function names and
complete current census. Native syntax and complete CST serialization/reparse
supply scheduling candidates, never type or ownership authority. Headers,
imports, generated helpers and source outside those original function bodies
must remain exact. Candidate rules use no injected compiler, caller registry,
persisted verdict or cross-invocation cache.

The language sequence schedules at most three deterministic complete batches:
existing scalar literals; original checked text predicate method tokens; then
remaining supported scalar/numeric/control bodies. It stages literal and method
edits in the same function while preserving every other original token. Each
batch invokes the original complete source proposal with all current sources,
rechecks original input membership and exact adjacent before/after sources,
and retains every full native source inverse. Unsupported source still refuses;
there is no expensive per-function trial search or swallowed checker error.

After all batches, the original compiler checks the entire final source again,
including its distinct serialized/reparsed checked semantic meta. Complete
executable, refusal, ordinary-method and generated-method census must remain
unchanged. Every requested function body and static type must reproduce under
the existing native body comparison, while all surrounding source stays exact.
The separate repository sequence retains final full original Rust and paired
JS/TS CST equations and inverses. Project installation still freshly recomputes
the complete proposal before the original atomic transaction.

Only changed native files and their complete inverses are retained per layer;
untouched full-project source inputs are captured once. Complete layer target
sources remain inspectable. A 192 MiB retained raw-source budget and existing
per-file, full-input, CST/native syntax and case deadlines remain explicit.
This bounds accounted raw source, not every JavaScript object allocation. No
measured speed or memory improvement is claimed before receiving verification.
The source preparer selects the complete original numeric proposal function,
retains its whole original source, applies separate language and repository
substitutions, and validates native source bindings when later executed.

Independent unrun source combines string literal and method edits in one
function with unrelated numeric, control and label edits under both JS and
strict TS. It checks adjacent full native histories and independent expected
Unicode, Boolean and integer-boundary behavior. Native scheduling, type/header,
unknown method, source-reader mutation, original/export source histories and
project transaction cases are also drafted. This composition covers only the
existing admitted source families. Wider owned/aggregate/generic/recursive/async
bodies, namespace/bootstrap, production adoption/parity, freshness, receiving and
all remaining requirements stay open.
