# Operation-local proof DATA byte composition

This additive source draft scopes the existing complete immutable DATA composer
and its byte-store policy to one explicit synchronous operation. It changes no
current serializer, proof issuer, arithmetic-only scope or default import.

```sh
node tools/translation/prepare-operation-proof-byte-sources.mjs --write
node tools/translation/prepare-operation-proof-byte-sources.mjs --check
```

The source producer uses native TypeScript 5.9.3 import/export/fallback spans to
copy every declaration of the pinned complete `private-frozen-json.mjs` into a
private lexical frame. Language and repository sequences retain the complete
original, intermediate and final CSTs, native bindings and both full inverses.
The five original composer fallback calls delegate to the actual original scoped
serializer after retiring all operation-local encoded entries. The original
module and every original Hash site remain unchanged.

The generated `withOperationProofByteComposition(run)` supplies one serializer
to `run`. The serializer performs the existing complete fresh immutable-data
preflight and current intrinsic checks. Repeated immutable syntax fields may
reuse their exact original composition bytes while complete root payloads are
rebuilt. This is a separate byte-format operation, not an extension of the
arithmetic-only proof scope and not a source, namespace or semantic permit.
Every original source/owner join and complete Hash.update/digest payload is
still required in a real consumer.

The original policies remain: 16 entries, 8 MiB retained bytes, 4 MiB per entry,
200,000 logical cells and depth160, together with the original composition text
budgets and fallback. A nested operation uses the original serializer, so it
allocates no second operation byte store. The outer serializer is suspended
until the nested operation closes. Every exit retires local encoded entries
with captured native operations; an escaped serializer refuses after closure.
No new encoded result survives an operation. Existing legacy caches retain
only their unchanged original policies.

Unknown DATA, changed JSON/prototype/intrinsic hooks and uncertain values keep
the complete original serializer/composer fallback. Operation-local byte state
is cleared before those legacy callbacks run. Native own-descriptor/prototype
inspection rejects proxy results, Promises and own or inherited thenable fields
without reading their getters. Returned async work cannot keep a byte frame
open. Nested, throwing, fallback and normal exits retain separate controls.
