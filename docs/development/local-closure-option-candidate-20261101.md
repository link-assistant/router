# Whole local closure and Option source candidates

This new family is **SOURCE ONLY, UNRUN, uninstalled and non-authoritative**.
It does not modify the committed scalar170 profile, any library or compiler
hook, existing parser flags, source issuer, namespace rule or old refusal.
The private original typed local closure issuer described in
[the design](local-closure-option-lowering-20261101.md) remains unimplemented.

`proposeLocalClosureOptionCandidates` accepts complete fixture module images,
entry and Cargo manifest/lock DATA, preserving the existing 128-file / 4 MiB
fixture envelope, 2 MiB source, 256 source-version and 16 MiB occurrence bounds.
It retains every supplied original module and every source-selection residual.
This fixture interface does not replace the scalar family's original opaque
production corpus interface or raise its resource limits.

The language phase resolves original source module views through the actual
module graph, selects ordinary whole function owners and drafts direct local
closure expansion. Typed immutable arguments have explicit primitive/shared
str source roles. Function-parameter captures and earlier local closure
dependencies are lexical source DATA only: written immutable shared or Copy
roles do not certify actual type, ownership, purity or capture semantics.
Unknown free names, mutation, move, escaping/forward/recursive closures,
ambiguous shadowing and unsupported binding/producer grammar remain residuals.

Every actual call evaluates **all** arguments once in written left-to-right
order into fresh hygienic block lets, including unused arguments. Only after
those evaluations does it bind the original parameter names in the new block.
The original closure body identifiers, comments and format literal bytes remain
unchanged. Earlier closure calls inside a later body expand recursively with
the same rule and original declaration order. This avoids inventing spans or
rewriting names inside strings. Deleting the original closure declarations is
an explicit proposed source migration, not an original construction/Drop or
typed closure equivalence claim. A fresh real checker may refuse the proposal.

The repository phase drafts a narrower two-arm candidate for a direct written
`Option<u64>` parameter with two inline primitive owned formatter bodies. It
uses the actual existing `u64_to_text_owned_map` and
`text_owned_unwrap_or_else` operation descriptions and complete layered core
source-substitution infrastructure. The receiver occurs once; arm bodies stay
lazy. The nested composition changes closure construction order; this family
explicitly leaves its original construction/loan/standard-owner proof false.
It does not admit arbitrary catalog methods or original `Option` ownership.
Named format captures, captured two-arm bodies, complex receivers and unknown
body producers retain residuals in this initial Option grammar.

Each phase emits complete source/CST equations for **every** supplied module,
including unchanged modules, serialized/reparsed by the actual CST APIs with
full physical inverses. The retained result factors complete source versions
and history indices. An immutable synchronous visitor receives every full
equation. The top-level rule sequence is language then repository; the actual
layered Option producer retains its own corresponding source rule sequence.
No source equation, metadata, public Boolean/name/hash or candidate descriptor
grants compiler admission.

The result separately retains actual scalar170 **whole-original** and
**whole-candidate** project checks, with complete admission/refusal meta and
both target sources when produced, or explicit hard diagnostics when checking
fails. These checks invoke the genuine original scalar source fence/compiler,
not a selected successful function. An uninstalled profile remains a hard
source refusal; the producer never bypasses that fence. Existing private
source-failure poisoning also remains in force. Neither source preservation
nor a hard-refused original is relabelled executable.

The source cases include the complete actual `token_report.rs` owner. Its
three lexically bound local closures can form candidates while retaining the
entire header, output loop, expanded if-let blocks, original test-module edge
and remaining standard methods. Actual row admission is **not claimed**:
captured `map_or_else` bodies, if-let/scalar adoption, filtering/defaults,
primitive text conversion, constant-index formatting and output migration
remain separate original or qualified checks. No owner is extracted to turn
its residuals into successful production coverage.

Independent case source covers unused/repeated operands, argument order,
earlier closure dependencies, shared-root provenance DATA, mutation/escape/
shadow/unknown/move refusals, two lazy arm source shapes, immutable full CST
events and both whole-project checking outcomes. Future receiving obligations
still include actual execution/order/panic evidence, strict lockfile
TypeScript5.9.3 and independent native baselines after all eight same-SHA JS
gates. No new native oracle is scheduled here.

The coordinator's independent `token-report-translation-edges-20261101-cases.mjs`
helper and `token_report_translation_edges_20261101_test.rs` native cases are
future receiving obligations. They may qualify a later actual compiled whole
owner against the canonical JSON runtime; they are not invoked with a
handwritten row, a selected successful excerpt or an unsupported-case skip.
This source candidate checkpoint does not claim that receiving lane is ready.

This family implements complete **physical source inverses** only. It has no
new semantic edited-target inverse: an edit to one duplicated closure body
needs a unique consistent original-definition mapping, complete re-expansion,
fresh native rechecking and exact paired JavaScript/TypeScript reproduction.
That provenance remains open, as do the original private typed closure issuer,
general capture/loan/Drop semantics, standard ownership and actual row coverage.
