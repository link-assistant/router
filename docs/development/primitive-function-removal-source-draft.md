# Receiving function removal source draft

SOURCE ONLY. API, source equations, strict paired behavior, lifecycle and refusal
case sources are UNRUN. Entire drafting and qualification remain OPEN.

The complete existing extension implementation is copied by ordered language
then repository source rules and extended with a fresh deletion operation.
The original implementation and source inverses remain exact; no generated
application body is hand edited and no receiving source executes during drafting.

The request supplies one actual complete JavaScript or TypeScript unit. Actual
native AST/CST partitioning requires a strict subset of the recorded original
names. All original receiving functions first enter the actual private checker.
JavaScript authority retains actual type headers for the surviving functions;
TypeScript supplies its complete current headers. Retained bodies update before
the removed Rust functions disappear, permitting a retained caller to stop using
a removed local dependency. Complete checked meta and canonical paired source
are independently reconstructed.

Every removal rechecks the fresh whole Rust/Cargo universe, genuine native
carrier, source SHA, actual active module and complete original function span.
Removed bodies must remain unchanged while retained bodies update. Original
outer documentation that lies outside a checked function span refuses pending
a separate ownership rule. Whole source reconstruction permits only the exact
selected retained-function replacements and removed-function substitutions.
A fresh final project must lose exactly the removed function identities and
retain every other executable, refusal and method identity. A native caller
outside this updated unit that still refers to a removed function refuses.

Removing all functions currently requires the exact empty receiving source and
a genuinely empty native module after deletion. Imports, constants, macros,
unsupported items and noncanonical empty requests cannot disappear through that
case. The durable native route permits a later independently checked insertion.
Mixed additions/removals, coordinated cross-unit caller deletion, broader trivia
ownership and zero-function modules with retained native items require further
drafts. This API is not yet connected to bulk composition or physical planning.

No proposal installs files or grants semantic, namespace, execution or freshness
authority. Every source context closes with fresh source fences on success and
failure. Bounds and private operation-local sharing remain unchanged. Independent
cases cover both authorities, retained behavior/strict TypeScript, full clear and
restore, retained local callers, external dangling callers, invalid/mixed source,
route and binding mismatches, outer documentation and preserved native items.
All are UNRUN. Coverage, parity, receiving export, freshness, resources, platforms
and CI remain OPEN; Rust stays CI-only after eight same-SHA JavaScript gates.
