# Canonical JSON reader domain source draft

All new implementation and regression sources are UNRUN. Source construction
and review executed no translator, adopter, preparer, tests, experiments,
generation, Rust tools or CI-triggering push.

The existing canonical Option reader equation now covers all nine already
registered read-only JSON readers: text, boolean, unsigned/signed integer,
null, binary64, number, array and object. Mutable readers remain outside this
domain. This adds no new library implementation boundary; each call still needs
the complete current native sources and independent existing host contracts.
Source-splice operands reject coercion callbacks and retain finite bounds.

The complete selector accepts distinct unbounded lifetime declarations, shared
written lifetime parameters/results, standard Option and owned Maybe spellings,
ordinary str key parameters and actual usize index parameters. Named canonical
JSON imports still require the original fresh same-module binding and active
complete import source. Type/const generic parameters, lifetime bounds, mutable
loans, custom owners, unknown producers and shadowed keys remain refused.

A bounded chain composes multiple canonical reader calls in a single proposal,
including object/array reader question marks followed by get and a text reader.
Every nested expansion retains its generic Option language equation. Generated
path spans are relocated by construction into the enclosing equation; repository
rules bind only those spans to the paired facade. Every source operator and
receiver stays in its original evaluation order. Both stages retain the complete
serialized/reparsed CST, source and inverse before whole-function checking.
The materialized and detached packet paths use the same complete selector.

Three whole compiler equations retain full originals, native owner spans and
separate substitution phases. Independent unrun source, JS/strict TS and native
CI-only cases cover lifetimes, genuine imports, missing/wrong/null/empty values,
Unicode, collection roots, indices, nested equations, unchanged sources,
resource bounds, and refusal of incompatible emitted return types.

These proposals grant no trait dispatch, native owner/loan equivalence,
application admission or executable coverage. Current source banks, exports,
canonical/profile generation, complete forward/reverse synchronization, strict
parity, all eight JavaScript stages, CI-only Rust and receiving qualification
remain open, along with the complete remaining bulk requirement ledger.
