# Explicit ASCII asset schedule

`hostCoreAsciiRuntimeAssets` is a new, separately named asset producer for the
unpublished owned ASCII interface. It selects the complete string iterator
runtime, whitespace module and paired declaration. It does not run HostChecker
or read unrelated assets. This is an explicit new read schedule; it does not
claim filesystem or HostChecker callback parity with either full asset builder.
Both original full asset builders and `ownedCoreRuntimeSources` stay unchanged.

`prepare-core-ascii-assets.mjs` derives all three `files.set` statements from the
complete pinned `hostRuntimeAssetsNamedDataAliases` body using TypeScript 5.9.3.
It checks the original `files` allocation, native lexical bindings of every
selected `files`/`readFileSync` occurrence, detached native subtree shapes, and
complete source grammar. The original declaration is copied from its native
string literal; runtime and declaration implementations are not handwritten.

Every new asset call reads and hashes the complete original producer and its
complete generated helper. It freshly reads both selected runtime modules and
compares/hashes all three complete selected sources against the source proposal's
fixed original data. Primitive source pins are not remembered validation results.
Selected input changes refuse; public metadata cannot replace the independently
checked source context, Rust owner closure or checked operation. Existing native
host guards retain their existing refusal domain. They do not prove stock FS
readers or unchanged HostChecker methods, and this contract makes no such claim.

The three-file source layer follows the original reverse ASCII layer. It retains
every historical before/after equation and complete native/CST inverse. Current
physical comparisons use the final composed output. Its CLI is
`node tools/translation/prepare-core-ascii-assets.mjs --write|--check`.
`prepareCurrentCoreAsciiReverseAssets` separately returns the unchanged reverse
birth plus this later layer. Current wrapper composers append
`composeCoreAsciiAssets` after `composeCoreAsciiReverse`.

The four complete tests in `router-core-ascii-assets.test.mjs` retain 60-second
deadlines. They compare all three full outputs with the original full builder,
record the exact new read schedule, independently parse complete JS/declaration
sources, retain every native/CST/inverse equation, reject changed selected and
producer sources/native hooks, and observe complete fresh hash inputs on two
independent calls. The existing reverse ASCII semantic case and its 60-second
deadline are unchanged. A separate receiving run must establish performance;
this source proposal claims no measured gain and executes no Rust.
