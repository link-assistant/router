# Conditional filesystem source draft

The additive `filesystem-control` profile copies the complete existing effect
frontend and canonical Rust reader. The original profiles remain available.
Actual string and Boolean parameter domains, exclusive complete branches,
immediate Result error returns and deferred async effect sequences pass through
serialized/reparsed CST and separately checked Rust semantic meta. Rust input
uses a source proposal followed by fresh checking and complete Rust reproduction.

Bindings retain payload-use counts independently on exclusive paths. Unused
successful effect values are discarded in native output. Qualified operations,
await/polling behavior, original runtime bytes and complete target inverses are
required. Source units capture physical runtimes, preserve baseline conflicts
and use the existing fresh proposal/apply transaction in all three directions.
Seven complete originals and their ordered language/repository substitutions
compose the preceding preparation histories. No source spelling or cached
receipt grants semantic authority.

Independent source covers selected effects, first polling, early errors, strict
TypeScript, all three authority directions, stale/forged proposals, full source
inverses and refusals. A native Rust oracle covers synchronous and asynchronous
behavior. All sources are **unverified**; no implementation, translator, compiler,
test, experiment or Rust tool was run for this draft.

General loops, arbitrary error conversion, HTTP, streaming, cancellation,
concurrency, persistent application state, production application and the other
bulk-ledger obligations remain open. This profile is not whole-Router parity.
