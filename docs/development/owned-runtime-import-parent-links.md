# Runtime import parent-link source proposal

This is an unmaterialized source proposal. No runtime, performance, artifact
freshness or additional executable function coverage is established here. The
original three complete builds and Bun's original five-second test deadline are
unchanged. The recorded inclusive `forEachChild` profile includes other work;
it does not predict this proposal's saving.

`prepare-owned-runtime-import-edges.mjs` proposes four complete outputs through
the existing ordered language and repository CST sequences. It retains their
complete original sources, native-selected edits, detached AST copies, lexical
binding checks, both phase documents/traces and complete inverses. The installed
TypeScript 5.9.3 source is independently pinned and retained, including the full
native parent-link traversal and child table. Native source occurrences are
review DATA; they do not independently establish function ownership.

The change still calls the original `createSourceFile` parser on every actual
runtime source use. The first use of each exact path/source in an operation uses
the original `setParentNodes=true`. Later qualified uses call a native-selected
copy of the same private parser with that one argument set to `false`. These
three consumers inspect only top-level import/export specifiers. Their original
complete recursion, path validation, resolution, source reads, current-source
checks, Hash calls, diagnostics and result sorting remain in place. Semantic
owned-source parsing keeps the original parser. No scanner or regular expression
execution is skipped or replayed.

The omitted native tail assigns parent links and traverses parser-created nodes.
Eligibility additionally requires actual loader-issued compiler function and
prototype identities, unchanged allocator constructors, native object/prototype
descriptors, no parent setters, disabled TypeScript performance/tracing/debug
hooks, and the original shared intrinsic guards. A changed descriptor or hook
retires the operation's dictionary and all active ancestors. Fallback executes
the original parser and returns its original result or exception once.

The loader identity extension preserves the existing first require's position.
The complete native `loadTypeScript` createRequire/join/require operation moves
through a native source selection into the same loader issuer; its public
function delegates to that operation. The original `ownershipCompiler` require
uses the same private capture. Neither path accepts a caller compiler or callback
as a birth permit. Native before/after cache-key censuses select one newly loaded
module whose exports equal the actual returned compiler. No extra runtime file
read, realpath or require.resolve is introduced. Linked node_modules paths need
no guessed cache key. Preloaded, ambiguous, over-8192-entry or uncertain loaders
issue no identity tape. Captured loader and filesystem descriptors are checked
again; unknown support never becomes eligible by matching function text alone.

The long-lived tape contains native function/prototype identities only, like an
intrinsic bootstrap. It holds no source, AST, checker, semantic owner, digest or
verdict. Separately, each synchronous build frame owns its primitive path/source
and import-edge DATA. Nested frames have separate dictionaries and share
nonrefundable limits of 256 rows, 2,097,152 source/path UTF-16 units and 16,384
edges. Every return or throw clears its dictionary; the outermost exit also
drops mutable compiler guard rows. No dictionary or build result is reused by a
later invocation. Qualified explicit scope calls refuse Promise/thenable/proxy
results without evaluating then getters. If original hooks make qualification
uncertain, fallback closes before returning the original result and introduces
no special result refusal.
