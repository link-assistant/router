# Explicit owned literal matches

This draft adds `crate::translation_core::matches!` as an explicit compatibility
API. Its native Rust wrapper delegates to absolute `::std::matches!`. The
library implementation remains untranslated. It does not infer the owner of an
old bare `matches!`, close a conditional namespace, or change standard macro
admission.

The forward parser requires the existing genuine complete owned-facade proof.
Its source producer copies the complete current ordered-match parser body and
source-pattern helpers through native TypeScript 5.9.3 and the serialized,
reparsed CST boundary. The existing ordered checker and emitter check every
subject, alternative, type, exhaustiveness and lifetime. The initial owned
domain permits scalar literal alternatives, without guards or bindings. It
evaluates the subject once. Unsupported domains retain their refusals.

`prepare-core-matches-sources.mjs` produces the additive facade, full source
DATA, inline Host parser hook, runtime module and independent Rust oracle.
Every output retains its complete original source, both CST documents and exact
inverse. The Host insertion occurs before the original class-birth method
snapshot. Existing bodies and the original snapshot remain in place; the new
receiving case compares the actual method with that immutable birth identity.
It does not certify the broader original compiler bootstrap obligations.

The original vector producer API and frozen input fixture remain intact.
Its CLI and complete first receiving case apply the new explicit source layer
after regenerating the full historical vector outputs. Every overlapping output
must equal the new layer's complete input before any current output comparison.
No historical source equation is silently dropped. The format/vector corpus
producers keep their APIs and continue to consume the current full facade through
their existing source imports; their own fresh producer equations remain required.

`prepare-source-backed-matches.mjs` derives a separate complete corpus adapter
from the actual vector corpus, formatting binding checks and shared function
barrier. It retains all original source maps, module/ancestor contexts, Cargo
inputs, diagnostics, fresh private attribute inspection and complete source/CST
inverses. Closed attributes and inactive items are blanked only in private
inspection DATA. Emitted source retains every original byte except the explicit
qualified macro name. Unknown attributes, local definitions/imports, foreign
qualified macros, separated or Unicode producers and unknown module conditions
remain barriers. Each candidate must be a plain boolean function with primitive
scalar or borrowed owned-core text parameters, and use only the positive literal
pattern grammar at every selected call. Nominal/iterator/effectful signatures
stay outside this initial candidate batch. Candidate counts are distinct functions;
they do not establish executable coverage or source equivalence to the old macro.

The production targets are the complete original
`client_launch.codex_root_option_takes_value` and
`client_launch.codex_root_boolean_option`. The receiving case retains their
whole original module, real root, operation-output parent macro source and Cargo
inputs, then checks both complete functions before and after explicit adoption.
Its graph leaves unrelated missing root children as diagnostics and is explicitly
not a whole-crate coverage measurement. Independent JS/strict TypeScript witnesses
cover all 17 value options, all nine flags and cross-domain/Unicode negatives.
The Rust oracle includes both complete source-selected functions and the same
application witnesses, plus primitive and once-only subject cases. Rust runs only
in CI after the complete same-head JavaScript gate.

The stored frontier contains 79 historical first refusals mentioning standard
matches ownership. All 79 source/body joins were checked against the retained
source inventory. They are source-bound historical hints, not 79 fresh failures
or gains. Fresh whole-project before/after admission and target execution are
still required to measure production gains. Generated source and test drafts
alone establish no new executable functions.

## Deferred standard namespace route

The neutral production profile leaves `unix` unknown. The root conditional
`unix_listener` child retains global bang uncertainty, so existing standard
matches refuses ancestor ownership even for simple literal predicates. Proving
both absent and original-present branches requires the child's complete derives,
format calls and tracing expansions, without selecting an OS or dropping code.

The complete pinned tracing/tracing-core archives already retain every feature
variant. A prospective reusable proof would follow actual all-arm token origins
and `$crate` helper bindings to a fixed point, retaining caller tokens and all
unresolved producers. That route reaches `format_args`, `file`, `line`, `concat`,
`stringify` and `module_path`. `format_args` needs the actual `ExprKind::FormatArgs`
constructor and every explicit/captured argument origin, including error/retry
branches. Merely returning an expression is insufficient: an expression block
may contain `#[macro_export]`. Local `#[macro_use] extern crate` also cannot be
discarded after a diagnostic, because the compiler still updates its macro-use
prelude. No completed tracing/builtin expansion footprint is claimed here.

Source CST inverses establish fidelity, not reverse executable coverage. This
draft does not add reverse owned-matches emission. Whole-source synchronization,
native parity and the broader JavaScript/Rust gates remain separate obligations.
