# Fresh operation-scoped wrapping source draft

This implementation and every new regression are source drafted, unrun. It
establishes no current source-history qualification, performance result, complete
translation coverage, synchronization parity or green JavaScript gate.

The fixed wrapping reader previously retained complete Rust inputs, tokens,
items and selected proofs in module maps. It now opens a bounded synchronous
operation, freshly checks the pinned complete manifest and loads the original
source/license archives only if wrapping is selected. Every compressed length
and SHA256, decoded length and SHA256, original Git blob identity and exact UTF-8
inverse remain mandatory. Before the original Rust item/token readers consume a
Rust input, its whole CST is serialized, reparsed and exactly reconstructed.
The original primitive impl, macro invocation, Self/ActualT/BITS assignment,
member body, namespace import, const stability and generic intrinsic checks are
retained. Native input remains bounded to 8 MiB combined and 512 KiB per member.

One root operation shares only its current raw source dataset. Nested frames
have their own selected-proof identities, retain the original nesting bound of
64 and charge a shared 200000-selection bound. Every exit freshly checks the
complete manifest and every selected archive, including licenses. A failed
source check invalidates the root and all nested frames. Catching a nested
failure and restoring bytes does not revive the parent's selections. All maps
and source references are cleared on the root exit, including errors. Callbacks
receive no frame and must be ordinary synchronous nongenerator functions;
Promises, proxies and own thenable/accessor results refuse without assimilation.

A genuine private proof can retain its identity for the original issuer API,
but using it reissues an equal current complete source proof. A copied proof
still cannot pass that private identity gate. Reparsed semantic metadata instead
uses a separate bounded descriptor-only copy and exact full evidence comparison
against a fresh source selection. That DATA comparison grants no caller,
namespace, ownership, effect, type or executable admission. The existing Host
checker/emitter guards still run, and fixed wrapping presentation now rechecks
its decoded source evidence before selecting native or legacy output.

Complete Host checking/emission and fixed contract construction group source
work into these operations. Pointer-only and empty operations avoid loading
native archives. The immutable public profile is configuration DATA, and the
module retains no source body/hash/verdict/result cache across operations.

Six complete source equations retain the original implementations and both
language/repository phases. The generic source-owner index also supports the
actual complete native SourceFile node for a bounded pinned module edit; this
is construction DATA, with the same exact spans, whole CST and complete inverse
requirements. No semantic or owner issuer is changed by that recipe selector.

The independent receiving cases make temporary complete module/profile copies
through native import/module-URL spans. They mutate those receiving archives and
manifest, preserving repository profiles even when test files run concurrently.
The written cases cover freshness after prior success, private/copy/metadata
boundaries, every width and signedness, source/license/manifest changes, final
checks, caught nested failure, cleanup, depth, callback errors and non-execution
of accessors. Every receiving case, original wrapping/forward/strict TypeScript
case, source equation and performance obligation remains unrun.

A separate two-equation source successor preserves the primary thrown value
when a final source fence also fails. Every fence still runs and invalidates its
root, and every reference is cleared. If the callback succeeded, a failed final
fence still prevents its result from escaping. Null/undefined throws retain
their identity through a distinct failure flag. Additional receiving source
cases cover source-read reasons, simultaneous callback/fence failures and caught
nested errors with restored bytes; all remain unrun.
