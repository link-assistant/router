# Failure-aware native source preparation draft

Nine complete source equations copy the original JS/TS source preparer, the
separate mixed Rust-CST preparer and their input fences into additive modules.
The original public modules, refusal domains, histories and APIs are unchanged.
The primitive sequence/vector core and root drivers and the newest JSON
discovery driver select the copies. No compiler, preparer, tests, diagnostics,
generation or CI feedback has been executed for this batch. All evidence is
UNRUN and complete delivery remains OPEN.

The shared synchronous source-failure relay now surrounds these copied source
operations. Trusted source preparation, source-writing validation and physical
input reads are explicitly classified as source checks. Source-validation
failures revoke every active source operation even if a caller catches an error
and restores the original bytes. The relay can only revoke; it cannot issue a
binding, namespace, type, body equivalence or execution permit. The copies share
this relay with the earlier primitive sequence/vector/literal source operations.

Application callbacks remain outside source-validation classification. Their
ordinary exceptions retain their exact identity, including null, undefined and
symbols. Complete original closing loops still examine every retained physical
input and preserve an application primary. A closing source failure still marks
active relay scopes when its exception is hidden behind that primary. Failed
scopes cannot become healthy after restoration; subsequent independent source
operations may succeed after inputs are corrected.

Both preparers preserve the actual native parser and original binding checks,
language/repository substitutions, complete serialized/reparsed CST equations,
all descendant/original/final source fences, original byte and line bounds and
original syntax-only sharing. Mixed Rust keeps its distinct CST-only path and
false native grammar/typechecking/compilation flags. JavaScript's original
preparer continues to reject Rust. No local Rust execution is authorized.

All relay frames, input maps and syntax trees live only inside active operations
and clear in finally blocks. No source, hash, owner, result, input or failure
cache survives an operation. The existing aggregate relay limit is 256 active
frames; existing per-family limits remain unchanged. Additional wrapper frames
consume that shared allowance. This new API does not promise the legacy API's
entire deepest nested-callback domain; callers needing the original behavior
retain the unchanged original exports.

Independent unrun cases compare complete original/new valid JS and Rust plans,
assert the old JS-only rejection and legacy caught-conflict behavior, and cover
changed/restored source and archives, bad pins, cross-family failures, closing
I/O, exact arbitrary primary identity, hidden source failures, ordinary callback
exceptions, result/descriptor hazards and fresh later operations. The pinned
source profile retains complete originals, nine ordered two-phase equations
and every inverse; predecessor preparation composes this additive successor.
An isolated child-process case instruments the two selected physical reads,
requires both to run after the first throws, and independently checks exact
application primary identity. Its filesystem binding changes remain confined
to that future child process. The case has not been executed.

This closes a drafted nested-failure protocol for the explicitly selected
preparers. It does not retrofit every historical preparer, prove production
caller translation, replace namespace closure or qualify receiving parity.
Whole-source drafting, actual generation/installation, freshness, current
coverage, strict parity and all same-SHA JavaScript gates followed by fatal Rust
CI remain required.
