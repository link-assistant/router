# Physical HTTP resource source-unit draft

The closed `http-resource` unit profile now composes the complete HTTP caller,
canonical Rust inverse and existing Git-aware synchronization transactions.
All implementation, receiving and native source remains unrun.

Complete original unit/signature source copies retain native-selected ordered
language and repository substitutions, originals and full inverses. The old
profiles retain their behavior. Both descriptor readers accept the new fixed
profile while keeping all original bounds and transaction checks. The required
native mapping adds the complete HTTP protocol, transport, deadline, guard, text
and Result sources to the original core/Cargo inputs, below the existing
32-mapping limit.

Source-unit runtime initialization mirrors every actual JS module and opaque
declaration between the physical JS/TS runtime trees. It uses the additive
deadline runtime closure and retains the original dependency/source-count
limits. Initialization alone never translates an unsupported application.

Every translation captures all current native, runtime and available paired
source bytes. Fresh complete caller checking independently validates the chosen
authority. Missing JS annotations may be proposed only from the current whole
checked TS pair, with actual function/arity/parameter identity and import-owned
type domains. The new JS proposal is freshly rechecked; the user's original JS
bytes and the complete annotation/import equation are retained. Public u64
inputs still need their own original dominating guards.

Rust authority requires complete original source membership, canonical source
proposals and exact whole-token reproduction through the same independent JS
checker. JS and TS authority retain their original source. The original
synchronizer performs import relocation, Git direction/conflict handling,
complete input/output capture, fresh recomputation, atomic installation and
rollback. No caller-supplied context or serialized metadata grants authority.

Independent source cases exercise all three edit directions, mirrored opaque
resource identity, nested timeout results, missing JS annotations, unsupported
application runtime initialization, native-source tampering, concurrent edits,
forged proposals and complete source histories. No source-unit planner,
installer, translator, preparer or test was run. Production adoption, wider
HTTP/resource semantics, native qualification and all unfinished requirements
remain open.
