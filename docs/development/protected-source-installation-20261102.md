## Actual installation behavior

`unit-runtime-materialization.mjs` now captures
`translation/source-ownership.json` before invoking the fresh producer, including
before awaiting an asynchronous producer. The original complete fresh-proposal
comparison, source/native checks, current HEAD requirement in the asynchronous
path, byte/mode comparisons, quarantine/backup/no-overwrite writes, rollback,
recovery and cleanup remain. The private policy receipt supplies no native,
namespace, type, executable or producer authority and has no public force flag.
Existing public function signatures and return shapes remain unchanged. The
additive `captureExplicitSourceMutationPolicy` export shares this exact
operational veto/closing scope with specialized writers; it is no compiler,
source-owner or namespace admission API. Those writers must invoke their own
fixed actual fresh producer and protect every mutation under that scope.

The explicit authored/unmanaged policy schema stays
`router-explicit-source-ownership-v1`, with exact `authored` and `unmanaged` path
arrays. Closed schema, valid ordinary relative paths and duplicate refusals apply.
All paths are receiving/output-root relative, independently of compiler/source
root. The operation checks actual root and existing policy-parent device/inode/
mode plus complete policy bytes, exact file identity, mode, size and nanosecond
mtime/ctime. Renaming an alternate hard-linked policy through a different parent
cannot preserve the original ancestor association. Present source changed then
restored bytes remain invalid when the metadata changes. No source verdict cache
survives the invocation. A detected policy failure permanently revokes this scope.

Protected destinations may appear only as exact byte/mode no-ops. Creation,
replacement, deletion or mode changes refuse before any public output mutation.
The policy itself cannot be generated, replaced or deleted by that transaction,
even when previously absent. Unknown generated comments or report flags do not
override it. If an absent policy's parent is created for ordinary metadata output,
the policy file must remain absent; this absence grants no checked compiler fact.

Policy closes before publication, at the original input guard around mutations,
separately alongside all original source closers, and after original cleanup.
Every closer is attempted even when another fails. Exact primary thrown values,
including `undefined`, `null`, `false`,0, empty string and frozen errors, survive
secondary policy-closing failure. Best-effort attached diagnostics or a bounded
stderr record retain that secondary fact without replacing the primary.

A policy change during staging refuses publication. Original backup/stage bytes
remain when the existing transaction cannot finish closing. This does not claim
global atomic visibility, durable crash recovery, hostile-writer resistance or
conditional inode compare-and-swap. The existing cooperating/exclusive-writer
boundary and inherited ordinary-file read/platform limitations still apply.
A failure discovered only after backup disposal may report incomplete final
qualification; it cannot recreate original inodes after cleanup.

## Limits and compatibility

The common transaction's8MiB per-source/64MiB aggregate source/192MiB proposal and
4096 input/output limits remain. Each policy list has at most4096 paths; present
policy source and retained parsed/path occurrences are conservatively charged
against the existing64MiB installation bound. Absent policy adds no source-byte
charge, preserving the old boundary. Resource/RSS/disk performance is unmeasured.
This common profile does not raise or replace the separate forward installer's
16MiB/200k-path ownership policy domain. Larger policies refuse the common path;
full production domain qualification remains OPEN.

The earlier producer bookkeeping API still handles exact ownership enrollment,
stale generated outputs, existing modes, authored policy and unchanged source
inputs. The forward transaction retains its separate fresh private producer and
policy closure. This change adds the common source/unit/runtime install paths to
that explicit policy behavior. It does not silently rewrite generated output
banks or qualify historical source profiles as current.

Specialized native leaf move/durable recovery writers are separate APIs. Their
original source, inode-preserving move and lifecycle checks remain, but full
explicit-policy integration there is a remaining source gap; the common patch
must not be claimed to cover them by name alone. Other manual source edits are
authored changes outside generated installation, not a policy-generation bypass.
