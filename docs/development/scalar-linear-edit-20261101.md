# Actual edited scalar specialized-target inverse — source draft

`tools/translation/scalar-linear-edit-20261101.mjs` adds
`translateEditedScalarLinearKernel(data, options, source, {sourcePath, language})`.
It accepts real canonical scalar callback-body edits in the existing linear
specialization, including BigInt/Boolean literals, arithmetic operation changes,
comparisons, predicates and conditional branches. It reconstructs and privately
checks changed ordinary application source, emits changed canonical Rust and
regenerates the specialized JS and TS. The earlier exact-original projection
API remains unchanged and still refuses edited specialized targets.

The current domain is one complete stage-only module with its existing complete
imports, function signatures, stage order/count, input/output domains and callback
parameters. Bytes outside scalar callback bodies must retain the fresh canonical
skeleton. Callback edits must themselves reproduce canonical generated bytes;
arbitrary whitespace, comments, alpha renaming, added imports/functions or
broader application edits are not accepted by this narrow lane. Existing
operators may change within their fixed native width/sign domain. The ordinary
application edit path remains available for broader changes.

The language pipeline first reruns the actual complete original chain/compiler
and both-direction specialization baseline. `scalar-linear-edit-20261101-syntax.mjs`
then parses the whole actual edited source with the original native TypeScript
compiler. An invocation-local in-memory program resolves its actual import
symbols against the complete fresh kernel/operator declaration/source closure;
it checks each alias's actual export declarations and each callback reference's
actual native parameter symbol. The immutable original kernel sources remain
under their full physical-read closing fences, and original primitive source
guards remain active. Declaration spellings or metadata flags alone provide no
source, namespace, scalar or ownership authority.

Only bounded pure scalar expressions can be decoded. Checked arithmetic,
complement, bitwise and shift imports map back to their ordinary scalar source
operations with fixed current metadata. Unknown calls/imports, captures, effects,
writes, references, suspension, dynamic Number coercion and unsupported types
are refused. The decoder independently locates each callback in the complete
actual original application source, preserving its original binding rather than
using an edited public stage field as permission. Complete CST substitutions
replace only those ordinary callback bodies and serialize/reparse the resulting
full bridge source.

That complete bridge passes the actual unchanged private source, type, ownership,
loop, callback and semantic-meta issuer, canonical Rust inverse and linear
specialization again. The final complete regenerated artifact must equal every
byte of the authoritative edited input. A copied callback, supplied domain flag,
source skeleton match or native symbol by itself cannot satisfy this equation.
No edited code is executed to obtain admission. Kernel and operator metadata
are candidates until the ordinary bridge's genuine original checks succeed.

The repository phase retains original-specialized→edited-specialized and
original-application→changed-bridge equations, full lossless edited-target CST,
all original bytes/inverses, genuine semantic meta and actual Rust/JS/TS outputs.
`readEditedScalarLinearKernelMeta` replays this entire process against current
original sources and compares the complete canonical edited meta, refusing stale
or forged bridge/meta receipts. Both input source languages and both target edit
languages retain their actual path/import layouts. Nothing installs or overwrites
authored files, and no new native ABI or cross-invocation cache is introduced.

Resource limits remain unchanged: 2 MiB edited source, complete source/AST
budgets, 16 MiB UTF16/UTF8 occurrence accounting, fixed eight-stage/4,096-value
limits and original source fences. All phases close their original asset/native
checks on failure while preserving the primary error. The in-memory native
program never writes files, loads unlisted modules or substitutes compiler
semantic diagnostics for the actual private ordinary bridge checks.

Independent new case source edits actual generated JS and TS literals,
addition→multiplication, predicate operators and conditional branches; expects
changed Rust and exact authoritative target regeneration; and runs the actual
edited JS and separately TypeScript5.9.3 strict-compiled TS at 4,096 values through
the existing receiving harness. Cases also cover overflow, malformed imports,
wrong native widths/domains, captures/effects, stale/forged meta, source tampering
and accessors. `rust/tests/scalar_linear_edit_20261101.rs` supplies independent
native expected values behind the existing full same-SHA JavaScript gate.

All cases keep their original 60-second complete and 20-second child bounds.
Repeated full baseline/bridge/meta/native checks remain inside those deadlines;
their cost is unmeasured and cannot be hidden with cached source verdicts,
smaller workloads or raised limits. Every new parser/compiler/translator,
preparer/interpreter, receiving/runtime and Rust execution is **UNRUN**. No CI or
review feedback was inspected. General edited-target syntax, changing stage
skeletons/signatures/domains, production/default dispatcher/export adoption,
whole-project conflict/install synchronization, broader ownership and full parity
remain open. No checklist closure, production gain or verified reverse parity is
claimed.
