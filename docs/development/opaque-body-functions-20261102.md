# Whole checked function associations: source draft

The fixed `inspectOpaqueFunctions` and capture/context siblings retain the numeric
whole original/native/adopted lane and add source/target associations independently
of literal/operator presence. This removes a future edit-planning prerequisite:
a checked function with no literal may still be mapped to its actual emitted
binding. It does not add semantic admission or make a refused body executable.
Every original numeric API, source image and case remains unchanged.

Inside the actual live constant188/Host frames, the collector selects only actual
fn entries in that project's admission census and reads each real source/target
reader. Exact source path, qualified name, entry kind/full name and target joins
must agree. Every selected checked association remains in the returned DATA list;
unknown/unresolved type hints remain explicitly null. Generated labels are kept,
and `originalPhysicalOwnerProved:false` remains explicit: later inverse rules
still need the actual original source/CST/namespace/ownership checks.

The signature hint is a bounded scalar/array/nominal/borrow/ownership spelling
summary, not a type identity, compatibility theorem or private receipt. Advanced
qualifiers may be erased or unknown; never use hint equality to authorize a call.
A caller-built object with matching public schema/spellings cannot supply the
fixed real compiler's private program or source context. No lower facade escapes.
Future callee/binding edits must independently recheck complete native programs
and both complete authored projections. This draft does not implement that wider
callee inverse or broaden the existing binding inverse automatically.
