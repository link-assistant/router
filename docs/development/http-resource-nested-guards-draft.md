# Source-typed nested numeric ingress

Numeric Option, control Result, textual Result and I/O Result chains can now use
one complete original payload guard under the existing eight-constructor native
bound. The original parameter's actual written type is checked independently
against current qualified operation/type sources. Its constructor chain decides
every required Some/Ok test and the exact `field0` payload path. Every successful
tag must dominate that path's BigInt/lower/upper checks. No diagnostic string,
returned record or unqualified type name can supply those facts.

A bare BigInt slot can choose its native width from the exact original range,
just as a scalar input does. An existing qualified u64/i64 operation domain cannot
change width through that hint. Guard records still need the independently
rechecked complete actual parameter type. Existing legacy simple guards retain
their spelling and behavior. General guards report a numeric payload error and
skip inactive constructors without reading deeper payloads. None/Err ownership,
error families, all-exit cleanup and whole body/meta checking remain unchanged.

Canonical native inversion reuses the actual generic deadline result witness
where needed and emits every original constructor/range condition. It still
must freshly reproduce every original Rust token. Generic callback execution
remains separately refused; a type witness grants no polling/effect permission.

Five complete prior implementations, ordered language/repository substitutions
and full CST/source inverses are retained. Independent JS, strict TS, native
inverse, constructor/path/range, fixed-domain, forged-meta and refusal cases plus
an oracle using the real native ControlError are drafted and unrun. No compiler,
test, experiment, preparer, translator, generation, Rust tool or CI ran.
Numeric collections, wider async/effect domains, namespace/bootstrap, production
parity and every unfinished bulk requirement remain open.
