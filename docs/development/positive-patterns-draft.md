# Positive range and sequence pattern source draft

Every new implementation and independent case is UNRUN. The private positive
parser now retains numeric/negative/character/constant-path range bounds, leading
or alternatives, slice patterns, one direct rest per tuple/slice sequence and
ordinary `@` bindings. Struct patterns retain qualified shorthand reference/mut
bindings and explicit numeric fields. All forms keep original spans and recursive
children under the existing source/token/node/depth budgets and private issuers.

Literal ranges require numeric, validated character or unresolved constant-path
bounds. Invalid/missing bounds, duplicate direct rests, standalone rests, invalid
binding names and missing numeric-field patterns refuse. Existing tuple shape
and older pattern forms retain their representation. Pattern type validity,
constant owners, binding/reference modes, exhaustiveness, iteration and original
native AST/visitor dispatch remain independently unresolved. Source nodes grant
no execution, type, borrowing, namespace or macro authority.

Two whole compiler equations retain original class/function/module ownership,
separate language/repository stages, complete CST/meta and whole inverses.
Independent unrun source cases cover boundary syntax, nested sequence structure,
conditional/for entry points, opaque macro roles and refusals. CI-only native
oracle source covers HTTP status boundaries, signed/character ranges, rest
bindings, shared slices and shorthand reference modes.

No parser, compiler, model, preparer, translator, test, experiment, generation,
Rust tool or CI-triggering push ran. Whole production function qualification,
native closure, corresponding target semantics, reverse/sync, source banks/
exports, freshness, parity and every complete delivery gate remain unfinished.
