# Emit-only original-module DATA routing proposal

`prepare-private-parser-assignment-data-adoption.mjs --emit` proposes a change to
the original physical executor without writing it. There is no `--write` or
`--check` installation mode. The original executor/defaults remain unchanged.
The proposal is not receiving or performance qualification.

First it freshly prepares and verifies the complete explicit candidate source
equation. The candidate must already be physically materialized and match that
equation. Installed TypeScript 5.9.3 selects its actual `assignmentData` function,
which is appended unchanged to the original executor. The native checker selects
only references to the original private `data` declaration in `execute` and
`lexPrivateConcreteSources`. Only those three current call identifiers change to
`assignmentData`. The new native program independently proves all three bind to
the appended helper; a local shadow is refused. The old `data` function remains
byte-for-byte identical, including its recursive calls.

Every other original byte remains. All original exports, function signatures,
source packet authentication, crypto arguments, independent SHA, source reads,
before/after source equality, final file identities, private transaction joins,
native intrinsic guards, error paths and budgets retain their existing code.
The eventual original module would keep its one existing private compilation
state; it adds no compiler/source/verdict/encoded cache or second executor.
Every inherited key and the special `__proto__`/`get` keys keep the original
`defineProperty` operation. Direct assignment is limited to absent keys on the
fresh ordinary outputs under the original live checks.

The plan records the append step, routing step, complete language phase,
repository phase and complete operation separately. Every step and phase has
its complete original/output source, serialized/reparsed CST, rule sequences,
trace and whole inverse. The repository phase preserves the original path and
API. A separate native-span inverse restores every call identifier and removes
only the appended helper, independently reproducing the entire physical input.
Native copied-source binding checks remain mandatory. Complete physical source
hashes and file identities are rechecked at the final boundary, including the
executor, actual candidate output, both producers, common/SHA dependencies and
CST/native-binding implementation inputs.

The complete new two-case receiving file checks these equations and proves the
CLI rejects installation modes without changing original executor bytes. It
must run after explicit candidate materialization. These source-equation tests
and the earlier six candidate cases require the untouched original/candidate
equation, so receive them before an isolated physical trial. They cannot be
claimed green from a trial with a deliberately different original input.

For behavioral qualification, Root can apply the emitted complete original-path
proposal only in an isolated, fully captured trial. Preserve every original
test byte, full input closure, engine, deadline and workload. Run the complete
existing private parser execution, ingress, common-intrinsic,
expected-descriptor, batched-descriptor and ASCII/SHA files, plus complete
`concrete-syntax-meta`, `concrete-syntax-transaction` and
`concrete-project-storage` files. The same physical route then reaches genuine
direct imports, public CST consumers, and original cold copied-executor source
fixtures; a renamed facade import alone would not exercise every such path.
Historical source/inverse controls remain mandatory. Any source-proof refusal
must be repaired through its genuine producer equation, never ignored or
replaced by an unchanged baseline run. Record before/after compiler/Rust/Cargo
vectors and actual source joins for the complete trial as usual.

All proposal generation, new two-case receiving, physical overlays, complete old
files, Node/Bun behavior, strict checks and performance measurements are
**unrun** for this batch. Root owns materialization and runtime leases. No
default adoption, executable gain or measured parser/vector improvement is
claimed.
