# Selected original-source transport successor — source design

Status: approved NEW implementation and independent case SOURCE drafting; all execution/fit verification and integration remain OPEN. Existing reader, corpus, producer, preparer and portable snapshots are unchanged. The original corpus read delegation below is a virtual source equation only.

## Authored implementation and API

`tools/translation/selected-source-reader-20261101.mjs` copies the complete committed reader and replaces its Git transport/fence. Its public DATA APIs are `readSelectedTrackedSourceBytes(root,name,{maxBytes})` and `withSelectedTrackedSourceOperation(root,run,{observe,limits,preload})`. Original default 32 MiB per-read, optional explicitly narrower operation buckets, detached observer shape, precise source/root/ancestor closing, alias/nesting and caught-failure poison stay. Generic aggregate/path buckets remain unbounded; original family budgets remain the producer's responsibility. No original source permissions or corpus issuer are added. The old flag/path helper bodies remain present.

Optional `preload` names are ordinary DATA, not permissions. The worker must join the same actual original selection to its private producer. One combined native `ls-files --stage -v -z` query yields complete stage/tag rows for each packed batch. Packing counts both UTF8 bytes and conservative Windows UTF16 quoting geometry, includes the actual root/fixed argument overhead, and avoids putting ancestor/descendant selections in the same exclusion batch. There is no fixed batch-count or total path ceiling. Late names are queried individually once; all retained rows reissue in complete closing batches. These are invocation-local metadata snapshots, never cached semantic verdicts or across-operation source caches.

`selected-source-reader-20261101-metadata.mjs` discovers genuine original Git control paths, symbolic hop chains, loose/packed/reftable namespaces and initial/closing identities. The active index/shared coordinates come from the private index-image transport. Literal stage and skip rows exclude the literal slash-terminated descendant prefix, covering ordinary files that shadow indexed directories and unmerged D/F entries. Malformed/extra rows refuse; they are not discarded.

`selected-source-reader-20261101-index.mjs` owns an invocation-local exact image of the whole original index. It streams source and copy chunks, keeps immutable original preimages, scans only to locate the `link` extension for actual SHA1/SHA256 v2/v3/v4 images, and leaves all other extensions intact for genuine Git validation. No unrelated Rust pathname listing or universal index-size/count bound is introduced. Full original bytes, inode/time and ancestor/sparse/ref evidence close independently of copied metadata.

For async caller-owned source-history lifetimes, the same helper exposes `acquireSelectedSourceIndexImage(root)`, `withSelectedSourceIndexHandle(handle,syncRun)`, `verifySelectedSourceIndexImage(handle)`, `closeSelectedSourceIndexImage(handle)` and detached `inspectSelectedSourceIndexImage(handle)`. Handles are issued only by a private WeakMap, have no source/type permissions, and cannot be forged from reports. No ACTIVE context spans an await. Each synchronous activation joins the real handle/root; caught failure poison remains on the handle. The async caller must verify and close in a complete finally fence. Source-history optional absent names can be preloaded without trying to read a missing source file; metadata envelope capture/verify runs inside the active handle. Unknown own paths remain retained, and inspection reports the owned recovery directory with `cleanupAllowed:false`.

The split-index transport is necessary because [Git's `read_index_from()` calls `freshen_shared_index()`](https://github.com/git/git/blob/master/read-cache.c), and that reaches `utime()` through [its object-file helper](https://github.com/git/git/blob/master/object-file.c). Ordinary read-only Git index queries can therefore change original shared timestamps. The draft copies both images into its own Gitdir and uses fixed `update-index --no-split-index` there with hooks, fsmonitor, lazy fetch, replacement objects, optional locks and maintenance disabled. [Git passes the repository Gitdir into `read_index_from()`](https://github.com/git/git/blob/master/repository.c), so the working shared copy is resolved inside that private directory. The resulting image must have no link extension. Every later fixed row query uses the ORIGINAL repository namespace with only an internally issued private `GIT_INDEX_FILE`; this retains its original worktree/conditional-config context. Caller `GIT_*` variables are stripped. This is source-authored transport logic, not measured isolation evidence.

Only the working shared copy may receive native timestamp changes, and its full bytes still compare with its immutable preimage. Source images keep strict original timestamps. Private conversion may replace its own index through Git's normal lock/rename; the fixed successful operation then registers that actual result and checks the complete known-name census. All other replaced/unknown paths refuse and are retained. Cleanup handles exact known files/identities and an empty exact owned directory only. Falsy/frozen primaries survive every cleanup/source closing failure without mutation.

If acquisition or a synchronous wrapper cannot return its internal handle and unknown paths remain, it attempts one bounded JSON recovery report on stderr, at most 512 KiB per failed image lifetime. The report contains owned recovery paths, phase, explicit omitted-path count/completeness and false source/semantic/cleanup permissions. It does not mutate the original thrown value. Diagnostic write failure also leaves that exact primary unchanged. Explicit lifecycle owners retain their inspectable handle and can report its detached recovery DATA themselves. Independent UNRUN cases cover caught source `false` plus unknown cleanup, frozen/undefined primaries, acquisition failure and secondary stderr failure.

The additional cost is explicit: at least a complete immutable original index preimage plus working image; split inputs also temporarily keep immutable/working shared images and an original HEAD preimage/copy, and flattening can expand the index. The working shared copy is removed after full byte/ID comparison once flattening proves it is no longer needed; its immutable original preimage remains through closing. Source closing rereads the whole originals. None of this is a measured throughput optimization. Disk exhaustion remains an actual I/O refusal; no old operation-wide cap/deadline is invented. Scratch allocation requires an existing parent outside actual source/Git namespaces; TMPDIR inside the source root is not accepted by prefix waiver, and other existing independent parents are considered. Unknown future Git object/index formats and inability to find an independent existing scratch parent are explicit OPEN transport domains. Ordinary cooperating Windows paths use available flags; stronger hostile reparse guarantees remain OPEN as in the predecessor.

`selected-source-reader-20261101-history.mjs`, its fixed pins and six complete raw snapshots preserve four complete source equations: old reader → full new reader, empty → metadata helper, empty → owned index helper, and exact current corpus → virtual delegation. Every full before/after CST serializes/reparses, language/repository rules and full inverse remain; all retained/transient source aliases count under the original 16 MiB/2M-cell/depth160 DATA limits before accumulating rows. No history/result is a semantic permit. The independent test source retains 60-second cases; fit is OPEN, including an actual >16 MiB unrelated index census case.

## Concrete regression and existing domains

`forward-output-ownership-20261101-bounded-bytes.mjs` defines `gitState()` using `git ls-files --stage -z -- '*.rs' Cargo.toml Cargo.lock rust/Cargo.toml rust/Cargo.lock`, with a 16 MiB output limit. `withBoundedTrackedSourceOperation()` acquires this state before its callback and compares it at closing. Thus an explicit single-file operation can refuse because unrelated Rust index rows exceed this new metadata budget. Its generic path/byte buckets already default to Infinity; that does not remove this separate census refusal.

`forward-output-ownership-20261101-inputs.mjs`, `captureForwardProducerFence()`, independently defines another global `selection()` with the same 16 MiB command-output bound. Changing only the shared reader leaves this second restriction intact. The compiler-root `tools/translation/` index census in that fence is a separate compiler prerequisite and is outside this selected-native-input proposal.

The eight planners select native inputs by `(corpusPaths ?? sources ?? git ls-files '*.rs').sort()`. Representative exact code is in `bulk.mjs:51–78`, `owned-field-bulk.mjs:54–81`, and `owned-definitions-bulk.mjs:55–83`. These are three different original selection domains:

* Explicit direct `sources`, including an empty array, do not require whole-root Rust discovery. Their ordinary direct reads use the original 32 MiB per-file limit. There is no universal direct path-count, aggregate-byte or operation-duration cap to add.
* A genuine `sourceCorpus` gets its paths from the original private WeakMap issuer. `assertSourceCorpusSelection()` checks any accompanying explicit list. `source-corpus.mjs:22–78` retains distinct safe sorted paths, 20,000 paths, 8 MiB per native file, 64 MiB native total, and the actual layout Cargo inputs at 8 MiB each. Public corpus descriptions/digests do not issue this authority.
* Default discovery genuinely selects the whole original Git Rust census. It must still perform and close that selection; observing only files eventually read cannot replace it.

The two owned-definition planners additionally call `captureOwnedDefinitionInputs()`. Its independent original `owned-definition-output.mjs:33–45` `sourceState()` already discovers all Rust paths with a 16 MiB Git bound, then captures the original source/Cargo domain. Preserve this original constraint for these two families. Removing the NEW generic census does not remove their original census or limits.

The forward fence already requires each selected native name to join actual delegated bytes and the full original private CST (`bindNative()` and `seal()`). Valid UTF-8 direct originals may use private complete-CST locators; non-roundtripping bytes remain separately retained. Corpus originals retain their original issuer. Those joins and fresh private producer reissue remain mandatory.

## Minimal proposed transport

The approved NEW complete reader successor is `tools/translation/selected-source-reader-20261101.mjs`, with its own invocation-local frame. Keep the committed bounded reader, corpus delegation, reader histories and both portable source profiles byte-exact until a separately approved successor integration.

The successor provides DATA byte reads and an ordinary synchronous operation, not a source-scope permit. Every actual delegated read registers its literal relative name before reading. For each name, retain exact original selected Git stage rows and skip-worktree state, whole actual source bytes, ordinary file/root/ancestor identities and nanosecond stamps, and sparse HEAD/absence evidence. Compare the complete bytes and rows at closing. A dirty ordinary working-tree file remains readable under the old domain; trackedness must not become a new prerequisite for ordinary explicit fixture files. Missing files require the existing exact sparse skip-worktree/HEAD fallback; an ordinary deletion remains a refusal.

Avoid any unrelated `*.rs` listing in this transport. Query exact literal pathnames, with `--literal-pathspecs`, retaining all index stages and the empty result for untracked inputs. Bound each query by the actual encoded pathname and Git's finite stage/record grammar, rather than a global repository-row cap. Use fixed-size request batches if batching is needed for command-line limits; retain and compare every selected result. Nonzero Git failures, malformed/extra rows, signals, sparse changes and truncated output must poison the active frame. Batching cannot impose a new maximum total input count or silently drop names. Existing per-child Git shutdown/time constraints stay explicit; they are not a new blanket producer deadline.

Before callback execution, capture actual HEAD/ref resolution and the active Git index identity/time envelope, including linked-worktree/common-dir and split-index dependencies resolved by genuine Git. At closing compare those original physical identities/times, exact current HEAD/ref value, and every registered literal index/skip row. This retains detection of unrelated index replacement or modification without materializing its unrelated Rust rows. Full selected stage/skip bytes and source bytes, rather than index hashes, are the comparison evidence. Changed-and-restored bytes or same-byte inode replacement remain failures through retained original stamps. Ordinary root spelling, canonical path and all source ancestors retain initial/closing checks.

The exact metadata dependency implementation remains a review prerequisite: `.git` file versus directory, active index, split shared index, symbolic HEAD/ref chains and packed refs must be covered consistently. Git path discovery is DATA, not permission to follow arbitrary filesystem paths. No symlink, worktree, sparse, alternate-index or unborn-HEAD domain supported by the predecessor may be silently lost. If a complete namespace closure cannot be established for one layout, record that specific unresolved layout before claiming domain preservation. Do not replace it with a broad new repository rejection.

Install the failure fence before acquisition. Every nested source/input failure poisons all joined active frames even if user code catches it and restores bytes. All acquired source/Git/ancestor closers run; an independent boolean preserves the exact first primary, including `undefined`, `null`, `false`, primitives and frozen objects. No diagnostic attachment may replace that primary. Ordinary semantic refusal still follows the original producer's rules. Detached observers retain DATA only; no private buffers, checker methods, emitted facades or issuer capabilities escape. Invocation-local records expire on every exit.

## Selection integration, separate from byte transport

Resolve and retain each planner's actual original selection exactly once inside its original producer path. A private selection handle may join that exact resolution to the fence; public `mode`, `verified`, digest or scope flags cannot select a relaxed path.

For explicit direct lists, preserve the original list contents/order/duplicate behavior and eventual sorted selection; do not impose the corpus array validator on the broader old direct API. Join the same immutable selected DATA to planner iteration, input fence and reissue recipe, including empty lists. Validate unknown delegated native reads against this actual set plus actual Cargo inputs. Retain absent optional Cargo evidence. A public explicit list requests byte inputs; it cannot qualify namespace/type/ownership or grant an output write.

For genuine corpus paths, call the original private `sourceCorpusPaths()` and `assertSourceCorpusSelection()` and preserve complete corpus/Cargo joining. Do not make a second copied corpus WeakMap. For default discovery, retain and recheck the full actual Git selection, including additions/removals not read yet. Its existing discovery domain and any original family-specific census limits remain. No observer-only fallback may stand in for either complete selected set.
