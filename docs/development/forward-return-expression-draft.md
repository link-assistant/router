# Whole return-expression synchronization source draft

`proposeForwardReturnExpressionSynchronization` drafts complete formula changes
in actual ordinary scalar functions from either full generated JS or full TS.
It supports scalar parameter/local reads, strings, Booleans, integer literals,
Boolean negation, strict equality, integer comparisons and Boolean conjunction/
disjunction. Up to 4,096 changed expressions can share one project proposal.
It does not infer semantic permission from a target name or public type flag.

The original compiler now optionally returns small scalar signature observations
with `targetBinding(true)`. The existing zero-argument binding contract stays
unchanged; non-scalar signatures do not clone complete metadata. These DATA
observations select candidates only. Every changed function additionally uses
the original compiler's actual `checkedSource()` association, full original
Rust source and checked parameter/local identities.

Language substitutions parse complete native JS/TS after serialized/reparsed
CST transport. Everything outside the actual final return expressions stays
exact. Qualified scalar let prefixes remain intact; their original source-bound
tail interval and actual target local names supply the scope mapping. Function
headers, imports and other bodies cannot change implicitly. Inline module
offsets retain the complete enclosing source. Unsafe, async, generic, shadowed
or otherwise unresolved source shapes refuse.

The syntactic Rust proposal is independently recompiled through the existing
whole-project checked semantic meta path. The complete original executable/
refusal/method census must remain identical. Its emitted target must reproduce
the entire requested source outside return expressions and the complete native
expression syntax inside them, allowing only redundant grouping/trivia spelling.
The supported grammar excludes reflective/optional-chain constructs for which
that normalization could alter semantics. There is no arbitrary injected
compiler, saved-body verdict or cross-invocation source/result cache.

The original checked program and declaration closures are explicitly released
before the second full compilation; only small signature observations, source
strings, requested native AST and review data remain. Each changed Rust file
is assembled once from ordered source pieces before applying the original
file and whole-source byte limits. The requested AST is
reused within that invocation. Original source, node/depth, memory, file and
transaction limits remain unchanged.

Repository substitutions retain complete Rust/JS/TS equations and inverses.
The source-unit planner/apply reuse the original fresh guarded transaction and
manifest fields with schema `router-forward-expression-unit-v1`. The CLI is
`scripts/sync-router-return-expressions.mjs`; its explicit plan/apply arguments,
fresh dependency-bound process and original resource limits remain intact. The
API facade and shared committed compiler export include this family.

Independent JS/strict TS formula truth tables, inclusive intervals, numeric
extremes, scalar local prefixes, Unicode, inline modules, unbound/call/assignment/
outside-source/format-only refusals, optional signature observations and fresh
transaction/forgery source plus native Rust oracle cases are drafted and unrun.
No compiler, planner, preparer, target, interpreter, test, experiment, Rust tool
or CI has executed. Arithmetic/calls, conditionals/statements, richer types and
scopes, full production synchronization and other open requirements remain
unfinished. This is source drafting, with no new coverage or parity claim.
