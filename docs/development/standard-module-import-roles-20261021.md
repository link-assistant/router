# Source-derived standard module import candidates

`node tools/translation/prepare-standard-module-import-roles.mjs --emit`
proposes the complete actual import-role selector through separately declared
language and repository rules. The proposal retains the full original and
edited serialized/reparsed CST, native TypeScript 5.9.3 grammar and complete
inverse. `--check` reproduces every installed byte. Existing standard time,
conditional type census, dependency and declaration-producer bodies remain exact.

The additive selector inspects complete pinned Rust 1.89 standard/core roots
for an unconditional, explicit public external module declaration. It uses the
original source census, rather than a spelling allowlist. Named imports of
`std::fs`, `std::env`, `std::io`, `std::path`, `std::process` and `core::cmp` can
therefore supply nontrait declaration candidates to the existing owned text
adopter. Each selection retains its complete original source/item hashes and
span. The selector performs a fresh original-root inspection for every request;
no cross-invocation source, owner, hash or verdict cache is introduced.

A named module import does not import its member traits. These candidates grant
no complete namespace, original trait-dispatch or executable authority. Unknown
roots or names, child types, globs, competing aliases, shadowed roots, unknown
attributes/configurations and unresolved declaration producers remain refused.
Existing `std::time` routes keep their original behavior. This extension does
not implement standard-library filesystem, environment, path or process APIs.

The new four-case file checks the actual producer and complete inverses,
original root/item source joins, positive module candidates and complete refusal
controls. A function containing all six imports is adopted through the actual
Core facade, translated to JavaScript and strict TypeScript, and executed with
an independently expected Unicode/NUL result. Changing the owned macro to an
unknown macro still refuses the function at the independent checker.

The complete four-file receiving group contains the new file, both original
literal/borrowed text adoption files and all source-producer freshness cases.
All 33 cases pass under Node with their original deadlines, in 209.146 seconds
at 622,264,320 bytes sampled peak aggregate RSS. Independent source deadline
audit `complete-8qLEGE` has zero breaches and errors. All 33 cases also pass
under fresh sequential Bun processes in 155.027 seconds at 619,773,952 bytes
sampled peak aggregate RSS, including complete source/name/line/deadline joins
and all 2,235 unchanged input vectors. TypeScript is the installed 5.9.3.

The first Bun evidence audit remains RED: every assertion and deadline passed,
but eight line joins compared Node's original registration wrapper with Bun's
original call site. Independent native parsing joins each literal case call to
the exact original wrapper, its imported Node test registration and unchanged
60,000 ms option. Both original spans remain retained. The subsequent complete
rerun qualifies these joins without changing any source case, workload or limit.
Full failed and successful streams, source vectors, wrapper declarations and
proposal/CST/native reviews remain under the task-owned
`router-standard-role-source-acquisition-v1` and corresponding bounded monitors.

Measured production executable coverage remains 155/2,567 (6.04%); no synthetic
fixture or selected source proposal is counted as a production gain. Application
adoption, full current compiler export, canonical/three-profile and reverse
freshness, remaining CI namespace/performance repairs, strict native parity and
the complete JavaScript gate remain open. Full bidirectional synchronization is
not implemented. Rust execution remains CI-only after all eight JavaScript
stages pass for the same SHA, and Rust failures remain fatal.
