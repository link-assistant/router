# Owned multi-module source draft

The owned project frontend copies the complete existing pure ESM linker and
public API packager. Original native symbols, import/export diagnostics,
initialization order, namespace selection, reflection refusals and complete
source equations remain required. Actual pinned runtime imports are preserved,
hygienically renamed and relocated. Application dependency functions link into
one source proposal; native-selected JSDoc/import-type paths retain full inverses.

The complete original project modules must match a current owned source context.
The linked JS/TS proposal enters a separate fresh source context and the existing
whole-function checker, checked callee closure, serialized/reparsed meta and target
emitters. Target packaging publishes only actual selected entry exports and
retains complete JS/TS/Rust layout inverses. It adds no business bodies or native
binding permission. No source, owner, verdict or encoded result persists between
invocations. Node/depth, file count, whole source and original output bounds stay
explicit; module constants and general aliases remain unsupported.

Independent source covers duplicate runtime aliases, helper calls, original JS,
linked JS, strict TypeScript, private interpreters, public re-exports, namespace
selection, source changes, reflection, missing/unreachable modules and both full
implementation copies. All implementation, translator, compiler, test, experiment
and Rust execution is **unrun**.

Packaged Rust authority, reverse distribution into original module files,
multi-module source-unit transactions, generic/class/async modules, production
application and the other bulk requirements still need their remaining draft.
This forward project batch does not close those obligations or certify parity.
