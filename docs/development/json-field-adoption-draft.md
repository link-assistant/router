# Automatic typed field-reader adoption draft

These source and independent regression drafts are unverified. No adopter,
packet producer, planner, source installation, tests or Rust tools have run.

The new field selector reuses the complete existing corpus adopter and its
actual source-role, producer, graph, Cargo, scope and snapshot checks. It selects
unshadowed shared JSON parameters with literal/borrowed text keys, small native
index literals, and four closed `get(...).and_then(...)` scalar-reader forms.
Named lifetimes and exact noncapturing scalar callbacks retain their source.
Unsupported producers, unknown aliases, loops, effects and shadows stay refused.

Each proposal retains complete original/edited Rust CST, selected spans,
receiver/key evaluation order and full byte-exact inverses. The original generic
method dispatch is not proved. The copied packet CLI supports an explicit
`json-fields` sequence under its unchanged storage/resource bounds:

```sh
node tools/translation/propose-json-field-adoption-corpus.mjs --root SOURCE_ROOT --output NEW_OUTSIDE_DIRECTORY --sequence json-fields --packet-storage gzip
```

`planCheckedJsonFieldAdoption` and `applyCheckedJsonFieldAdoption` also have
complete source copies of the existing checked installation path. Every selected
complete replacement function must freshly pass the original project checker,
semantic meta and both target emitters. Apply recomputes the full proposal from
physical source, package/workspace Cargo and Git inputs before the existing
transaction. Candidate counts, type spellings and stored reports supply no
callable, runtime or semantic authority.

`prepare-json-field-adoption.mjs` retains all three complete prior
implementations and exact native-selected substitution recipes. Their originals
are physically unchanged. Both ordered rule sequences and CST/inverse histories
remain. Independent unrun source covers all six patterns, actual JS/strict TS,
scope/native/accessor refusals, complete compressed packets, selected installation
and forged plans. Native field oracle source is retained separately.

Production source application, receiving qualification, general Option/Result
and effect/state behavior, complete parity and all CI repairs remain open.
No coverage or performance gain is claimed.
