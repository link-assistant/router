# Owned source-unit peer reconciliation source draft

This is a complete additive SOURCE DRAFT, with every case and native oracle
UNRUN. No parser, translator, preparer, compiler, replay, package/install command,
test, CI query or Rust tool was executed while drafting. It supplies neither
runtime parity nor a qualified receiving/platform result.

`tools/translation/owned-peer-reconcile-20261101.mjs` exports
`planOwnedPeerReconciliation({root,manifestPath})` and async
`applyOwnedPeerReconciliation(serialized,options)`. Existing unit planners and
the installed canonical pair/triple planners remain unchanged. The original
owned unit planner still refuses the same concurrent edit in the independent
case. There is no authority/force/adopt override on that API.

## Actual admitted domain

The lane accepts one existing `router-source-unit-sync-v1` unit with profile
`owned-outcome` and auto authority, one whole packaged Rust caller, mirrored
`js/src/*.mjs` and `ts/src/*.ts`, and actual `js/runtime`/`ts/runtime` roots. No
application dependency/module edges or multi-unit descriptor is admitted here.
The original `primitiveOperators:true` feature remains optional and retains its
original private type/source requirements; omitting it preserves the ordinary
owned-outcome domain. A literal `false`, unproved field, extra role or unknown
descriptor override remains a refusal.

There is no new scalar-only syntax whitelist. Every body is admitted only if the
ENTIRE original owned-outcome JS inverse, strict written-TypeScript inverse,
canonical native inverse/forward and private source/type/ownership/meta checks
all succeed. This includes only the operation families actually accepted by
those original issuers with the supplied complete native/runtime input cohort.
The scalar bitwise and Result → Option → JSON composition cases are independent
examples, not a claim that the full Router or every vector/effect family works.
Owned-project/distributed modules, async/resource/cancellation profiles, general
topology, rename/deletion and edited native helpers remain outside this lane.

The Rust caller must be inside the resolved physical native source directory and
outside its mapped native library inputs. Complete original
`OWNED_OUTCOME_NATIVE_INPUTS` and any extra native mappings remain ordinary
logical `src/*.rs`/Cargo paths joined to `repositoryRustLayout`'s actual physical
files. Descriptor/runtime/metadata cannot overlap authored peers or any native
library/unrelated native source. Complete runtime roots must contain exactly the
union of the actual original owned runtime producer and original unit asset
producer, including mirrors and the existing effects assets. Missing, edited,
unknown, linked or different-mode members refuse before an output is installed.

## Independent proofs and source preservation

Every operation captures one exact current HEAD and one explicit committed source
baseline. An optional older `baselineRevision` resolves through the original
baseline API. Its complete peer/native/runtime/Cargo blobs remain the source
coordinate, while the descriptor separately matches the current committed HEAD;
this allows a committed descriptor to name an older complete source coordinate
without a self-referential commit hash.

The native file census, complete mapped libraries, workspace/package/lock,
descriptor and all registered runtime bytes/modes are checked against those exact
coordinates. Only the two authored peer entries may differ from their baseline.
The caller itself may match either the original native baseline or the complete
candidate independently reproduced by both edited peers. Any other current
native change refuses. Added/deleted/renamed source files and changed helper/
Cargo/runtime inputs cannot be silently absorbed.

One fixed `language` phase calls the real existing owned producer independently:

1. Current JavaScript is checked against the complete original native/runtime
   cohort. Any missing written signature proposals come from the complete checked
   baseline TypeScript, and the entire edited JS body still re-enters the original
   private checker. The concurrent TS edit supplies no authority to this inverse.
2. Current strict TypeScript re-enters the original native typed-source projection
   and checker independently. The original adapter strips its JS counterpart
   before checking, preserving the original written-type/ownership obligations.
3. The two complete canonical Rust strings must agree byte for byte. Public
   metadata, matching hashes, copied type reports and syntax observations do not
   satisfy this condition or bypass either issuer.
4. Each actual candidate independently re-enters the original Rust producer, whose
   complete canonical support/function parser, source/CST inverse and fresh
   JS/private-meta reissue must reproduce that native source. Complete physical
   canonical JS, strict TS and forward metadata sets must agree exactly.
5. Each canonical forward peer independently re-enters its original inverse and
   must reproduce the same whole native candidate again. Runtime/dependency sets
   are complete original producer sets, not inferred from a matching report.

Source-specific JS/TS metadata naturally records different original text and type
projection history. Both complete independent inverse metadata records are
retained, while exact metadata comparison is performed on the independently
re-forwarded canonical native result. They are never normalized by dropping
source/type/ownership obligations.

One fixed `repository` phase merges only the checked complete Rust candidate,
byte-identical original runtime rows and a bounded proof record. Neither authored
JS nor authored TS is ever an output. Their complete original text, comments,
formatting, CST transport and whole-source inverses remain in the proposal.
Metadata itself must match its exact committed before image or the independently
reconstructed current proof. An unrelated metadata edit refuses.

Unchanged original peers are fully checked and return an empty deterministic
output set. After a successful reconciliation, a fresh replan may observe the
already-installed exact candidate and return a bookkeeping no-op; all private
checks still run. A subsequent semantic edit that would overwrite a DIFFERENT
uncommitted Rust candidate refuses. Advance the committed baseline between such
semantic cycles, as in the second-edit case. This is not general three-language
owned reconciliation or a metadata-based claim to overwrite native edits.

## Installation, closing and resources

Apply delegates to the existing `installFreshAsyncSourceProposal` with a complete
fresh call to this planner. It does not introduce another application writer.
The original guarded installer rechecks the current source epoch, full before
images/modes/inodes and original sources, stages known outputs, quarantines
replacements and performs no-overwrite rollback while retaining unknown data.
Both authored peers remain protected inputs throughout. Existing exclusive/
cooperating-writer and same-filesystem hard-link boundaries remain; no global
atomic visibility, arbitrary hostile-race or durable-crash guarantee is claimed.

All directory reads attempt close without replacing a falsy/nonextensible primary
failure. Native and runtime directory device/inode/mode/mtime/ctime identities
and complete child names close independently. Every captured source, original
runtime producer and current Git epoch gets a closing attempt on success or
failure; an original failure remains primary. Existing private source issuers
and codecs are re-entered per invocation. No cross-invocation verdict/source/type
cache or saved semantic permit is introduced.

The original reconciliation bounds remain: 8 MiB per source/output/proof file,
64 MiB complete retained source/metadata occurrences, 192 MiB serialized proposal
and 4,096 captured/census entries. Repeated references receive no DAG discount.
Original unit native-map bounds, full original meta-codec bounds and private
producer refusals remain. Large complete proofs can refuse; these are conservative
source limits, not measured peak memory or throughput qualification.
