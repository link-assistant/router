# Explicit Schemars Type override output candidate

The installed enclosing-namespace format already proves source-confined Debug
output. It does not close the actual `ClientKind` invocation's Schemars sibling:
the old Schemars checker refuses `#[schemars(with="String")]`. The separate
TypePath helper proves a type clone and no helper definitions for one generator
branch; it explicitly supplies neither type-owner resolution nor whole output.
Those old APIs, source pins, refusal domains and complete test files stay intact.

`prepare-schemars-with-output.mjs --emit` proposes three separate copies of the
complete actual Schemars checker, schema-expression route and enclosing issuer.
It requires their exact current full source pins and installed TypeScript 5.9.3.
Actual native imports, parameter/local symbols, output template predicates,
checked splices, macro-owner fields and DATA cache accesses select every edit.
Each language and repository phase retains its full original and changed source,
serialized/reparsed CST, native edits and independent inverse. Both phase
inverses and the complete source inverse remain in the proposal. The original
prover's proof membership, final source/owner checks and error constructors remain
available. The copied source/function/resolver cache reads and writes are removed
through their actual native lexical bindings, so each new operation reconstructs
that DATA instead of retaining a source program or resolver verdict across calls.
Private issued output membership remains tied to its genuine original context.

The authored helper selects only nongeneric unit enums with one genuine container
`with` Type helper. It reuses the original bounded TypePath parser and private
locked derive/helper registration. Eighteen actual source clauses join entry
preprocessing, custom metadata, Serde filtering, common metadata and output
dispatch. Other nested helper attributes require actual private helper proofs and
their declaring owners. The original parser's exact path filters must prove those
attributes ignored by this Schemars branch. No `schemars`/`value` spelling is
accepted as owner or expansion authority. Unregistered, duplicate, conditional,
callback, custom-schema and unknown macro domains remain refusals.

The actual source selects two distinct complete output branches:

* With original document literals, `CommonAttrs::doc` is nondefault and a unit enum
  has no transparent struct field. The original four-method anonymous-const impl
  uses `expr_for_container_with`; its Type clone supplies no helper definitions.
  The existing source-derived document TITLE/DESCRIPTION mutators and every
  actual output macro/attribute owner remain checked. This is ClientKind's branch.
* Without docs or other common metadata, `get_transparent_type` selects the
  original six-method anonymous-const impl. Its complete output is macro-free.
  The genuine private core error-owner join remains checked, while the output
  records zero macro targets and no invented concat/module_path observations.

Both use the original checked quote inventory, full semantic syntax round trip,
complete output footprint and generated-attribute guards. A separate copied
enclosing issuer consumes only the actual new private Schemars output; every
other original builtin/dependency sibling still requires its complete proof.
Copied flags, aliases, public certificates and empty arrays cannot acquire that
issuer's membership. Whole-source cfg, ancestor and unrelated producer uncertainty
remain independent of an item-local output.

The new candidate deliberately retains `typeOwnerResolved:false`,
`generatedImplBehavior:false` and no runtime or trait-dispatch authority. A copied
TypePath in a generated impl header is syntax, including when the path is
`String`; this operation does not establish that type's implementation or execute
the generated methods. Its original successful quote branch is the namespace
footprint being checked. It is not a full crate compilation or parity proof.

## Meaningful production adoption after receiving

The three parallel candidates alone do not change any production selection.
After their complete receiving qualification, propose a source-derived private
Schemars enclosing dispatcher. Its new-prover selection must first join the
genuine original context/module/invocation and actual container Type helper.
Other inputs retain the original prover and refusals. Assertion/output dispatch
must use actual private `isSchemarsWithOutput` membership, never a public schema,
helper spelling, boolean or copied metadata. An unsupported candidate stays a
refusal; it cannot borrow another output's token or erase a sibling obligation.

Native-select only the actual Schemars import in
`derive-enclosing-namespace-context.mjs` for that dispatcher. Keep the installed
module's existing private context/effect issuer identity and complete source
guards. This reaches `project.mjs`'s existing owned-definition/core-json-readers
namespace branch, `derived-source-bindings.mjs`'s enclosing fallback and
`core-adoption-producer-context.mjs`'s enclosing creator through their actual
imports. Existing Default/Clone enclosing consumers and the owned resolver then
consume the same genuine issuer; no foreign parallel context token is installed.
Review the complete native/CST source proposal and every whole consumer file,
then run the actual full production graph/profile and emitted-target checks.

Keep `schemars-bang-footprints.mjs` and `derive-bang-context.mjs`'s standalone/full
proof APIs unchanged in this first adoption. The existing actual ClientKind
ValueEnum control intentionally requires its full-bang JsonSchema residual.
The ordinary non-owned project mode also uses that legacy full-bang lane; the
enclosing extension does not claim to repair it. Extending that production route
requires a separate source-derived complete consumer proposal and fresh whole
qualification while preserving the legacy controls. No dispatcher, default
import rewrite or production adoption is implemented by this draft.
