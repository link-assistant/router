# Project public scalar synchronization draft

Owned project units and original-module restoration now use the public scalar
profile. JavaScript authority obtains existing public type definitions from a
fresh actual paired TypeScript project. A separate native binding census can
skip that full type-API pass when exports are definitely values; unresolved
edges require qualification. The census grants no type or namespace authority.

Only canonical closed root type definitions are carried from the proposal.
Previous Rust function bodies supply no body authority. The interface adapter
reemits the genuine current program, checks actual native/Cargo/runtime source
joins and packages its public type API. Empty programs receive a fresh JS source
check, including refusal of invented effects. Copied or forged programs refuse.

Rust authority reconstructs the root scalar definitions in the receiving TS
entry. Existing dependency type declarations can remain source proposals.
Every receiving JS/TS module tree must freshly check and reproduce the entire
authoritative Rust. Function imports use `.js` for `.ts` and `.mjs` for `.mts`.
Receiving JS also gets missing parameter/return annotations from actual checked
item domains and captured runtime operations, enabling independent translation
after TS authority. Those annotations provide no loan or effect authority.

Five complete original integration sources, full two-sequence CST inverses,
independent JS/TS/Rust-edit transactions, source/body forgery and native type
census regressions, and Rust scalar boundary oracle source are drafted and
unrun. Type-only interfaces add no invented executable functions or coverage.
Generic/owned/compound public types, full module type identity preservation,
broader runtime syntax/effects, production adoption, parity, receiving
qualification and all other remaining requirements stay open.
