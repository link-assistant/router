# Parsed builtin operation native source draft

All new implementation and cases are UNRUN. Only source construction and review
occurred; no implementation, preparer, translator, test, experiment, generation,
local Rust tool or CI-triggering push ran. No timing or memory result is claimed.

The complete existing native source reader is copied and selected by an explicit
parsed builtin operation. Common builtins, inner lints, module macro_use and
documentation keep separate parser/catalogue premises and rule results. Their
current whole native physical inputs, decoded source and serialized/reparsed CST
can share one source frame inside that synchronous operation. Source-frame
retention uses the original combined 8 MiB bound; every archive, manifest, source
hash, owner span, callback and complete source inverse remains required.

The frame contains authenticated source data only. It does not retain owner or
semantic verdicts, skip actual caller parsing, merge conditional premise domains,
or grant namespace/runtime authority. Each native proof still runs its original
constructor and current-source finish checks. Every native domain is checked on
operation exit even if another fails, followed by a final check of the complete
shared physical input frame. Entering a nested operation discards the parent's
reusable reader reference; the child has its own fresh frame. On every exit the
operation clears its reusable reference and restores its parent. Receipt reads
outside an operation construct fresh native source inputs.

Two complete compiler source equations preserve the original reader body,
explicit ordered language/repository substitutions, native owner spans, CST/meta
boundaries and full inverses. Independent unrun cases cover all four domains,
nested restoration, caller changes, native operation changes, error cleanup and
private receipt reads after exit. This structural optimization does not qualify
runtime performance, actual macro/attribute ownership, production coverage,
reverse synchronization, CI or receiving requirements.
