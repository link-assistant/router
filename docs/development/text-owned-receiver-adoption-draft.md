# Immutable owned text receiver source draft

All new implementation and independent cases are UNRUN. Only source construction
and review occurred. No selector, decoder, parser, translator, preparer, test,
experiment, generation, local Rust tool or CI-triggering push executed.

The complete current text selector is copied through separate ordered language
and repository source substitution rules. Actual immutable parameters written as
String can join the existing owned-text domain. Existing source-producer checks
still reject shadowed String names and unresolved owners; custom types, mutable
bindings, arbitrary constructors and unknown effects gain no string permission.
Only the exact standard spelling is added, without guessing aliases or trait
implementations. Fresh whole-function semantic and ownership checks remain
mandatory before installing any candidate.

Existing owned receiver handling borrows once when calling paired native helpers.
An exact zero-argument as_str method on an already tracked owned receiver becomes
an immutable borrow inside a selected helper expression. It supports explicit
borrowed pattern arguments, immutable aliases and temporary owned receiver
chains; no implicit String Pattern implementation is invented. Arbitrary as_str
owners, extra arguments, standalone unselected bridge expressions and borrowed
String parameter domains retain their old boundaries. Old dispatch/Drop timing
proof and executable admission remain false.

Both source phases and complete intermediate/original inverses from the current
text proposer remain intact, including scalar pattern language edits. The
existing paired native/JS/TS operation catalogue and reverse helper mappings
describe the resulting calls; runtime implementations and generated targets are
unchanged. Two complete compiler equations and independent unrun whole-source,
JS/strict TS, owned argument/local/temporary, mutation/shadowing/owner refusal and
native oracle cases are drafted. This does not qualify production adoption,
source-bank/export freshness, whole-source parity, reverse synchronization, CI,
receiving requirements or any current coverage percentage.
