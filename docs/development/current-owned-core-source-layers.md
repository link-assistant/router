# Current owned core source layers

The current vector refresh, matches, lifetime-refusal batch, checked-source and
primitive identity boundary CLIs compose the explicit ASCII source layer and
then its separate four-file reverse source layer.
Their historical birth APIs still return the complete original before/after
sources, native evidence, serialized CSTs and inverse equations. A current
wrapper compares physical outputs against the final composed sources; it does
not replace a historical source equation with the latest installed bytes.

The complete vector refresh retains the order vector → lifetime → checked source
→ source proof preservation → matches → primitive identity boundary → ASCII
→ reverse ASCII.
The narrower current wrappers retain their existing scope and then add the same
seven-file ASCII layer and four-file reverse layer, with exact predecessor
checks wherever paths overlap.
The primitive boundary CLI validates every complete physical input before any
write. No source output is edited manually by these adapters.

The existing first receiving case in each of the five whole test files checks
the historical equations and both final ASCII layers, including all eleven
physical sources, both CST phases, full inverses, native JavaScript AST copies
and exact Rust source/hash joins. The vector case also rejects modified forward
and reverse predecessors.
The reverse source layer is an implementation draft awaiting its independent
receiving workload. These composition checks are source freshness checks. They establish neither production semantic
admission nor reverse executable support for the ASCII operation.
