# Automatic primitive Option method draft

The source selector now drafts standard presence, unwrap/expect, eager fallback
and and/or operations for written primitive Option inputs and immutable local
aliases. It retains closed primitive argument domains and evaluation order.
Direct JSON bool/u64/i64/str readers can provide optional receiver proposals.
Borrowed text unwrap/fallback is selected only with its explicit following
`to_owned()` or `to_string()` allocation, matching the owned core interface.

The corpus, bounded compressed-packet producer and fresh checked installer are
complete original integer-adoption copies. Their native-selected substitutions,
separate language/repository sequences, full source and CST inverses are retained
by `prepare-primitive-option-method-adoption.mjs`. Every selected entire function
must independently translate before installation. A candidate never proves
original trait dispatch, arbitrary Drop behavior, runtime parity or coverage.

Independent source cases cover typed inputs, immutable aliases, eager chains,
JSON reader results, false/zero/empty payloads, explicit text allocation, panic
boundaries, forged plans, compressed packets, selected installation and complete
source histories. All implementation, regression and preparer source is unrun.

Lazy fallback, map/and_then callbacks, nested or owned aggregate options, Result
counterparts, production adoption and the remaining ledger requirements still
need their implementation drafts. No local Rust tools, translator execution,
tests, experiments, generation or CI have been used in this drafting phase.
