# Enclosing producer and tool-attribute composition source draft

The explicit enclosing-project compiler now composes its genuine complete
derive-output context with tool-prelude resolution. Previously this consumer
still used the legacy binder after the project had already constructed a
separate enclosing-output issuer. The ordinary project and tool APIs retain
their existing lane and proof domains.

`createEnclosingToolAttributeContext` is a complete source copy of the original
tool context creator, sharing its private certificate registry and unchanged
source/header/candidate/parser checks. Language substitutions add the exact
complete enclosing-output association and select the enclosing binder;
repository substitutions retain the separate exported API and project consumer.
Complete original source, native-selected spans, serialized/reparsed CST,
ordered rules and inverses remain in the source preparation archive.

Before inspecting any candidate, the new API rejoins its supplied complete
module set, current source/view/path/profile, external namespace table and item
carriers with the genuine enclosing-output context. A copied or unrelated
context, missing module, supplied item subset or changed source refuses even
when there are no tool candidates. It does not create a derive input context or
supply a missing original owner proof. Every actual derive output, ancestor,
configuration condition, type-prefix binding, import and prelude check remains
required. The privately scoped provisional tool projection is removed in a
`finally` block; it never escapes as admission.

This closes a consumer connection where complete original producer evidence
already exists. It does not close an unresolved architecture type-prefix import,
an unknown producer or the bootstrap prerequisite needed to issue a genuine
input context. The non-trait architecture census remains insufficient for
`rustfmt` type-prefix absence. No public flags, known derive spelling or retained
source hash replaces those obligations.

Independent source cases cover genuine composition, exact certificates, copied/
foreign contexts, complete input association, item filtering, source mutations,
type shadows, unknown derives/imports/configurations, disabled preludes, legacy
behavior, actual enclosing-project consumers and strict JS/TS boundary cases.
Native Rust oracle source is included for CI after all JS stages pass. All
implementation, source preparers, tests and oracles remain unrun. No new coverage,
production parity or complete namespace closure is claimed.
