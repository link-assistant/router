# Common builtin metadata source consumers draft

A complete copied original registry/parser join selects fifteen actual ungated
builtin registrations. It adds bounded `inline`, `cold`, `must_use`,
`deprecated`, `track_caller`, `repr`, `non_exhaustive` and `target_feature`
metadata alongside the existing stability/lint forms. Exact original leading
attribute tokens, actual item targets, literal values, key uniqueness, simple
representation alternatives and alignment bounds remain checked. Raw,
qualified, macro-valued, malformed, incompatible or misplaced forms refuse.

These rows identify and preserve source metadata. They do not qualify layout,
CPU safety, caller-location behavior, diagnostic traces or runtime bodies. The
actual original registry, full parser callbacks, current native input checks,
complete CSTs and whole inverses remain required. Original narrow catalogue and
source APIs retain their domains outside the explicit common-builtin operation.
Its private domain selector grants no source/owner permission, caches nothing
and restores after every exit; each actual resolver creates its own source scope.

Four complete source adapters are copied into one separate module, preserving
their original private input capture, bounds and source/profile joins while
selecting the wider actual builtin scope. The generated source helper/frame and
five-domain project select the same rules. The existing checked frontend uses
the explicit source operation for its configured resolver, and still must check
all types, bodies, ownership, metadata and emitted targets independently.

Eight complete source equations, independent unrun source/native-boundary,
legacy-scope, conditional/generated, JS/strict TS target and Rust oracle source
are drafted. The native oracle explicitly keeps layout and caller-location
observable for later qualification. No tests, experiments, diagnostics, draft
compiler/preparer/translator, generation, Rust tools, push or CI ran. Wider
producers, architecture/type/bootstrap closure, general language/effects,
production adoption/parity and every remaining ledger requirement remain open.
