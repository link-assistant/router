# Native profile receiving source contract (UNRUN)

This additive materializer drafts the native receiving half of the coordinator's CI-only oracle executor. It invokes Git and bounded filesystem I/O, never Cargo, Rust, a translator, TypeScript, Python, a preparer or tests. Nothing here authorizes execution from public context, pins, paths or semantic flags. The executor remains responsible for the actual hosted CI guard, all eight successful JavaScript stages at the same SHA, original native commands, fixed Cargo arguments, child completion, resource monitoring and artifact upload.

The closed control registry selects persistent987 and dynamic4d3 through their complete native-only portable source visitors and entire independent native oracles. The dynamic target also includes the generalized-control oracle because its String/native backend image is unchanged; all original native workloads remain. No caller module, source archive, target or Rust command is accepted. The actual fresh visitor delivers every full before/after CST, complete inverse and language/repository trace; the receiver independently reparses those boundaries and consumes every full raw resource. It retains bounded raw source images and chronology, not every full CST. The native overlay installs only exact Rust substitutions/additions. The complete original Rust packages, Cargo workspace/local-path packages and configuration, declared readme/license/build inputs and `rust/ui/dist` are copied. Transitive Rust token includes and embedded-folder resources are discovered from actual source, including external included fixture scopes. Original physical profile source rows and archive ancestry are copied as proof/recovery custody; unrelated tracked archived CI/meta banks are excluded. JavaScript profile substitutions are neither installed nor qualified by this native-only operation.

`createNativeProfileOracleWorkspace({root,profileId,sourceSha,evidenceRoot})` exclusively allocates a UUID subdirectory inside the existing executor evidence directory and returns an opaque WeakMap handle before copying. `materializeNativeProfileOracleWorkspace(handle,{tick})` performs the asynchronous source copy. `inspectNativeProfileOracleWorkspace(handle)` exposes data describing `cwd`, `workspaceRoot`, `tmpRoot`, `ownedRoot`, `targetName`, recovery paths, lifecycle, source/file/write/retained/raw counters and known-file count. Inspection remains available after failure. `readNativeProfileOracleWorkspaceSource` returns detached complete source bytes from a genuine complete handle; it grants no proof or cleanup authority. `verifyNativeProfileOracleWorkspace` rechecks the original and receiving sides. `cleanupNativeProfileOracleWorkspace` accepts only its private issued handle and never removes `evidenceRoot`.

The entire original Git HEAD tree and index must agree on source SHA, exact path census, blob IDs, stages and executable modes. Every selected native/source/resource file and ancestor has a complete nanosecond identity snapshot before its consumed bytes or blob stream. The complete package cohort and transitive resource closure remain selected across all original cfg branches; profile inputs are additionally captured inside their fresh visitor fence. HEAD/index/loose-ref/packed-ref paths and absence are joined through closing as well. Git blobs are streamed through one `git cat-file --batch` process, with request writing concurrent with consuming stdout to avoid pipe deadlock. Each bounded chunk is compared directly with the actual worktree and written into a separate receiving inode. No hash-only before comparison, per-file Git process, hardlink, manually successful resource whitelist or full-corpus RAM buffer substitutes for that join. Full HEAD/index metadata may exceed the selected-copy path count while remaining under the original 16 MiB per-command metadata bound. The selected copy alone retains the 50,000-path/256 MiB/32 MiB native source limits. Only changed native files retain their original byte preimages; every other receiving source remains the complete original-byte comparison at closing.

The new native-case limits are the control module's 256 MiB source, 32 MiB file, 50,000 paths, 384 MiB total evidence, 64 MiB raw, 20-minute original whole deadline and 2 GiB free reserve. They do not change any old JavaScript/TypeScript receiving deadline or profile API bound. `tick` is an ordinary synchronous operational callback that may throw on time, disk or evidence refusal; it is never a semantic permit. Every serialized full equation is bounded as a transient pair, every retained source image/preimage/metadata occurrence counts, and aggregate counters remain visible after resource refusal. Root-level monitoring still must count the complete evidence parent, child outputs and shared external Cargo target. No capacity-fit or speed measurement has been run.

The receiver preserves Git executable intent and actual checkout mode separately. On POSIX it requires an ordinary executable-mode join and copies the actual permission projection; on Windows it uses available descriptor flags, Node-visible reparse/ordinary path checks, complete identities and actual checkout permissions without inventing Unix executable attributes. Case aliases, tracked symlinks, submodules, nonordinary ancestors and absent sparse worktree files explicitly refuse. Checkout bytes must equal actual HEAD blob bytes; CRLF/filter/worktree-encoding transformations are an explicit unsupported projection, not normalized or hash-only accepted. Cooperative checkout paths are the admitted domain; hostile parent-link races are not claimed closed. A concrete upstream gap remains: the unchanged genuine persistent visitor itself insists on positive `O_NOFOLLOW` and `O_NONBLOCK`. A Windows runtime lacking either still fatally refuses at that earlier profile boundary. This is a workload refusal, never an all-platform pass or a skipped oracle.

All acquired descriptors/processes close on failure. Primary values, including `undefined`, `null`, `false`, zero, empty strings and frozen errors, survive secondary close/source failures. Original file/ref changes and byte-restores or same-byte inode replacement refuse at closing. A poisoned workspace remains retained; arbitrary public paths cannot recover cleanup authority. Source metadata is read-only; no Git index or source file in the original repository is mutated.

The generated native target includes the entire oracle source. The executor must set `TMPDIR`, `TEMP` and `TMP` to `tmpRoot`, and `CARGO_TARGET_DIR` to its original CI workspace target, preserving lockfile/offline flags and dependency reuse. Build targets never belong inside the receiving tree. The native child and all of its processes must exit before verification/cleanup. Unknown files, symlinks, special entries or directories, including leftover native temporary outputs, cause retention and artifact recovery. Cleanup first verifies the complete known census and exact file identities; it then unlinks only known leaves and removes exact owned empty directories, with no recursive deletion, prefix wildcard, cache removal or parent deletion. A concurrent cleanup failure retains the remaining paths.

Independent unrun source cases cover forged handles/options, accessors, path/ADS/alias refusals, a census larger than common pipe capacity, zero/binary/Unicode blobs, actual Cargo local-path/workspace graph selection, transitive external includes, manifest-directory concatenation and RustEmbed folder selection, irrelevant evidence-bank exclusion, unknown/dynamic/outside-root resource refusal, immutable HEAD mismatch, exact primitive/frozen consumer errors and early operational failures with recovery paths. The additional gated receiving assertions independently consume every full profile equation, verify all actual installed native bytes, preserve raw resources, original Cargo configuration and embedded UI assets, and refuse unknown native temporary outputs. Those helpers invoke no Rust. Actual Cargo typechecking, native oracle behavior, Windows receiving, dirty/mutation and resource-edge receiving outcomes remain unverified and belong to the coordinator's subsequent CI-only execution.

The initial whole-repository copy design was abandoned from source Git metadata: the actual tracked HEAD exceeds the fixed native source envelope. The implemented selector retains the complete real Rust package instead, using vendored TOML parsing only for DATA resource discovery and the existing complete Rust lexer for source token paths. It never detaches nominal owners or grants compiler permission. Root `.cargo/config.toml` or legacy `.cargo/config`, and package ancestor configurations, remain actual tracked inputs; no debug/incremental/cache flags are synthesized. The existing build script receives the executor's verified `ROUTER_SOURCE_COMMIT` only for copied-profile Cargo. Unknown dynamic include producers, unsupported Cargo member globs/paths and missing tracked resources are fatal retained workload gaps. Actual selected-cohort fit remains UNRUN.

The actual root is a workspace-only Cargo manifest. A package at repository root explicitly refuses instead of using an empty `./` prefix; this is not advertised as a general arbitrary-root package materializer. Git stdout/stderr reads and stdin drain waits have removable per-operation abort waiters, and every failure destroys all three pipes and attempts child shutdown. Shutdown waits at most two seconds within the original remaining whole deadline; an unconfirmed exit is retained and reported through descriptor process counters/IDs, never treated as a successful workspace or cleanup permit. Primitive/frozen primary values survive secondary shutdown failures.

Raw Git accounting retains and charges the initial complete HEAD/index census DATA once. Every closing check still reads and compares the entire current stdout stream byte for byte against those original strings, using a bounded transient UTF8 comparison buffer; duplicate closing stdout is not retained or charged as new raw evidence. `gitPhysicalReadBytes` separately reports all repeated actual read work, including batch body/header/delimiter bytes. Stderr and newly retained initial output remain charged. This distinction does not alter the 64 MiB native Cargo/raw cap or omit a source check. Bounded readers still guard the full Git metadata paths, including a linked-worktree `.git` file.

The new pure metrics module is used by the coordinator's actual monitor. It validates exact ordinary process/resource DATA and uses a bounded O(n) descendant BFS, with unique safe PID/RSS rows and safe sum refusal. Observed boundary equality is accepted; exceeded deadline, free reserve, evidence, raw or sampled RSS bounds produce reasons. Null RSS stays explicitly unknown (`rssKnown:false`, `unknowns` retained), never zero or a peak-memory proof. Independent subprocess-blocked control/workflow cases cover all eight actual stage IDs, forged gate/data/local refusal, original full YAML CST/inverses/commands/deadlines, actual Windows scalar newline boundaries, all five resource boundaries, full32768-row process observations, overflow/forgery and fake-child closing errors. All remain UNRUN and never invoke real Rust even when executed later.

The workflow source cases use a separate subprocess guard from the local/private-gate refusal cases. They retain the genuine original bounded tracked-source operation, whose Git HEAD/index/sparse checks must actually run. Only its exact read-only `execFileSync` Git command forms, bounded timeout/output options, original root and isolated Git environment are permitted; sparse object reads are restricted to the actual complete workflow and history paths. Cargo, asynchronous Git, write commands, ps, PowerShell and all other child APIs remain blocked. No Git state or HEAD is mocked. This correction is source-drafted and UNRUN.
