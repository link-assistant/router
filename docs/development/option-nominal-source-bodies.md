# Checked Option payload source bodies

The forward compiler specializes the pinned original Rust `Option::unwrap_or`,
`unwrap_or_else` and `or_else` bodies through its existing checked match/let
pipeline. The unchanged `Mode` fixture in `option-unwrapping-types.test.mjs`
now translates instead of refusing. This fixture is not an original Router
runtime module and establishes no new whole-corpus coverage count.

Nominal payload admission uses the existing complete project Copy prepass,
including original parser associations, resolved derives, implementation
owners and field layouts. A private association carries that evidence to the
actual checker. Copy establishes the required no-Drop property. Every nested
nominal/standard layout is compared again; public cloned certificates and
matching names/checksums cannot issue this association. Flattening preserves
named Rust generic arguments and checks their exact qualified identities.

Eager fallback arguments evaluate once in source order. Zero-argument closures
and resolved function items are checked before their bodies are substituted
into the original lazy branch. Captured locals require the same bounded Copy
or borrowed-str ownership evidence. The selected `or_else` wildcard alias uses
a private parser adapter; it returns the checked original receiver in the Some
arm. Emission validates lazy bodies before applying the emitter's existing
lexical renaming, then compares the complete exact renamed node.

The new nominal and lazy semantic nodes require fresh original-source checking
in the emitting process to reestablish their private contexts. Serialized meta
alone does not confer nominal ownership or callback authority. Existing scalar
eager nodes retain their independently reconstructed fresh-process path.
`unwrap`, `expect`, nominal Default, custom Drop, owned String/PathBuf payloads,
Result lazy counterparts and unproved capture ownership remain outside this
batch. Complete runtime parity and the full gate remain the integration
owner's responsibility.

The bounded fixtures execute generated JavaScript and independently strict
compiled TypeScript, verify side-effect timing and lexical captures, preserve
qualified nominal identities, and reject mutated root/dependent layouts,
public clones, missing Copy and Drop implementations. Node and Bun run the
same source tests; no Rust/Cargo build is needed.
