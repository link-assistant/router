# Whole paired direct helper replacement: source draft

`proposeOpaquePairedCalleeInverse` extends the edit toolbox to existing direct
helper calls. It consumes complete authored JS/TS, uses a fixed genuine function-
association capture and prepares exact original Rust callee-token changes. It
then checks fresh original/native/adopted projects and requires exact complete
reproduction of both authored projections. No external capture, verifier,
callback, type hint or public success flag can supply compiler admission.
Everything remains SOURCE/UNRUN; full translation/synchronization is unfinished.

## Native/target scope and semantic boundaries

Each selected call is a plain declared target function invocation inside a unique
actual emitted top-level function. Every original occurrence for that owner/callee
must change consistently. Arguments, definitions, imports, types, comments and
all other whole-module syntax stay exact. Up to256 groups/4096 original target
and native edits include disjoint simultaneous swaps. Partial occurrences,
unknown or shadowed callees, optional/generic invocation, property calls, nested
closures and changed argument/module syntax refuse.

The native join requires actual fresh source/target associations for caller and
both helpers, one original/adopted physical top-level owner per declaration, exact
span containment and one source file/module prefix. No original method or ancestor
is extracted into a fake standalone module. Unqualified native call multiplicity
must equal both adopted and actual target counts. Member/path/macro/reference/
shadow ambiguity and direct caller recursion refuse.

The original/adopted helper headers must also match as full written token shapes,
normalizing only function/parameter names from the actual association. The check
retains reference/mutability/lifetime/type/qualifier/attribute syntax, caps headers
2048 tokens/64KiB and refuses generic function declarations or unknown parameter
joins. This is an additional source refusal guard, **not a type or ownership
proof**. Both full changed programs still pass the original private semantic,
namespace, effect, borrow and source checks. Cross-module resolution, changed
argument adaptation, methods, wider generics and broader expression edits remain
unsupported. Exact header spelling cannot bypass an unresolved private owner.

The fixed sampler uses complete actual function DATA and bounded hints only to
prioritize one candidate. Hints are grouped once by source/module/signature to
avoid repeated whole-table serialization; candidate work caps2M. Native written
header and physical call checks still follow. No failed source check is swallowed,
no tiny substitute graph is fabricated and no missing candidate is skipped.
The fixed inverse recaptures everything rather than trusting the sampler's DATA.

## Two ordered rule sequences and full source custody

The language sequence transports/reparses both full targets as CST, captures the
complete original baseline, builds whole physical Rust candidates and independently
checks the changed graph. The repository sequence retains complete Rust/JS/TS
before/after source/CST/inverses and agreed authored targets. The original complete
admission/refusal/method census must agree. There are six top-level project
attempts in the inverse; the independent sample adds three, for nine total.
This is source-coded accounting, not a measured speed or resource result.

Three full sibling copies retain the previous fixed binding inverse, actual
strict/runtime verifier and function-association receiver. Their fixed producer
uses complete pinned original bytes and counted language/repository substitutions;
all renamed imports point to their actual matching copied modules. It retains
full originals, successors, CST and inverses. The stable hub before/after is a
fourth whole equation. All older APIs, snapshots, constructors and cases remain.

## Correct baseline versus edited receiving

Replacing a helper may intentionally change behavior. The receiving source
therefore strict-compiles and imports **both** the original adopted baseline and
the edited complete program. All nine unchanged independent token-row vectors
still run against their original adopted baseline through the unmodified verifier.
They are not asserted as unchanged outcomes for a legitimately changed caller.
The edited caller's behavior still needs independently authored new vectors;
`editedCalleeBehaviorQualified:false` and runtime/native parity false remain
explicit. Import/strict success alone never becomes complete caller parity.

The two native oracle cases independently retain changed checked-boundary outcomes
and repeated argument/callee effect order. Their ordinary *_test.rs target uses
existing gated all-feature/suffix discovery; Rust stays CI-only after all eight
same-SHA JS gates. They are family edge oracles, not claimed full production
caller parity. Broad actual edited-caller feature/vector mapping remains OPEN.
