# Ordinary macro file-token source context draft

This implementation and every new case is UNRUN. Only source construction and
review occurred. No issuer, source executor, translator, preparer, generation,
compiler, experiment, test, local Rust tool or CI-triggering push executed.

The additive source domain copies the complete original request validator,
current native/CST/source-constructor request processor, private issuer and fact
reader. It selects an ordinary ASCII source identifier immediately followed by
a bang. The previous ordinary identifier API keeps its original boundary domain.
Raw identifiers, lifetimes, partial names, nonmacro names, changed source views,
accessors and invalid source/profile/span associations remain refused.

The new route retains every original FD/current-source check, independent source
hash, genuine module view, full canonical CST serialization/reparsing, fifteen
complete original constructor inputs and 102 original constructor programs.
Positive results remain conditional ordinary lexical-token equations. Existing
source normalization, input, node, ASCII-predicate and constructor bounds remain.

Private receipt state contains only the original request/module/view identity
and immutable selected span. It retains no computed source/hash/constructor/
verdict/result cache. Every fact read rebuilds the complete current native source
equations. Cheap original view/span association checks precede expensive native
construction, and complete associations are checked again after asynchronous
source work. This preserves late-change refusal without caching a prior result.

The ordinary token equation does not produce an actual rustc context object,
resolver scope, source-callsite Span or macro owner. Those fields remain null or
false, as do namespace/type/runtime authority and whole-compiler execution.
Joining the genuine include-str attribute to this separate source-origin domain
still needs an explicit consumer; actual owner/global/visitor closure remains.

Three complete compiler equations preserve whole original implementations and
native owner spans through language/repository substitutions and full CST
inverses. Independent unrun source cases cover the actual macro name, complete
constructor inputs, fresh fact identities, original API separation, private/
changed-view/refusal cases and source equations. Wider source/production/parity,
reverse/synchronization/freshness/CI and receiving requirements stay unfinished.
