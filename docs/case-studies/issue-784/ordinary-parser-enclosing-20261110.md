# Ordinary parser enclosing namespace repair

The ordinary project parser reconfigured its name domain from the complete
generated-method context. A large, genuine `Clone` invocation can exceed the
unchanged method AST budget while its enclosing item names remain closed. That
method refusal then incorrectly prevented an unrelated CSV function from
resolving the standard borrowed `str` type. Delivery remains in
[PR #785](https://github.com/link-assistant/router/pull/785).

The actual facade producer now composes one ordered repository source rule
after its complete ingress-boundary history. The rule gives the top-level
parser the existing checked enclosing context. Actual impl methods still
construct their independent full context lazily. The ordinary public binding
report, generated method admission and all original AST budgets remain intact.
The complete proposal retains both serialized/reparsed CST phases, original
native statement copies and bindings, full source and its complete inverse.
Source transport grants no semantic or executable authority.

The added regression uses a 128-field derived record beside a CSV function.
The original whole five-case file reproduces one failure: `shadowed borrowed
str type`. After the repair, the function executes in emitted JavaScript and
strict-compiled TypeScript, including duplicates, Unicode and Rust whitespace.
The over-budget `Clone` method remains refused. Unknown derives, a shadowing
`str` module and unresolved imports retain their refusals.

A wider draft changed the public binding report and failed the original
method-owner contract. Its complete proposal and failed whole-file run are
retained. The final rule changes only the parser's private context. All eight
complete focused files pass **33 Node cases and 33 Bun cases**. Node's
independent source-deadline audit observes all 33 completions, 29 finite source
deadlines, zero breaches and zero unobserved finite deadlines. No test cases,
assertions, limits or original deadlines were removed or raised.

Node 20.20.2 takes 134.137 seconds and samples 1,768,071,168 cgroup bytes.
Local Bun 1.4.4 takes 117.878 seconds and samples at most 1,980,764,160 bytes
across the eight sequential files. CI uses Bun 1.4.3. Neither reaches the
unchanged 2,866,933,760-byte guard; samples are total container observations,
not exact process peaks. The source-selected inputs remain identical across
the complete Bun cohort.

The unchanged historical `config.rs` one-parent ordinary-project probe now
emits `parse_csv`, source span 38315–38488. `parse_usize_csv` remains refused
because this isolated graph cannot resolve `ConfigError`. The complete probe
takes 65.900 seconds, including original fixture/module loading; its compiler
call takes 32.157 seconds. It samples 1,752,621,056 cgroup bytes and exits
normally. This diagnostic is not the original whole-library test and does not

The retained complete JavaScript and TypeScript outputs also pass independent
strict compilation and both receivers execute five CSV cases. Null, objects,
numbers and lone surrogate strings refuse. This receiving check takes 4.052
