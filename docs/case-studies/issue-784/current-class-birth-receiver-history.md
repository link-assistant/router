the registered class program was generated. The original class producer could
only reverse an exact installed birth successor. It therefore rejected the
current receiver successor before the first original class test could run.
Its untransformed Host entry pin was also stale.

The producer now composes the actual `prepareSharedF64MethodReceivers` history.
It accepts either the registered birth predecessor or its registered receiver
successor, reverses the complete birth edits, and checks the original 55,188-byte
input with SHA-256
`8d8563e6c7311c7f18d928cc6783fc1064e9001c790a6958b0af84697616b1c9`.
The original pin stays in the producer. The receiver language and repository
rules then pass through serialized, reparsed CST source equations and inverses
before independent class selection. Final physical inputs are reread.

The existing Host entry producer generated the current untransformed entry pin.
The actual class producer regenerated the complete stored program. All 24
class source hashes, parent/factory domains, names, arities and public method
shapes match the previous stored program. Only the pattern-control file row and
the Host entry pin change. All 13 generated class files reproduce their current
physical sources; no class source body was edited for this repair.
