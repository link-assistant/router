# CI evidence archive

The pinned branch population is defined by each `pull.json`, all paginated branch-run responses, `complete-branch-runs-all.json.gz`, and `requested-attempt-ledger.json.gz`. New runs created after that snapshot are outside this population. `computed-metrics.json` separates latest workflow-run outcomes from historical attempts, workflow-specific success from complete observed revision success, and recorded commits/revisions from unknowable exact push counts.

`archive-completeness-ledger.json.gz` records every requested adverse or historical attempt, all retrieved job inventories, completed run-log manifests, errors, and any remaining budget gaps. A historical `logs-not-downloaded.json` or extraction error remains as provenance when a later retry succeeds; the current complete manifest takes precedence. Eleven run ZIP endpoints returned404 after retry; those runs have zero jobs and zero check runs. `unavailable-run-check-receipts.json` preserves their check-suite results. HTTP404 alone does not establish retention expiry.

Full ZIP downloads are hashed in `source-manifest.jsonl`, held only in memory, scrubbed, and stored as gzip or XZ text members. `expanded-log-manifest.json[.gz]` records each member's stored path/hash/size, redaction, and decoded SHA256 where collected or migrated. `log-compression-migrations.jsonl` links prior gzip hashes and paths to atomically installed XZ files after exact decoded-byte verification. The first 152 migrations recorded timestamps but did not measure individual elapsed seconds; the following 1,181 log migrations and 162 artifact-object migrations measured per-file elapsed seconds as well as exact decoded hashes. Decode with Python `gzip.open` or `lzma.open` according to the final suffix. The source ZIP's original byte hash cannot be reconstructed from scrubbed members.

For formal-ai run 37652296393, six failed jobs have no acquired log: a second full ZIP capture reproduces the missing members, direct job-log endpoints return404, and their check-run annotations say each job was never started because it repeatedly failed to be acquired. These annotations and direct endpoint receipts are retained separately. Six jobs are six occurrences, not 72 because each check returns 12 annotations.

All relevant retained artifact metadata is preserved with IDs, run IDs, archive URLs, original sizes and expiry flags. Artifact selection manifests explicitly distinguish selected textual failure reports from unrelated successful-run reports, native binaries, native coverage objects/profiles, unavailable bytes, and any budget limits. Native coverage objects in formal-ai include six archives around 7.4GB each; their metadata is retained, their binary bytes are not part of this text archive. ZIP text members are content-addressed in `text-objects`, with exact member names and each originating artifact retained in manifests; identical decoded text shares one stored object. `artifact-storage-migrations.jsonl` preserves migration provenance for earlier per-artifact files; `artifact-object-compression-migrations.jsonl` links gzip objects to verified XZ objects. Older incomplete JSON variants are retained losslessly in `historical-json-variants` with records in the metadata compression ledger, so an earlier empty inventory cannot shadow the current complete one.

`source-manifest.jsonl` is the cumulative append-only API provenance record across all collector passes; `source-manifest.json` is only the most recent individual collector invocation that made API requests's convenience summary. Large immutable API responses are gzip-compressed and `metadata-compression-provenance.jsonl` preserves their original hashes. Transient malformed/EOF responses record stdout length and SHA without exposing response contents. `rate-limit-final.json` records an observed API budget; it is not a claim that API limits remain unchanged.

`archive-integrity-initial.json` and `archive-integrity-before-derived-update.json` preserve earlier failed scans. `archive-repair-provenance.json` documents the recaptured log-container receipts against an unchanged source ZIP. `derived-manifest-updates.json` preserves the superseded stored and decoded hashes of one mutable Router artifact-selection summary, its current hashes, and the independently checked current references. The old summary bytes were not recovered; the receipt distinguishes demonstrated selection changes from inferred effects of earlier remapping. The final scan explicitly counts this superseded derived receipt rather than treating its historical hash as a current immutable API response.

The archive scripts use a shared disk allocation, credential scrubbing, and at most two concurrent large-log XZ compressors. `archive-integrity.json` reports final receipt checks and allocated case size; it must be regenerated after any archive payload or receipt change. Host issue resource figures are source-authored incident observations; the accompanying CI receipts independently establish workflow outcomes and concrete diagnostics. Original host journal/cgroup/disk time-series exports were not provided.
