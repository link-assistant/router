# Reuse the JavaScript-first publication standard

This bundle is a copyable policy and contract, not evidence that a target repository already translates its complete runtime. Copy the agent and contribution templates into the repository's own guidance, adapt the parity manifest and checker to its real file layout, and replace workflow placeholders with checked-in commands. Preserve existing terminology, test tiers, credential requirements, release policy and changelog rules.

The contract has one publication owner and one complete JavaScript gate. The gate covers lint, native Node and Bun tests, types, strict parity and deterministic forward/reverse generation diffs. Its success is bound to the current SHA and file contents. Workers use isolated worktrees and draft commits. The owner integrates one complete batch, verifies it, pushes one head, leaves running CI intact, then collects every completed failure before scheduling the next repair batch.

`parity-manifest.template.json` records the generated subset and explicit exclusions. `check-parity.template.mjs` validates safe paths, declared source/output/fixture existence, identity and inventory completeness for the declared roots, then rejects every non-generated/non-ported entry in strict mode. It also rejects exclusions in strict mode. Native code cannot become proven parity by changing its status: the real repository must add shared behavior tests and translation/regeneration checks, whose outputs the complete gate verifies. The checker is an inventory guard, not a semantic equivalence proof.

Run the synthetic fixtures from this directory with `node check-parity.template.mjs fixtures/complete.json --root fixtures --strict`. `fixtures/incomplete.json` must fail strict mode; `fixtures/missing-inventory.json` must fail even without strict mode. The fixture files are deliberately tiny and do not represent Router behavior.

`workflow.template.yml` is a reusable callable workflow with required explicit commands and a required immutable 40-character source SHA. It is additive and requires adopting CI callers to wire every Rust compilation job behind it. Do not paste shell commands from untrusted workflow inputs. Repository-controlled callers provide the reviewed commands; pull request authors cannot override them through dispatch inputs. The checked-in action SHA pins are copied from Router’s existing bindings workflow. Verify these revisions under the receiving repository’s policy. The workflow validates its checkout against the source SHA and exposes `tested-sha` only after complete checks and a clean final working tree. Generated release pipelines must match this output to their declared source SHA, which can differ from the generated repository commit or `github.sha`. Forward and reverse checks must reject stale generated files; build jobs check out the validated `tested-sha`. Adapt permissions, tool versions and artifact handling to the receiving repository's policy. Keep cancellation disabled, and make every Rust job depend on the gate. A structure checker should reject Rust jobs without the dependency and compile steps within the pre-gate job.

For scarce disk, avoid clones and local builds. Prefer streamed compressed evidence under a configured budget. A local Rust exception requires the complete current gate, an explicit targeted command, a locked target outside every worktree, low CPU concurrency, memory/time/disk limits, no debug/incremental artifacts and a free-space reserve. Cleanup is limited to the task's own temporary artifacts and never removes existing user caches or a running build's lock.

Measure archived runs/jobs/PRs using Router's `scripts/measure-js-first.mjs` or a copied tool after reviewing its schema. Archive every attempt and job timestamp required for the comparison. Keep RSS, target disk and costs null unless independently measured. Sum job seconds separately from elapsed feedback time; label synchronize-event coverage, unique CI heads and commit counts honestly. Use comparable workloads and runner/cache conditions before attributing savings to the standard.
