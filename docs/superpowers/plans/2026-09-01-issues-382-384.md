# OAuth Durability and Subscription Health Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix issues #382, #383, #384, and #385 in one pull request and verify
the resulting patch release is publicly delivered.

**Architecture:** Decorate every production credential reader with a
data-directory-backed recoverable store, make lock/persistence failures stop
refresh transactions, serialize every Router-owned credential writer on that
same lock, and give subscription health explicit absent/starting/healthy/
degraded semantics derived from credential and catalog evidence.

**Tech Stack:** Rust 2024, Tokio, Reqwest, Serde, SHA-256, Axum, Cargo tests,
GitHub Actions, GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-09-01-issues-382-384-design.md`

## Global Constraints

- Deliver #382, #383, #384, and #385 in one pull request.
- Never log, expose, or place OAuth token values in filenames.
- Never contact a token endpoint without a registered, acquired durable lock.
- Never return/cache a rotated refresh chain before either the primary or
  recovery store is durable.
- Preserve all vendor-specific credential fields when reconciling.
- Conditional import never replaces a credential that appears before or while
  it waits for the shared lock.
- A malformed or explicitly rejected conditional-import candidate changes no
  destination; rejection requires explicit force before installation.
- Starting health is distinct from healthy and degraded, and does not return
  HTTP 503.
- If release delivery fails, repair it through a follow-up pull request.

```rust
#[derive(serde::Serialize, serde::Deserialize)]
struct RecoveryRecord {
    version: u8,
    provider: SubscriptionProvider,
    baseline_fingerprint: Option<String>,
    token: SubscriptionToken,
```

Derive Serde for `SubscriptionProvider` and `SubscriptionToken`; validate the
version/provider, use SHA-256 account filenames, owner-only atomic replacement,
