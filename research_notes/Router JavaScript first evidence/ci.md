### Inferences
- Many green parity or small utility workflows can coexist with a permanently red acceptance or principal pipeline. A parity badge alone does not demonstrate full product behavior or delivery readiness; the relative-meta-logic and formal-ai histories demonstrate the distinction. — [relative PR184](https://github.com/link-foundation/relative-meta-logic/pull/184); [formal-ai PR1188](https://github.com/link-assistant/formal-ai/pull/1188).
- The issue's 15-run relative-meta-logic denominator and 11/12-run formal-ai denominators omit earlier retained history. They should be quoted as source-issue observations, with the complete reconstructed counts alongside them. The exact original `gh run list` limit and selection are not preserved. — [issue759](https://github.com/link-assistant/router/issues/759).

### Gaps
- Git pushes are not reconstructible exactly from unique CI head SHAs or commit counts. One push can introduce several commits, one revision can be retriggered, and a push can trigger no retained workflow.
- Run `updated_at` supplies a final-update timestamp; it is not a billing measurement. Billable CI minutes, complete success-job execution minutes and runner-rate multipliers have not been recovered. All 1,735 requested adverse/historical attempt job inventories are archived separately.
- Retained API runs are available history, not proof that deleted runs never existed. The collection records the exact source responses and retrieval errors.

## Which causes are demonstrated by failure evidence?

### Takeaway
Router's red runs include coverage policy, a missing release fragment, external registry rate limiting and a timing-sensitive test; Rust compilation load does not explain all of them. Meta-language also has failing native JavaScript verification, so JavaScript-first execution must retain strict tests and aggregate requirements rather than promise automatic success.

### Cited Findings
- Router run37862094392 failed its changelog-fragment check: no fragment was present. This is a release-policy failure, not a compiler/resource failure. — [failing job](https://github.com/link-assistant/router/actions/runs/37862094392/job/113600497239).
- Router run37873145649 failed the unchanged coverage ratchet at 86.50% versus the default-branch baseline of 86.76%. Several later runs passed measured coverage but failed the separate requirement to commit a reviewable baseline increase. Run38007252770's README records 80,586 covered / 92,490 measured lines (87.129419%) while the failure job requires the baseline change to be committed. — [ratchet failure](https://github.com/link-assistant/router/actions/runs/37873145649/job/113646788582); [reviewable baseline failure](https://github.com/link-assistant/router/actions/runs/38007252770/job/114088114676); [experiment evidence](https://github.com/link-assistant/router/blob/f556c81127c5cda35de7b7ca2a4f4fb09e119543/experiments/issue-724/README.md).
- Router run37990162689's Tunnel Image Smoke Test failed fetching pinned Alpine from Docker Hub with HTTP429 and an unauthenticated pull-rate-limit response. Docker Runtime Build run37990162700 failed on pinned Rust, Debian and Bun image metadata with HTTP429 across its recorded attempts. Pinning the digest did not remove registry availability or pull-authentication requirements. — [tunnel failure](https://github.com/link-assistant/router/actions/runs/37990162689/job/114021969438); [runtime run](https://github.com/link-assistant/router/actions/runs/37990162700).

### Inferences
- Collecting all failed jobs before drafting a push should combine coverage-review updates, regression corrections, changelog policy and registry mitigation in one reviewable revision. The archived evidence supports cause-specific fixes; changing the implementation language alone would leave policy and infrastructure failures intact. — [Router PR749](https://github.com/link-assistant/router/pull/749).
- High cancellation counts quantify adverse workflow outcomes; they do not by themselves establish cancellation initiated by concurrency versus manual intervention. Causal cancellation attribution requires workflow configuration and matching log/event evidence. — [run API fields](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-repository).

### Gaps
- The final durable ledger accounts for all 1,735 requested adverse/historical attempts: 1,724 complete run-log archives and 11 HTTP404 responses, with all 1,735 job inventories collected. The 11 unavailable run archives each have zero jobs and zero check runs; expiry is not established. Six failed jobs within formal-ai run37652296393 never started because runners repeatedly failed to acquire them, as their archived check-run annotations establish. Detailed failure classification is retained in `failure-analysis.json`.
- Full logs are stored once per run attempt as scrubbed gzip or verified XZ members. The artifact inventory contains 5,691 relevant records and 616 completed selected text bundles / 4,181 member references, including all 165 selected formal-ai text bundles. Native binaries, Docker build records, raw coverage objects/profiles and unrelated successful-run artifacts retain metadata with explicit selection reasons; this is not a claim that all artifact bytes were downloaded. `collection-final-summary.json`, `archive-completeness-ledger.json.gz` and `archive-integrity.json` provide the delivery counts and verification receipts.

## What does the host incident establish about resource use?

### Takeaway
The linked host incident distinguishes repeated child compiler cgroup kills from the final host Docker-daemon OOM and recovery-snapshot disk exhaustion. The provided issue bodies and checked-in experiment notes report measurements, but this collection does not contain the original host journals, `memory.events` series or disk/RSS traces needed to independently reproduce every stated figure.

### Cited Findings
- Hive-mind2889/2892 report a 2026-10-09 12:11:39 UTC global OOM that killed host `dockerd` at approximately 7.3GB RSS after roughly 22 simultaneous `docker diff` calls, then a daemon restart that force-killed four Router task containers. The root container was restarted manually at 13:31 UTC. These are dated source-issue incident statements, with a short host-journal excerpt in2892, not fresh measurements made during this case study. — [disk incident2889](https://github.com/link-assistant/hive-mind/issues/2889); [OOM attribution2892](https://github.com/link-assistant/hive-mind/issues/2892).
- Issue2892 reports earlier surviving child cgroup OOM events: task724 five,725 three,727 two,728 two, at a roughly2.9GiB limit. It attributes the final exit137 to Docker force-killing containers after daemon restart, with a stale lifetime `State.OOMKilled=true` flag causing misclassification. The source differentiates task-child and host-daemon failures. — [incident2892](https://github.com/link-assistant/hive-mind/issues/2892).
- Issue2889 reports four simultaneous snapshot commits of11 /21.2 /23.5 /36.8GiB writable layers, mostly Cargo target directories, on a host with52GB free. It reports free disk declining to2GB, `no space left on device` for two commits and retained original-container plus recovery-image copies. It proposes resuming existing containers, serializing snapshots and checking/excluding regenerable caches. — [incident2889](https://github.com/link-assistant/hive-mind/issues/2889).
- Disk-space-saviour36 reports a1.02GB `target/semver-checks` baseline cache and missing cache-location/rule coverage from a `du -xsk` scan; the exact scan output is not attached in the captured issue body. — [cache issue36](https://github.com/link-foundation/disk-space-saviour/issues/36).
- The preserved bounded-build source limits a single child's sampled `VmRSS`, scans `/proc`, uses one build job and returns125 if its finite guard terminates its command process group. It does not continuously measure aggregate cgroup memory or disk, and its sampled single-child peak must not be presented as total container RSS. — [bounded-build source](https://github.com/link-assistant/router/blob/f556c81127c5cda35de7b7ca2a4f4fb09e119543/experiments/issue-719/bounded-build.py).
- Router's experiment724 README reports disjoint unit-test partitions, preserved test inventories and finite2400MiB guards; experiment725/727/728 notes independently state that ordinary combined library-test builds exceeded their workspace limits. All available checked-in files under experiments719/723/724/725/727/728 are copied with commit and SHA256 provenance; ignored local execution logs described by those READMEs are absent from this checkout. — [724 notes](https://github.com/link-assistant/router/blob/f556c81127c5cda35de7b7ca2a4f4fb09e119543/experiments/issue-724/README.md); [725 notes](https://github.com/link-assistant/router/blob/f556c81127c5cda35de7b7ca2a4f4fb09e119543/experiments/issue-725/README.md); [727 notes](https://github.com/link-assistant/router/blob/f556c81127c5cda35de7b7ca2a4f4fb09e119543/experiments/issue-727/README.md); [728 notes](https://github.com/link-assistant/router/blob/f556c81127c5cda35de7b7ca2a4f4fb09e119543/experiments/issue-728/README.md).

### Inferences
- Compiler memory reduction, Docker-daemon resilience and snapshot storage admission are three separate corrective actions. Reducing Rust compilation can reduce the Cargo-cache component but does not alone correct stale OOM attribution or concurrent full-layer snapshot copies. — [2889](https://github.com/link-assistant/hive-mind/issues/2889); [2892](https://github.com/link-assistant/hive-mind/issues/2892).

### Gaps
- The quoted RSS, kernel child-kill counts,52→2GB disk change and writable-layer sizes are self-reported incident evidence. They must not be labeled independently measured by this research.
- Original host journal exports, timestamped cgroup `memory.events`/peak series, `docker diff` concurrency traces and per-task disk histories are not supplied by the captured sources. Future measurement should preserve these alongside command, PID/process-group, container ID, revision and monotonic timestamps.
