# Authentic translation sources and shared JavaScript-first gates

## Which Rust → meta → JavaScript/TypeScript path actually exists?

### Takeaway
The best demonstrated explicit intermediate path for a bounded pure fragment is formal-ai's JavaScript-hosted Rust parser → its portable-pure-v1 Links Notation IR → JavaScript emitter; the baseline emitter provides JSDoc rather than typed TypeScript. For wider supported constructs, meta-language PR201 supplies a genuine lossless parser/links/self-translation implementation and native portable-core emission, but neither source provides a complete Router conversion. Unsupported constructs must block readiness rather than count as translated behavior.

### Cited Findings
- meta-language PR201 was open at capture, head `e46e196db5ec34bf13a73b8645aa38d409737e60`, base `eb0574d5528babd3b4aadece81590d8e2230b99b`. Its body explicitly retains incomplete full-language translation and zero-carried delivery obligations. This is a research pin, not an assertion that the PR is merged or released. — [PR201](https://github.com/link-foundation/meta-language/pull/201), raw `meta-language/pr-201.json`.
- `translateProgram(source, sourceLanguage, targetLanguage)` dispatches the Rust/JavaScript/Lean/Rocq frontend, type checker and target emitter. A `TranslationError` becomes a reversible envelope with a named diagnostic; this is not executable semantic translation. Native output separately exposes semantics, encodings, assumptions, obligations and provenance. — [implementation](https://github.com/link-foundation/meta-language/blob/e46e196db5ec34bf13a73b8645aa38d409737e60/js/src/program-translation.js).
- `selfTranslate(source, from, to, options)` accepts JavaScript, TypeScript and Rust; `selfTranslationSignatures` exposes checked imported signatures. It records each item as translated, carried, comment or restored. Carried items are source comments; unchanged reverse translation can restore even those byte-for-byte, so a lossless roundtrip alone cannot certify behavior. Dependencies may be supplied via the imports option and export signatures. — [implementation](https://github.com/link-foundation/meta-language/blob/e46e196db5ec34bf13a73b8645aa38d409737e60/js/src/self-translation.js), [contract](https://github.com/link-foundation/meta-language/blob/e46e196db5ec34bf13a73b8645aa38d409737e60/docs/self-translation.md).
- meta-language has actual generated `frontend_rules.rs` integration with a regenerate-and-diff command, rather than claiming its entire Rust implementation is generated. Its full self-translation report measures generated output against handwritten Rust. — [generation documentation](https://github.com/link-foundation/meta-language/blob/e46e196db5ec34bf13a73b8645aa38d409737e60/docs/self-translation.md), [generator](https://github.com/link-foundation/meta-language/blob/e46e196db5ec34bf13a73b8645aa38d409737e60/js/scripts/generate-frontend-rules.mjs).
- formal-ai PR1188 pin `e9f057c8300cab787f746afbcc0133cef80e2948` includes `scripts/self-translate.mjs --to meta FILE`, `--from meta --to rust FILE.lino`, and reversible JavaScript/Rust self translation. The explicit IR path uses `toMeta`, `fromMeta`, `fromLino`; frontends and emitters are shared implementation modules. — [CLI](https://github.com/link-assistant/formal-ai/blob/e9f057c8300cab787f746afbcc0133cef80e2948/scripts/self-translate.mjs), [envelope/IR bridge](https://github.com/link-assistant/formal-ai/blob/e9f057c8300cab787f746afbcc0133cef80e2948/scripts/self-translation/envelope.mjs), [IR](https://github.com/link-assistant/formal-ai/blob/e9f057c8300cab787f746afbcc0133cef80e2948/scripts/self-translation/ir.mjs).
- Its `parseRustItem(tokens)` reads a bounded set of typed functions and constants and explicitly refuses generic functions, unsupported statements, methods, macros and literals. `emitJavaScript(item)` emits JavaScript with JSDoc types. The five copied baseline implementations were byte-compared against public PR1188 source and match exactly; cite the accessible public pin rather than the unavailable local baseline revision. — [Rust frontend](https://github.com/link-assistant/formal-ai/blob/e9f057c8300cab787f746afbcc0133cef80e2948/scripts/self-translation/frontends.mjs), [JavaScript emitter](https://github.com/link-assistant/formal-ai/blob/e9f057c8300cab787f746afbcc0133cef80e2948/scripts/self-translation/emitters.mjs).

Its actual upstream pin is `eb0574d5528babd3b4aadece81590d8e2230b99b`, which differs from PR201's head. These numbers describe its recorded scoped census and do not establish whole-project parity. — [ledger](https://github.com/link-assistant/formal-ai/blob/e9f057c8300cab787f746afbcc0133cef80e2948/data/meta/js-rust-translation.lino).
- `translate-js-rust.mjs` scopes only `js/agentic/crate/*.mjs` and `js/worker/formal_ai_worker_meta_*.js`; `--verify` checks source/projection hashes without downloading upstream, `--check` retranslates, optional `--compile` compiles fixtures and executes call observations, and `--write` rejects regression. This is useful orchestration, not an unrestricted compiler. — [orchestrator](https://github.com/link-assistant/formal-ai/blob/e9f057c8300cab787f746afbcc0133cef80e2948/scripts/translate-js-rust.mjs).
- RML PR184 pin `9b509ec0f4f3554b234a275bbd21f4c540995243` consumes official meta-language1.0.0 source `a79782093cae3b33606483ac9f3e1d05faf36de0` and exact crates.io `=1.0.0`; its wrapper reexports upstream contracts and retains refusal/assumption boundaries. It does not consume PR201 simply because its PR number is184. — [source integration](https://github.com/link-foundation/relative-meta-logic/blob/9b509ec0f4f3554b234a275bbd21f4c540995243/docs/UPSTREAM_LANGUAGE_SOURCE.md).
- RML's separate portable-natural translator exercises12 directed JavaScript/Rust/Lean/Rocq target pairs with bounded natural-number observations; the general translation-obligation API explicitly does not claim12 general translators or preservation of Rust ownership/effects. — [integration limits](https://github.com/link-foundation/relative-meta-logic/blob/9b509ec0f4f3554b234a275bbd21f4c540995243/docs/case-studies/issue-183/meta-language-integration.md), [bounded translator](https://github.com/link-foundation/relative-meta-logic/blob/9b509ec0f4f3554b234a275bbd21f4c540995243/docs/case-studies/issue-183/portable-natural-translation.md).

### Inferences
- Use the portable formal-ai path to demonstrate real Rust parsing, explicit IR, JavaScript output and meaningful native observations, then retain unsupported Router modules as blockers. Add a typed TypeScript emitter as an explicit new adapter and validate its generated types; do not describe JSDoc output as an existing TS backend.
- Use meta-language's own pinned parser/selfTranslate for expanding coverage because it carries structured diagnostics/import-signature support. Keep the source SHAs for formal-ai and RML's different upstream revisions distinct.
- A complete production source path needs every Router public interface, asynchronous/network behavior, state/persistence contract and deploy path in a feature inventory, native JS execution first, pinned deterministic JS→Rust generation and complete reverse/parity checks. Evidence here supports construction of that path, not its present completion.

### Gaps
- Whole Router translation/ownership/async/network/dependency behavior is not demonstrated by these pinned implementations; no fabricated success or estimated completion percentage is supplied.
- The recursive formal-ai tree response was truncated, so it was supplemented by exact contents fetches for all cited implementation files. First-page PR files lists are not claimed as complete diffs.

## What authoritative CI and Cargo facts constrain the design?

### Takeaway
Same-workflow `needs` on a successful native JS prerequisite gives a clear dependency; a separate workflow_run requires explicit source result/revision/trust handling. Bound expensive builds and keep publication writers uncancelled; share compatible caches without promising reuse across incompatible build configurations.

### Cited Findings
- GitHub requires needs dependencies to succeed; failed/skipped prerequisites propagate skipping unless a conditional continues execution. `always()` is appropriate for an aggregate reporter that inspects results, not permission to run Rust after a failed gate. Path-skipped workflows can leave required checks pending. — [workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idneeds).
- workflow_run triggers independent of upstream success; its ordinary GITHUB_SHA is the default-branch tip. It can gain secrets/write tokens even after an unprivileged run, so check conclusion and source head SHA/repository/event/artifact trust before executing code. Prefer reusable workflows under the original trigger for straightforward same-revision dependencies. — [workflow_run](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run).
- A concurrency group admits one active run; default pending replacement still happens with cancellation of active work disabled. `cancel-in-progress:true` explicitly cancels active runs. Use one shared repository writer group with false for releases/deploys/tags, separate job/matrix groups for replaceable read-only checks. `queue:max` is available but incompatible with true; it is optional to the required writer policy. — [concurrency documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency).
- Cargo supports a common CARGO_TARGET_DIR/--target-dir; dev/test and release/bench artifacts occupy different profile directories, cross-target outputs separate by triple, and --target changes host build-script/proc-macro sharing. The Cargo book also describes sccache as cross-workspace compiled dependency sharing. Cache reuse therefore requires compatible toolchain, flags, features, profile and target; simply sharing a directory cannot erase incompatible compilations. — [Cargo build cache](https://doc.rust-lang.org/cargo/reference/build-cache.html).

### Inferences
- A read-only cancellation policy must not encompass release-writing jobs at workflow scope. Avoid top-level cancel:true when the same workflow includes publishing.
- Gate all paths that compile Rust, including test/coverage/container/setup smoke tools, not only the named main build job. Caller checks need explicit strict refusal/missing-feature semantics.
- Bounded local JS validation and exact-revision coordinator checks can prevent repeated expensive Rust rebuilds while remote CI remains the eventual full validation authority. Budget or disk limits justify reporting blocked readiness, never relabelling incomplete tests as green.

### Gaps
- Disk/CI savings are not quantified by this source audit; parent experiments must supply measured runtime/cache evidence.
