## Native JS draft test repairs (Node 20, `npm run native:test --prefix js`)
These six draft tests fail at the pre-merge HEAD too (checked in a separate worktree); they
were never run when drafted. Fixes keep each original assertion's intent; one expectation
was corrected to match the Rust behavior.
- native-client-launch-draft: the fixture core now implements `withConfig`; operations.mjs
  refuses a core without it when cwd/env are injected. At the dispatcher, `with` data is now
  projected to the exact with.v1 contract `{client_exit_code, stdout, stderr}`, on success and
  on a nonzero exit. The direct `executeNativeWith` result keeps `signal`/`output`.
- native-client-launch-plan-draft: for `claude --model=chosen hello` on a terminal, the test
  expected `--print`. rust/src/client_launch.rs:56-73 (`carries_a_prompt`) only checks the first
  forwarded argument, so a leading flag means a session. The expectation now matches Rust,
  and a new non-terminal case asserts that `--print` is added.
- native-client-remote-health-draft: `sendRemoteManagement` ignored a signal that was already
  aborted, because `Promise.race([promise, aborted])` picks the input listed first when both are
  settled, and an injected fetch had already settled. It now rejects before fetch, and in-flight
  races list `aborted` first. Effect: no management token was minted after cancellation.
- native-client-persistent-draft:

    The semantic parse normalizes CRLF to LF; source edits keep the original bytes.

    deletions separated only by spaces/tabs now merge, and a run ending at `}` also drops its
    leading comma.
  - Paired TS: 8 `--strict` errors in ts/src. `fail` is now a function declaration so
    TypeScript narrows on it, explicit `string` params were added, and null was coalesced
    for `includes`/`credential`. The CRLF and comma fixes are mirrored in ts/src/client-toml-cst.ts.
