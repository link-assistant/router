# Online research (issue 648)

| Topic | Source | What it established | How it was used |
| --- | --- | --- | --- |
| `ubuntu-latest` → Ubuntu 26.04 | [actions/runner-images#14748](https://github.com/actions/runner-images/issues/14748); GitHub changelog 2026-09-17 | The label migrates between 2026-10-19 and 2026-11-19. Every job on the alias prints a notice (29 of the 48 annotations in run 36764352534, at `.github:1`). | All `ubuntu-latest` runners are pinned to `ubuntu-24.04`. `scripts/check-release-workflow.rs` rejects `-latest` aliases in every workflow. |
| macOS label | Runner image names in the downloaded logs (`macos-latest` → `macos-26-arm64`) | `macos-latest` already resolves to macOS 26. | Pinned to `macos-26`, so nothing changes now and future moves are explicit. |
| Fresh runner per job | GitHub Docs, "About GitHub-hosted runners": each job runs in a fresh VM | Tools installed in one job are absent in the next. | Root cause 1. New per-job check `scripts/check-workflow-tools.rs`. |
| Cargo's own warnings | [rust-lang/cargo#8424](https://github.com/rust-lang/cargo/issues/8424); [cargo `warning_override` tests](https://rust.googlesource.com/rust-lang/cargo/+/HEAD/tests/testsuite/warning_override.rs) | `RUSTFLAGS=-Dwarnings` and Cargo's `build.warnings = "deny"` deny **rustc lint** warnings only. Cargo's hard warnings (manifest, "multiple build targets") never fail a build. No upstream option exists yet, and #8424 already tracks it. | Lint now greps `cargo check` output for `^warning` and fails. No new upstream report, because #8424 covers it. |
| Template injection | zizmor `template-injection` audit; GitHub Docs, "Security hardening for GitHub Actions → Understanding the risk of script injections" | `${{ github.event.inputs.* }}` inside `run:` is substituted before the shell parses it. | Inputs move to `env:` and are quoted. zizmor 1.30.1 high findings went from 4 to 0. |
| Secret scope | GitHub Docs, "Using secrets in GitHub Actions" (a workflow `env:` reaches every job) | The run 36764352534 log shows `CARGO_REGISTRY_TOKEN: ***` in the env of jobs that never publish (e.g. Dependency Audit). | Token set only on the two publish steps. A check rejects a workflow-level token. |
| `always()` and cancellation | GitHub Docs, "Status check functions": `always()` runs even when the run is cancelled; `!cancelled()` does not | Job-level `always()` kept test and coverage jobs running after a cancel. | `always() && !cancelled()`. A check enforces this at job level. |
| Concurrency for scheduled runs | GitHub Docs, "Control the concurrency of workflows and jobs" | Without a group, hourly runs can overlap. | `concurrency:` groups with `cancel-in-progress: false` on delivery and verify-releases. |
| Existing linters | [actionlint](https://github.com/rhysd/actionlint) 1.7.12, [zizmor](https://github.com/zizmorcore/zizmor) 1.30.1 | Both run locally (logs in `ci-logs/`). Neither models "tool used in a job that never installed it": actionlint checks syntax, expressions and shellcheck, and zizmor checks security. | A dedicated per-job check is the gap filler. |
| Installing tools | [taiki-e/install-action](https://github.com/taiki-e/install-action), [cargo-binstall](https://github.com/cargo-bins/cargo-binstall) | Prebuilt binaries install in seconds, and `tool:` lists are declarative. | The check recognises `tool:` lists. Moving router to install-action is a possible follow-up; current `cargo install --locked --version` pins work. |
| cargo-audit strictness | cargo-audit `--deny warnings`, `.cargo/audit.toml` `[output] deny = ["warnings"]` | Router already denies warnings through config (asserted by `tests/release_workflow_test.rs::dependency_audit_fails_on_warnings`). `cargo audit` 0.22.2 is clean (`ci-logs/local-cargo-audit-0.22.2-deny-warnings.log`). | No change needed. |
