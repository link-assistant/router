# Implementation options

The [requirement matrix](README.md#requirements-and-evidence) records the selected work and its evidence. The choices below also cover alternatives that can unblock remaining checks or simplify a later update.

| Requirement | Options and implementation plan |
| --- | --- |
| Reproduce and repair the six merged updates | Diagnose the failing job at its original SHA and repair the consumer against the new interface. Reverting the dependency merge would recover the old interface at the cost of losing the requested updates. Keep the new interfaces and reproduce the old failure with focused issuer, terminal, storage, fixture, and workflow cases. |
| Supersede all seven action changes in #790 | Apply matching revisions or resolve fresh upstream release tags. Resolve each action's full commit from the publisher, retain the reusable-workflow gate and artifact commands, and list #790 in the PR. Close the old PR after the updated pins are on the default branch. |
| Find every ecosystem and record registry versions | Start with the Git tree, read manifest and lockfile records, and expand plugin realms, workflow-installed tools, and image package inventories. Registry and release APIs provide a dated candidate version. An SBOM provides a cross-check for the resolved build. Match each result to a repository path or build stage and record any upstream constraint that retains an older version. |
| Bring active manifests and transitive locks up to date | Apply compatible updates with ecosystem resolvers. Use npm-check-updates and cargo-edit to identify incompatible changes and review those manifest changes with their callers. Use the existing JavaScript gate before hosted Cargo resolution. For generated clients, verify the committed Maven, Go, and Composer fixtures against a fresh generator run. [npm-check-updates](https://github.com/raineorshine/npm-check-updates), [cargo-edit](https://github.com/killercup/cargo-edit), [uv locking](https://docs.astral.sh/uv/concepts/projects/sync/). |
| Cross major versions and adopt upstream features | Use the publisher's migration guidance and trace each changed API through its application entry point. Consolidate the duplicate JWT signing and decoding adapters into a raw RustCrypto HMAC implementation and use the safe mapped-file reopen API. For TypeScript, qualify the new public compiler independently. The private translator can retain the legacy API or migrate through Microsoft's TypeScript 6 compatibility package after compiler-host qualification. [Migrations](migrations.md). |
| Align constraints, pins, and toolchains | Resolve shared active pins once and use the resulting values throughout builds and tests. Keep a compatibility matrix where minimum supported consumers or an upstream platform regression require a distinct runtime. Verify floors against actual feature requirements and test supported versions. Preserve the provenance of recorded requests and historical incident snapshots. [Retained versions](scope.md). |
| Align the Rust packaging toolchain | Update the official slim-trixie digest and the existing overlay manifest after their publishers ship the patch. An extra Rustup install in the builder could use the current compiler before the base image is republished and would add a second distribution step to the image build. Fenix can pin the official channel manifest by hash and cover Nix packaging before rust-overlay updates. That would replace the existing flake's toolchain provider and need fresh verification on all four advertised platforms. [Official Rust manifest](https://static.rust-lang.org/dist/channel-rust-1.100.1.toml), [Fenix toolchain API](https://github.com/nix-community/fenix/blob/main/README.md#L174-L197). |
| Keep automation current | Add real active install roots to the existing Dependabot configuration and retain the reviewed groups. Renovate supports custom managers for version pins embedded in verified shell or workflow logic. Introducing it would add a second updater, so leave the custom pins in the registry-backed inventory while Dependabot covers its supported roots. [Dependabot ecosystem support](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories), [Renovate custom managers](https://docs.renovatebot.com/modules/manager/regex/). |
| Verify builds, suites, lint, and performance | Preserve the four JavaScript stages and run complete Rust verification on the same candidate in hosted CI. Compile the exact PR base for the mandated benchmark and preserve both results. Until the base builds, a separate comparison against its buildable parent gives a performance reference. For a changed compiler coverage metric, measure the full parent and candidate suites with the same instrumenter before deciding whether tests or a reviewed baseline recalibration are needed. [Hosted evidence](ci.md). |
| Clear advisories in the shipped and build graphs | Prefer patched releases selected by the native resolver and verify the installed tree. Where the top-level release pins an old transitive graph, a checksum-verified source archive with a refreshed lock can apply compatible fixes. When a stable distribution or publisher has no compatible fixes, assess reachability, record each advisory, and confirm any replacement preserves the runtime or tool's supported behavior. The Maven Site Plugin fix is already merged upstream and requires a release. [Advisory evidence](ci.md#cargo-tool-advisories), [Maven replacement](https://github.com/apache/maven-site-plugin/pull/1303). |
| Report dependency defects and remove local duplication | Search the upstream tracker and add a narrow reproducer to an existing report where possible. Create a report when the defect is distinct. Retain required workarounds until an upstream release passes the same regression, then remove them alongside the pin update. [Upstream reports](migrations.md). |
| Deliver the refresh in PR #811 | Keep earlier repair and resolver commits reviewable, retain the release fragment and the closing reference, and verify the current default ancestry. Review the final tree and every same-SHA check. An external advisory fix or a broken comparison base stays open until the corresponding acceptance criterion has evidence. |
