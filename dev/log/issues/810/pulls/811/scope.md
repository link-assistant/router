# Dependency scope and retained versions

The starting manifest scan used the tracked Git tree. In addition to the issue listing, it found the npm projects under `js`, `ts`, `ui`, and `scripts/ci`, the PyPI package under `packages/python`, the `rust/fuzz` Cargo workspace, standalone Rust experiments, and the Nix flake. Go, Java and PHP client material uses generated fixtures and downstream tooling. The scan found no consumer-owned `go.mod`, Maven or Gradle build, or `composer.json`. Terraform and Helm manifests were also absent.

The captured Proxypal input for issue #37 and the captured test-sharder incident for issue #759 are provenance records. Updating their copied dependencies would change the historical inputs. The active sharder is under `experiments/issue-725/test-sharder`. The standalone `experiments/issue-372` pins earlier versions to reproduce the behavior being investigated. The failing deployment candidate takes its base image from the accompanying Router e2e test and deliberately implements only a health check. The npm and Cargo inventories include the captures they scanned so their historical pins can be traced to paths.

The npm registry `latest` tag for `@iarna/toml` is 2.2.5. Both Router implementations intentionally use the publisher's newer 3.0.0 TOML 1.0 release, distributed under the `toml-1.0.0-rc.1` tag. Retaining 3.0.0 preserves the parser semantics used by the current sources. [Publisher dist-tags](https://registry.npmjs.org/-/package/@iarna%2ftoml/dist-tags).

The Node 20 and 24 jobs exercise supported consumers. The active TypeScript stage and native profile source check also use Node 20.20.2, whose named `util.types.isProxy` matches the private compiler's source-integrity checks. The tested Node 22, 24 and 26 releases expose an anonymous native function. Node 26.13.1 serves the other three JavaScript stages and release tooling. Active Node 24 and 26 jobs use npm 12.2.3. Node 20 jobs use npm 11.21.3, the latest CLI release whose supported runtime includes Node 20. TypeScript 5.9.3 supplies the JavaScript compiler API used by the translation profiles. The public declarations use TypeScript 7.0.2. [node binding report](https://github.com/nodejs/node/issues/67826), [npm 12.2.3 metadata](https://registry.npmjs.org/npm/12.2.3), [npm 11.21.3 metadata](https://registry.npmjs.org/npm/11.21.3), [TypeScript API transition](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).

The Python package continues to support 3.10. Only the audit tool group needs 3.11 and later. Restricting that group allowed uv to resolve a patched `filelock` across the audit environments. The Python build tool requires `importlib-metadata` only before CPython 3.10.2, and the latest release requires Python 3.11. The universal lock also retains `rpds-py` 0.30.0 for Python 3.10 because the current release requires Python 3.11. The Go checksum file records older `github.com/kr/pretty` and `github.com/kr/text` as the validator's upstream test dependencies. The client build graph uses neither. Composer locks `ergebnis/agent-detector` to the 2.x range required by PHP CS Fixer. The Java probe uses a checked-in Maven manifest alongside the Go and PHP manifests so Dependabot can track all three. [Python registry inventory](python.tsv), [generated client inventory](generated-clients.tsv).

The npm and Cargo lockfiles retain transitive releases within their parents' published requirements. For example, Chakra UI pins its Ark UI release exactly, Emotion still uses Babel 7, and Lino Objects Codec depends on the Links Notation 0.31 series while Router and link-cli use 0.32. The per-install inventories record each parent requirement that prevents resolving the latest registry release. [npm retained versions](npm-retained.tsv), [Cargo retained versions](cargo-retained.tsv).

The real-client inventory covers the installed Linux x64 graph and declared optional platform packages. The package publishers own their embedded binaries and exact dependency pins, such as Qwen's Bun and Gemini's native keychain addon. Frozen OAuth request fixtures and the associated fallback identities retain the versions recorded with their request data. The real-client workflow installs newer vendor binaries independently. The refresh contract checks exact captured identities and requires the workflow's pinned installs to be at least as recent as the captures. [Real-client inventory](real-clients.tsv), [Gemini native addon report](https://github.com/google-gemini/gemini-cli/issues/30285#issuecomment-7220830037).

The isolated Linux verifier uses the same Node 26.13.1 and npm 12.2.3 pins as the hosted vendor checks where Node publishes a binary. It verifies the publisher's SHA-256 before extracting and approves the two vendor lifecycle scripts it needs. The Linux x64 archive verified and the pinned npm installed in a temporary prefix. The Rust base also ships for armv7, 386, and riscv64, so the verifier retains Debian's Node packages and uses npm 11.21.3 on those architectures. The full verifier still requires Docker, the hosted Rust test path and the selected account credentials. [Node release checksums](https://nodejs.org/dist/v26.13.1/SHASUMS256.txt), [Debian Node package](https://packages.debian.org/trixie/nodejs).

The archived strict CI lane remains suspended under the maintainer instruction in #785. Its old fixed-gate source inventory and neutral compiler profiles need a separate qualification against the currently retained sharded workflow. Changes here keep the original stage partitions and commands. Dynamic Debian and Alpine packages continue to come from the pinned distributions' supported repositories so the image build receives their security updates.

Intel macOS uses the final Nix release series with an official installer and the maintained Nixpkgs 26.05 Darwin channel. The current Nix 2.36 installer and Nixpkgs unstable dropped native Intel macOS support. Both Linux architectures and Apple Silicon use the current Nix release and unstable channel. [Upstream removal](https://github.com/NixOS/nix/pull/16293), [26.05 Darwin platform list](https://github.com/NixOS/nixpkgs/blob/b79fb186802610f5363769394ba4a4b921ea15c9/lib/systems/flake-systems.nix).

Rust 1.100.1 became the current stable release during verification on 2026-11-27. The distribution manifest marks rustc, Cargo, rustfmt, Clippy and LLVM tools available on the hosted Linux, macOS and Windows targets, and the hosted workflows use 1.100.1. The latest official slim-trixie Rust image and the locked rust-overlay still provided 1.100.0 at the tooling inventory check. Keep the minimum supported compiler at 1.100.0 for those packaging paths until their publishers make 1.100.1 available. [Rust release](https://github.com/rust-lang/rust/releases/tag/1.100.1), [official image tags](https://github.com/docker-library/official-images/blob/master/library/rust), [overlay manifests](https://github.com/oxalica/rust-overlay/tree/master/manifests/stable).
