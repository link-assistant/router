# Migrations and upstream findings

## Rust CI breakage from #809

`jsonwebtoken` 12 made its symmetric key constructors fallible to reject empty signing and verification keys. Router now passes key creation errors through the existing issuer errors. The deployment fingerprint code needs a raw HMAC that can accept arbitrary bytes, including an empty key. It now uses RustCrypto's `hmac` with `sha2`, both already part of the JWT crypto dependency tree. The local secret digest delegates to the same function and keeps its 128-bit output truncation. [JWT changelog](https://github.com/Keats/jsonwebtoken/blob/v12.0.0/CHANGELOG.md), [RustCrypto HMAC](https://docs.rs/hmac/0.13.0/hmac/).

`vt100` 0.18 accepts nonzero row and column counts. The built-in PTY size now carries that invariant in the private constants and exposes the existing public `u16` dimensions. [Parser API](https://docs.rs/vt100/0.18.1/vt100/struct.Parser.html).

`link-cli` 3.2 supplies a safe reopen API for existing mapped storage. Router now uses it and keeps the existing-length floor around the Doublets bootstrap request. The upstream bootstrap still asks the allocator to shrink an existing map before reading its persisted header. The issue includes the affected versions, source trace, a standalone source-derived reproduction, and a proposed initialization fix. [Mapped storage API](https://docs.rs/link-cli/3.2.1/link_cli/mem/struct.FileMapped.html), [Doublets #97](https://github.com/linksplatform/doublets-rs/issues/97).

The release and fixture scripts now use `ureq` 3's response body and `http` status and header APIs. The vendor fixture recorder still records bodies for error statuses and replaces duplicate outbound headers. [ureq 2-to-3 migration guide](https://github.com/algesten/ureq/blob/main/MIGRATE-2-to-3.md).

Lino Objects Codec 1.0 raised its Rust floor to 1.100.0 and retained the existing encode and decode entry points. Its optional strict decoding settings do not duplicate Router's legacy JSON routing or token-store schema checks. Links Notation 0.32 retains the public parser used by the format regressions. Syn 3 alters its AST modifier and coding APIs, while the sharder uses file parsing, item and attribute inspection, and visitor hooks that the new release still provides. [Lino Objects Codec changes](https://github.com/link-foundation/lino-objects-codec/blob/main/CHANGELOG.md), [Links Notation registry package](https://docs.rs/links-notation/0.32.0/links_notation/), [Syn 3 migration](https://github.com/dtolnay/syn/releases/tag/3.0.0).

## TypeScript

TypeScript 7 uses a native compiler and no longer exposes the JavaScript Compiler API through `typescript`. The translator depends on that API and many source profiles pin TypeScript 5.9.3. Microsoft offers `@typescript/typescript6` as a compatibility path for the legacy API. Moving the compiler host requires migrating and requalifying the affected source profiles with the new API runtime. [TypeScript 7 release and migration notes](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).

Both public declaration checks use TypeScript 7.0.2. The separately installed translator compiler retains its legacy API and exact version. The UI's Vite configuration now uses Rolldown's `codeSplitting.groups` and preserves the three groups and their load order. [Vite migration guide](https://vite.dev/guide/migration.html), [Rolldown output options](https://rolldown.rs/reference/output-options).

Node 22.23.5 and 26.13.1 return an empty string for `util.types.isProxy.name`, while Node 20.20.2 returns `isProxy`. The predicate still identifies a proxy on the newer releases. The report includes the runtime reproduction and the change from the original native registration helper to the fast-call helper. The private compiler's integrity check still requires the named binding. [Node #67826](https://github.com/nodejs/node/issues/67826).

npm 12 blocks dependency lifecycle scripts by default. The existing locked install commands still work. The client jobs approve specific launcher and optional native dependency scripts with npm's install-time policy. Gemini CLI 0.59.0 and 0.71.1 both pin deprecated `@github/keytar` 7.10.6. The newer release retains the existing credential-store behavior. The upstream report records the install and addon-load reproduction, narrow script approval and a possible replacement that preserves stored credential identities. [npm 12 migration and CLI changes](https://github.com/npm/cli/releases/tag/v12.0.0), [Gemini CLI reproduction](https://github.com/google-gemini/gemini-cli/issues/30285#issuecomment-7220830037).

Qwen Code 0.28.7 deprecates `--prompt` and supports positional input for headless sessions. The JavaScript, TypeScript and Rust launch planners now infer that form for prompts and pass through explicit `-p` and `--prompt` flags. The positional form also works with the previous 0.23.1 release. The planners recognize current vendor subcommands so their arguments remain in command mode. Existing OAuth fixtures retain the stored request identity independently of the newer CLI pins. [Qwen Code 0.28.7](https://github.com/QwenLM/qwen-code/releases/tag/v0.28.7), [Qwen command-line reference](https://qwenlm.github.io/qwen-code-docs/en/users/features/commands/).

The live capture installed Claude Code 2.1.332 and exercised routed inference. The existing launcher messages record earlier manual qualification of account features. Anthropic's current gateway guidance confirms that a gateway credential takes precedence for API requests while the saved account login stays on the host. It also documents that a non-Anthropic API endpoint prevents Remote Control from starting even with an eligible account. The inference capture provides evidence for the new installation pin. The vendor account features retain their existing qualification record. [Gateway authentication and billing](https://code.claude.com/docs/en/llm-gateway#billing-and-usage), [Remote Control requirements](https://code.claude.com/docs/en/remote-control#requirements), [hosted capture](https://github.com/link-assistant/router/actions/runs/46051595091).

## Generated HTTP clients

The Go probe uses a committed module and checks that `go mod tidy` would produce the same files. The PHP probe uses a committed Composer lock, PHPUnit 13, Guzzle 8, and PSR-7 3, with a PHP 8.5 minimum. Guzzle 8 applies stricter transport option types and the probe exercises the generated callers using those options. Java targets the Java 17 API for JUnit 6, uses the JVM OkHttp artifact, and generates Jakarta imports. Its Maven fixture records the dependency and plugin pins while preserving the generated artifact version from the API specification. [Generator v7.28.0](https://github.com/OpenAPITools/openapi-generator/releases/tag/v7.28.0), [Guzzle 8 migration](https://github.com/guzzle/guzzle/releases/tag/8.0.0), [JUnit 6 migration guide](https://docs.junit.org/current/user-guide/#migrating-from-junit5), [PHPUnit 13 migration guide](https://phpunit.de/announcements/phpunit-13.html), [OkHttp Maven usage](https://square.github.io/okhttp/).

OpenAPI Generator 7.28.0 emits the pre-5 OkHttp coordinate for Java `okhttp-gson` and a JUnit 4 bridge alongside the Jupiter tests. The reports include a one-operation OpenAPI input, the generation command, the affected Maven dependencies and the POM workaround checked here. The recently added generic `okhttp` generator library already uses `okhttp-jvm` but also emits the JUnit bridge. [OkHttp Maven report](https://github.com/OpenAPITools/openapi-generator/issues/25852), [JUnit configuration report](https://github.com/OpenAPITools/openapi-generator/issues/16352#issuecomment-7220001535), [generic generator](https://github.com/OpenAPITools/openapi-generator/pull/25713).

Both Java OkHttp generator libraries emit two `JsonReader.setLenient(true)` calls. In Gson 2.15.0 that setter is deprecated in favor of `setStrictness(Strictness.LENIENT)`, which preserves the same behavior. The generator preparation step updates both overloads and checks the number of old call sites. The Java regression parses a comment and a single-quoted string through both overloads. [Gson implementation](https://github.com/google/gson/blob/gson-parent-2.15.0/gson/src/main/java/com/google/gson/stream/JsonReader.java#L328-L346), [OpenAPI Generator #25853](https://github.com/OpenAPITools/openapi-generator/issues/25853).

## Available tooling

Cargo and npm can refresh transitive versions within existing constraints. Major versions require manifest and caller updates. uv produces a universal Python lock. The repository uses Dependabot for npm, Cargo, uv, Docker, GitHub Actions, pre-commit, Go, Maven, Composer and Nix. Renovate also supports flake inputs and can extract custom pins. [Dependabot ecosystem support](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories), [Renovate Nix manager](https://docs.renovatebot.com/modules/manager/nix/).
