The route census checks 368 canonical method/path pairs against the configured native handler. `native-route-outcomes.json` is an explicit expected-outcome table, not an output snapshot or a parity certificate. Every row declares `fullParity: false`. The inventory must match `openapi/router.yaml` exactly; a new method/path needs a reviewed table entry and assertions.

Each case creates a real in-memory RouterCore with a private temporary data directory, isolated home, one OpenAI-compatible stored provider named `fixture`, exact model `fixture-model`, and declared Claude/Codex/Gemini/Qwen client support. Management uses `token_admin_key` and a loopback socket peer. Inference uses a newly issued client/principal/account-bound JWT; Codex backend and identity requests use the paired `at-` form. The provider secret is distinct from every Router credential. There are no subscription credentials, GitHub credentials, emergency opt-in, renewable wrapper leases, retained resource IDs, or optional management hooks. Real private request logging is installed; error capture is disabled.

The upstream fixture requires HTTP 426 for ordinary GET requests to WebSocket endpoints. The census verifies that native forwarding preserves this rejection; separate WebSocket fixtures verify upgrades. OpenAI response-ID cases explicitly use the local foreground Responses fixture store with the actual JWT owner. They do not certify durable native Responses retrieval or cross-process recovery.

`success` means the declared scenario returned a verified 2xx handler outcome. `observed`, `status`, `contract`, `upstreamVerified`, `bodyVerified`, and `headBodyEmpty` retain the distinction between an observed configured handler contract and deeper behavioral coverage. Missing providers, rejected inputs, and unimplemented hooks remain explicit. Full endpoint behavior requires additional independent fixtures before any full parity promotion.
