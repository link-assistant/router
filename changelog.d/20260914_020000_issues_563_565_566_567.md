### Fixed
- `router with claude` now targets the model the provider is currently advertising. The gateway fallback took the first entry in catalog order, so a deployment advertising ten z.ai models pinned the oldest one the provider happened to list first — for both the main and the subagent slot — while offering a picker whose newest row was the current model. Selection now ranks on the vendor's own `created` timestamp with the model id as a deterministic tie-break, so the result never depends on array position (issue #563).
- A model Router pins is a fallback, never an override. `/model` is the documented way to choose a model, and a wrapper-set `ANTHROPIC_MODEL` outranked the client's own selection for every new session. Both ways of having already chosen now suppress the pin — a value in the environment, and a default Claude Code saved in the profile it reads — and Router prints which choice it is deferring to instead of silently standing aside (issue #563).

### Changed
- Claude client capability is resolved per model instead of per catalog owner. A single value for a whole provider made any per-model difference unrepresentable rather than merely unset. The owner still selects which reviewed adapter contract applies and no model id is enumerated, so the live catalog keeps owning the inventory (issues #565, #546).

### Added
- Conversation record and replay. An opt-in mode captures complete client exchanges — request and response bodies, ordered streamed events, thinking blocks, signatures, tool calls and results — as links notation, and a replay mode serves them back in order, failing loudly and naming the turn and the difference when an incoming request does not match the recorded one. Replay needs no provider credential and makes no upstream call, so a whole conversation can be proven in CI without spending tokens. Credentials are redacted at record time, and a recording states the Router version and provider that produced it (issue #566).
- Named test tiers, documented in `docs/testing-tiers.md`, with the live credentialed tier runnable on demand. Every live-tier skip now announces itself with the tier, the test and the variable that would enable it, so a passing run can no longer be mistaken for a run that proved those properties; `tiers::skipped_live_tests()` exposes the count. The credentialed tier moved out of the pull-request workflow into a dispatch-only `live-tier.yml`, because on a fork it either failed for want of a secret or silently proved nothing while looking green (issue #567).

### Fixed
- A live-tier test asserted on a request log key that `with` never writes to, because `with` mints its own client-bound run credential. It failed for a reason unrelated to the property under test, and only a machine holding credentials could see it — which is the blindness the tier work addresses (issue #567).
