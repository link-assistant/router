### Added
- Upstream requests now have a connect timeout (`UPSTREAM_CONNECT_TIMEOUT_SECS`, default 10 s), an optional first-byte timeout (`UPSTREAM_FIRST_BYTE_TIMEOUT_SECS`) and an idle-read timeout (`UPSTREAM_IDLE_TIMEOUT_SECS`, alias of `UPSTREAM_READ_TIMEOUT_SECS`). `0` disables a bound (#669).
- API-key provider base URLs are checked against loopback, private, link-local and metadata addresses when they are configured, when they are used, and again when their host name is resolved, so a DNS rebind cannot reach an internal address. Local setups opt in with `UPSTREAM_ALLOW_PRIVATE_NETWORKS=loopback,private,link-local` or `all` (#669). Processes that embed Router can install the policy with `upstream_guard::install_process_policy` instead of setting the variable.
- Fuzz targets for every SSE stream translator and every public request translator (`fuzz/`, run with `cargo +nightly fuzz`), a `Fuzz` workflow that runs them briefly on pull requests and longer nightly, and a stable test that replays the checked-in corpus (#670).
- Property tests: re-chunking a valid upstream stream at arbitrary points (CRLF, `:` comments and pings, multi-line `data:`, split UTF-8) yields the same translated output; tool calls and cache breakpoints round-trip across Anthropic, Chat and Gemini; and translating a longer conversation keeps the earlier translated turns byte-identical, so the vendor prompt cache keeps hitting (#670, #671).
- Opt-in pool failover (`POOL_FAILOVER=pre-first-byte`, `POOL_FAILOVER_MAX_ATTEMPTS`, `POOL_FAILOVER_BUDGET_SECS`): a pooled Claude request that gets a 429, 529, retryable 5xx, transport error or 401 before its first byte is retried on the next account under the same correlation id and billed once. Sessions detour while their account cools down and return afterwards, concurrent failovers spread across the pool, pinned tokens never fall back, a disconnected client stops the retries, and signed thinking blocks are dropped when the account changes (#676).
- Pool failover also covers the Codex subscription path, under the same policy; a retry that switches accounts drops `reasoning` items carrying `encrypted_content`, which only the issuing account can decrypt (#676).
- Vendor rate-limit state: `anthropic-ratelimit-unified-*` headers (from `count_tokens` too) set cooldowns until the window resets, the longest window winning, and a model-family rejection cools only that family. `ACCOUNT_PAUSE_AT_PERCENT` pauses an account at a utilization threshold, `POST /api/management/accounts/{name}/pause` and `/resume` pause and resume it by hand, and `INTERCEPT_WARMUP` answers Claude Code's warmup probe locally. The state appears in the accounts API, `accounts list --json`, `usage`, `doctor`, `deploy --status` and `/metrics` (#677).
- `router accounts pause <name> [--reason ..] [--until ..]` and `router accounts resume <name>` pause and resume a pooled account through the selected router's admin API, or in the local data directory with `--local`; `--until` takes Unix seconds, an RFC 3339 time or a delay such as `6h` (#677).

- Each pooled account now sends with its own HTTP client — its own connection pool and, on canonical Codex, its own Cloudflare cookie store — on the Anthropic and Codex pool paths, including its token refreshes. Idle connections close after `ACCOUNT_POOL_IDLE_TIMEOUT_SECS` (default 90 s) and an account's client is replaced after `ACCOUNT_CONNECTION_MAX_AGE_SECS` (default 300 s), with in-flight requests finishing on the old one (#678).
- Optional per-account egress proxies (`ACCOUNT_EGRESS_PROXY`, HTTP, HTTPS or SOCKS5). Credentials come only from an environment variable or file reference, never from argv, and an unresolvable proxy fails closed instead of egressing directly (#678).
- Tests: client disconnect mid-stream closes the upstream connection and still settles the partial output; a reset after the first byte is not failed over and ends with one in-band error; vendor redirects are not followed on the API-key provider, Anthropic subscription and Codex subscription paths; a stream stalled past `UPSTREAM_IDLE_TIMEOUT_SECS` ends with one in-band error for Anthropic and OpenAI Chat clients (#668, #669); and per-account cookie, connection and proxy isolation (#678).
- `router deploy --config FILE`: one declarative TOML file (`[deploy]`, `[local]`, `[remote]`, `[env]`, `[ssh]`, `[tokens]`, `[provider_keys.NAME]`, `[verification]`) drives local, host-mode and remote deployments (`--remote` takes the server from it), with flags overriding its keys. `--instance NAME` lets several deployments share one host. `--env NAME[=env:VAR|file:PATH]` passes runtime variables by name, never via argv, with an HMAC fingerprint so a changed value reconciles. `--ssh-port`, `--ssh-identity`, `--ssh-known-hosts` (pinned, never `accept-new`), `--ssh-keepalive` and `--deadline` (exit status `12`) tune the SSH session. `--token-ttl-hours`, `--token-max-requests`, `--token-max-tokens`, `--token-rate-limit` and `--token-allowed-model` bound the client token deploy issues (#679).
- `router deploy --server ... --provider-key NAME=env:VAR|file:PATH` (repeatable) validates an API key in an isolated Router inside the candidate: the catalog must list the model and a minimal request must succeed. `--provider-key-mode keep` (default) only reports. `if-absent` installs the key when the provider is missing. `replace` installs it only after positive validation, and a negative result stops the deployment before cutover. Values travel on the SSH session's stdin, and `--json` reports a fingerprint and the validation per provider (#680).
- `router deploy --verification-profile FILE` (or `[verification]`): required clients and providers with exact models, an optional stub `router with <client>` launch, quota treated as proven only with upstream evidence, and an opt-in Claude thinking-display check via `--settings`. Candidate verification now probes the full removed-route list, checks the anonymized public `/api/usage` view, and checks that the public listener refuses the admin token for inference. `--json` adds the profile result and per-step and per-subprocess timings to a `link-assistant-router/deploy/v1` document (#683).
### Fixed
- A stream whose upstream fails after the first byte (connection reset, stall past the idle timeout, or a body that ends without its terminal event) now ends with exactly one error event in the client's own dialect. Router no longer synthesizes `message_stop`, `[DONE]` or `response.completed` for a cut turn (#668).
- A stream cut before the upstream's final usage report is charged at least an estimate of the output it streamed, instead of almost nothing (#668).
- Anthropic `cache_creation_input_tokens` and `cache_read_input_tokens` are now charged against token budgets, matching OpenAI and Gemini, whose prompt counts already include cached tokens (#671).
