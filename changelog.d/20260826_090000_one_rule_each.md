### Added
- `router configure <client>` points a client at the router permanently: one name for what used to be two commands that disagreed on the address, the credential, the reversal and the client list (issue #296). It acts on the router this machine is pointed at, mints a credential from that router and stores it outside the client's configuration at mode 0600, so the client works when the command returns. `--all` configures every client the machine has and names the ones it cannot; `--undo` restores the client's own file byte for byte and revokes the credential it minted. `with --global` is the same command under an older name and maps onto it rather than keeping a second implementation.
- `GET /health/subscriptions` answers whether the router can serve what it advertises, with a reason per degraded subscription, and `/metrics` gained a `link_assistant_subscription_healthy{provider="…"}` gauge (issue #318). A revoked subscription is now visible to a stock uptime check and to a scraper; `/health` itself is unchanged, because it drives both Kubernetes probes and a restart cannot mint an OAuth token.
- `with --local`, `--label` and `--pick-model`; `--ttl-hours` is accepted as a name for `--run-ttl-hours`. `tokens list`, `accounts list`, `providers list` and `clients list` take `--json`. `providers add` takes `--api-key-stdin`, so the one secret that could travel only through argv no longer has to. `auth clear <provider>` / `auth clear --all` give withdrawal a name; the `--clear` flags keep working. `tls` takes `--local` / `--server` like every other family. `--home` is global, like `--data-dir`.

### Fixed
- A stand-in `TOKEN_SECRET` can no longer sign or encrypt. When a command that might act on another deployment turned out to run locally, the placeholder installed for it signed real `la_sk_` tokens and encrypted vendor API keys under a value published in the source, while reporting `has_encrypted_api_key: true` (issue #300). The sentinel now begins with a NUL, so it cannot be supplied by any environment variable or command line, and signing, validating and encrypting all refuse it with the ordinary "`TOKEN_SECRET` is required" error before anything is written.
- Every spelling of "take this login away" — `auth claude --clear`, `auth gh --clear`, `auth status --clear-all` — accepted `--server`, discarded it, and deleted the credentials on the machine that ran the command, reporting success for a deployment it never contacted (issue #305). Withdrawal now refuses and names the target, and removing more than one credential at once asks first: an OAuth login cannot be put back without a browser.
- `with` no longer chooses a model or an effort level on the user's behalf. A bare launch replaced the model the user had configured with whatever sorted first in the catalog for that vendor and forced `MAX_THINKING_TOKENS=16384` or `reasoning_effort=xhigh` — the most expensive setting available, on a user who never asked and may be paying per token (issue #295). The client's own configuration decides; `--model` names one and `--pick-model` asks the router to choose and reports what it picked. Clients whose configuration embeds the catalog are still given an id, because they cannot start without one.
- A client flag no longer turns a session into a one-shot run. `router with claude --resume <id>` added `--print`, so the client was told to resume a session, answer once and exit with no prompt to answer, and its own error named neither `--print` nor the router (issue #297). A bare positional is a prompt; a flag is an option passed to a session; streams that are not a terminal are one-shot. For four clients the injected mode argument takes the prompt as its value and was placed immediately before the user's flag, which is a silent change of meaning rather than an error; and a mode the user already spelled — Claude Code's own `-p` — is no longer added a second time.
- Everything after the client name reaches the client verbatim. Twelve names were claimed back from it by no principle a user could state: `--port`, `--host` and `--managed` are router options and were forwarded, while `--model`, `--token` and `--server` are router options and were not — so `claude --model opus[1m]` was intercepted, validated against the router's catalog and aborted, and `with claude --managed` started nothing (issue #299). Router options go before the client name, and the option table is read from the parser rather than a hand-kept list.
- Clients that cannot be extended keep a profile instead of a directory thrown away after every run. For codex, gemini, opencode and agent every launch was a first launch — no session history, so the `--resume` the client prints on exit could never be used, and onboarding was answered again from scratch (issue #298). The profile lives under the router's own per-user directory rather than a shared `TMPDIR`.
- The stale-run sweep no longer deletes another user's live run. `kill(pid, 0)` fails with `EPERM` for a live process owned by somebody else, and any failure was read as "dead", so on a shared `TMPDIR` one user's `with` deleted another's working directory, client configuration and credential while in use (issue #313). Ownership is checked first and a process that exists but is not ours counts as alive.
- `with` no longer answers the client's own safety questions. Codex's git-repo guard was removed for every run the router supplied `exec` for — and left on when the user typed `exec` themselves — and Gemini's workspace-trust prompt was pre-approved even for an interactive user sitting at the terminal (issue #310).
- The working directory's name is no longer sent to the router as a token label, so a deployment stops accumulating a list of the projects its users work in (issue #316). `--label` sends something the user chose.
- Naming the server that is already selected no longer throws away the token stored for it, and the resulting error no longer recommends the command the user just ran (issue #311). The persisted token is matched by origin rather than by how the origin was spelled.
- Gemini CLI and Qwen Code were declared `OpenAI` clients, so a Google model could never be selected for the Gemini CLI and a Qwen model never for Qwen Code; on a deployment serving only a Gemini subscription the run aborted with a message reading as though the router were short of models (issue #301). `with`, `clients setup` and `clients doctor` now answer "which models suit this client" with one rule, so a client config cannot embed a model the launcher would refuse to start it on.
- `clients remove claude` restores the `ANTHROPIC_BASE_URL` the takeover replaced instead of deleting it, the way the Codex integration already restored its previous provider (issue #302). `setup` says when it is replacing a value the user set.
- One malformed client configuration no longer ends `clients list` mid-table, hiding every client after it while the error named a different one (issue #304). The row says `unreadable` and the listing runs to the end.
- `clients` outcomes match what happened: `setup grok` no longer reports that nothing changed while minting a token and writing two files, and `remove` and `--undo` refuse a client the router can never configure instead of reporting success (issue #303). Gemini's status is read rather than hardcoded to `false`.
- `clients doctor` probes at the floor instead of the ceiling. Checking that a URL answers spent a 24576-token adaptive-thinking request at `high`, or `xhigh` reasoning, on the first model in the catalog (issue #309).
- `accounts list` against a selected server prints the same columns as `--local`, including `healthy` — the one the command exists to answer — and reads numbers as numbers, which `as_str()` rendered as `-` whether the server had sent a figure or nothing at all (issue #306).
- `auth import` and the platform-store guard now agree on what "the vendor's home" means. Setting `CLAUDE_CODE_HOME`, which a deployment does to name its *destination*, stopped `~/.claude` counting as the vendor's home, so the macOS Keychain went unconsulted and a stale file could win over the live login (issue #307). The help says what is actually read.
- `tls` acted on the local machine whatever was selected, and the artefact it prints is a trust anchor — so the wrong answer was trust in the wrong key, not a wrong report (issue #308). It now takes the target flags and refuses, naming the target, until a remote form exists.

- A 403 that names a permission failure is no longer treated as a verdict about the credential, and a refresh token this process adopted moments ago is never spent again (issue #319). `oauth_not_allowed_for_organization` arrived one millisecond after a successful rotation, was folded into the same "credential looks bad → refresh" path as a 401, and the refresh consumed the last good link of a single-use chain — destroying a subscription the router had just minted itself. The stored token is now left alone and retried on the next tick, and when a chain does die after a self-rotation the message says this process spent it rather than blaming another holder.
- A revoked subscription is reported where a monitor is already looking (issue #318). `degraded_providers` stayed empty while a provider was revoked — it simply vanished from `data`, and absence cannot be told from "never configured here" — so the only truthful signal was a substring in an error a client saw after its request had already failed. Configured-but-unusable subscriptions are now named in `degraded_providers` with a reason.

### Changed
- `TOKEN_SECRET` is required where signing happens, not per command family. `clients list`, `clients show`, `clients doctor` and all of `tls` refuse to *start* without a secret they never use, and the check was satisfied by any value — it only taught operators to keep a deployment's signing secret exported in their shell. Worse, the relaxation was attached to "might be remote", so `--local` — the only way to state "this machine" out loud — was the spelling that broke (issue #308).
- `clients setup` mints from this machine's own token store, so it cannot follow a remote selection. It used to write this CLI's `--host`/`--port` default into a client while another router was selected, with no error; it now refuses and names `router configure` (issue #296).
- One verb per operation, with the rest kept as aliases: `tokens issue` accepts `create`/`add`, `tokens revoke` accepts `remove`/`delete`, `providers add` accepts `create`/`issue`, `clients setup` accepts `create`/`add` (issue #314). `tokens expire` is documented as the alias of `revoke` it has always been. `--token` means a credential everywhere; the log-directory selector is `--token-id`. `clients setup --base-url` is `--server`, the name the router's own URL has everywhere else.
- `--managed` is refused by the families that cannot start a container, naming `--local`. Its description promised a disposable managed container while on everything but `with` it started nothing and quietly meant `--local` (issue #315).
- `with --help` describes the default it has had since issue #277, hides the ~28 global server options that cannot affect it, marks the retired `--extend-global-config` in its first line, and reports when `--isolated-config` is a no-op for the client being launched (issue #312). Usage lines, the shared target flags and the `providers add` options say what the code does (issue #315).

### Breaking
- `auth status --clear-all` requires `--yes`. It removes five credentials in one call, on a command whose name promises a report, and an OAuth login cannot be restored without a browser.
- Options written after the client name in `router with` now reach the client instead of being claimed by the router. Move router options before the client name; `--` still works as an explicit boundary.
- `with --global` mints and stores a credential, so it needs a token for the target where it previously wrote a configuration that could not authenticate and told the user to set a variable themselves.
