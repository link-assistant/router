This separate source-only draft extends the shared descriptor and generic codec with field aliases and bare primitive field defaults. It starts from the integrated standard-body/scalar baseline `ca1de0dcce06d6fe4c40966e3a5510725b6725d4`; the verified 73-owner artifacts and 198-case evidence remain frozen. Production imports and generated artifacts are unchanged. The 15 new tests and the retained 49 source tests have not run on this draft.

Aliases come from the original checked field helpers and the pinned serde 1.0.229 attribute/identifier branches. Each spelling maps to the same canonical field slot during deserialization. Canonical plus alias, repeated alias and multiple aliases therefore share duplicate-field refusal, including null values. Serialization uses only the canonical name. Repeated aliases and an alias identical to its own canonical name are deduplicated as the original attribute set does; aliases colliding with another field are explicitly refused rather than assuming procedural derive precedence. Enum alias behavior remains unchanged.

A bare default for a checked original bool or fixed-width 8/16/32/64-bit integer field selects the actual Rust 1.89 `Default` implementation via the verified standard-body adapter. That adapter expands the original `default_impl` macro and retains original definition/invocation/expansion and complete-source identities. The production parser parses its complete body; the production checker checks the body against the field's actual primitive type. Only an actual checked literal result is admitted. The metadata retains that body/parse/type/source proof, and metadata checking re-extracts it from the private original context. No per-owner default-value table, target function body template or caller-provided proof flag is used.

The locked serde derive branches use the private core `Default` trait for missing map and sequence fields. The codec applies the source-derived value only to missing fields during deserialization. Supplied null, floats, exponent spellings, wrong booleans and overflowing integers still use the existing strict visitor checks. Serialization requires a supplied typed primitive value and never supplies a default. Local source traits named `Default` cannot alter serde's private core route; primitive type masks are still refused through the whole-file namespace checks.

String/Vec/aggregate defaults, derived or custom Default bodies, custom omission predicates, maps, floats and container defaults still require separate proofs. The complete original first-refusal ranking and exact source/pin branches are in `aliases-defaults-source-receipt.json`; a first-refusal count is not a transitive unlock prediction. Callable Serialize/Deserialize directions still require their actual independent original traits. This draft does not grant whole serde/core trait authority or native runtime parity.

Proposed first engine scope is the four schema test files: bulk (14), checked extraction (17), scalar/direction (18), aliases/defaults (15), totaling 64 cases. Node concurrency 1 then Bun with a finite 15-second authored test timeout, each engine capped at 180 seconds, with immutable source/head/input/resource receipts and both complete initial failure inventories before repairs. Actual bulk generation, freshness, strict TypeScript and retained runtime validation remain separate stages scheduled by Gate after source validation.

The initial 64-case pair ran on unchanged `c1dc6ec46`: Node and Bun each passed 55 and failed the same nine Default-dependent cases. The primitive-body checker was called without its ordinary program initialization, and its flow state was absent. All retained 49 source cases and the other six alias cases passed. Complete initial logs, actual runner/input/resource receipts, frozen plan and prerequisite hydration proof are archived losslessly in `aliases-defaults-initial-raws.tar.gz`; all eight reopened members match their original bytes. No producer, generated artifact or native import changed, and the engine slot was released before repair.
