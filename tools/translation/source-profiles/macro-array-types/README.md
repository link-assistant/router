Original declarative array and slice type fragments

Five unchanged full Rust1.89 sources and licenses are reused from retained
profiles. This loader verifies the manifest, compressed archives and original
source bytes before issuing private syntax rules. Full selected parser bodies,
source spans and original AnonConst/TyKind schemas remain recorded, including
recovery branches that the bounded fragment grammar does not admit.

The generic declarative engine can capture `[T]` and `[T; N]` when T satisfies
its existing recursively bounded type grammar and N is one unsuffixed decimal
integer token with1..20digits. Unknown const names, arithmetic, blocks, macros,
negative/suffixed/base-prefixed/float literals and parser recovery remain
refused. Accepted digits are syntax; an integer's value, target usize range,
array allocation, const evaluation and type layout are not checked or granted.
Existing depth/FOLLOW/step/output limits and opaque type forwarding are retained.

This prerequisite permits the entire original `make_MacEager!` invocation in
rustc_expand/base.rs to expand through its actual full declarative transcriber,
including all eight result slots and their original nested array types. It does
not rewrite those type arguments or synthesize a smaller invocation. Default,
constructor effects, result trait dispatch and compiler/caller namespace closure
still require independent source proofs. Namespace/layout/runtime flags stay
false. The complete five-file pure grammar cohort passes36 cases in both hosts
with original case timers and a ten-second process cap; no runtime cohort or
whole-source coverage gain is claimed.
