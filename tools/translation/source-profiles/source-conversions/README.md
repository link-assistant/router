# Original Into and From execution

The profile references five complete licensed Rust 1.89.0 source archives already retained by other profiles. Their archive and decoded byte lengths and hashes are checked without replacing any existing row. The original `Into<T>: Sized` and `From<T>: Sized` declarations, common standard/core prelude routes, blanket `Into<U> for T where U: From<T>` member, reflexive `From<T> for T` member, and `From<&str> for String` member retain full attributes, original source and coordinates.

The actual Host parser reads `U::from(self)` and the selected From body. The checker binds the original generic/parameter slots, evaluates the caller receiver once, and produces ordinary checked let/body IR. `&str` to `String` executes the original `s.to_owned()` through the existing `checked-standard-string-ownership-v1` capability. Eleven by-value fixed-integer/bool identities execute the original `t` body with the existing original Sized and generic identity proofs. No function or owner names select these routes.

The destination must be an actual checked expected `String` or matching fixed/bool type. Original caller source views, call token, active namespaces, implicit prelude, visible trait members and supertraits, anonymous imports and potentially overlapping explicit conversion impls are independent obligations. Copied or changed public source selections cannot issue body authority; serialized checked evidence must replay a privately issued complete proof and unchanged computation before emission. The project preserves proof coordinates during relocation/flattening.

Owned String identity requires a separate single-use move proof and remains refused. `From<&String>`, custom/imported/ambiguous traits, unknown item or expression macros, unresolved helper attributes, missing destination inference, nonidentity primitive conversions, pointer/floating identities and const execution remain refused. Existing direct `String::from` handling retains its separate boundary. `impl Into<String>` signatures remain original unresolved generic obligations; they are not replaced by String parameters.

The complete alloc String/str/slice and core borrow inputs retain the allocation route: str ToOwned, slice specialization, Vec allocation/copy, unchecked UTF-8 and OOM conditions. These internals are not compiled or interpreted. Using the existing checked to_owned capability does not establish allocator equivalence, unsafe behavior, OOM behavior, whole trait authority or runtime parity. All such flags remain false.

The completed original-source census has five direct Into method refusals, 38 impl Into signature refusals (29 String-bound owners and nine PathBuf-bound owners), and three separate IntoIterator refusals. Bounded unchanged whole-file tests gain the two bridge control functions `untranslatable_moderation` and `untranslatable_chat_prediction`. Their behavior is checked for missing, null and nonnull canonical JSON inputs in JavaScript and independently strict-compiled TypeScript. Other original targets retain separate borrowed-pattern, anonymous trait, namespace, formatting or Default barriers. This batch does not claim a completed whole-corpus generation or parity check.
