# Original standard container Default bodies

This profile reuses the complete, licensed Rust 1.89 sources at revision
`29483883eed69d5fb4db01964cdf2af4d86e9cb2`. Every existing gzip member remains
unchanged. The manifest validates both compressed and original byte hashes,
including the original MIT and Apache licenses; no new archive is duplicated.

`default-container-source.mjs` selects the complete original nominal declaration,
Default implementation, associated-item set, zero-argument signature, and method
body. Its private source selections retain the exact full-source spans. The
actual bodies are `String::new()`, `None`, and `Vec::new()`. Option and Vec have
the original single unconstrained `T` parameter; they require no payload Default
implementation. Source selection alone grants no namespace or execution authority.

The generated-record route first joins the genuine caller-bound compiler Default
AST output with its original declaration and derive invocation. It validates the
complete zero-parameter method and named-field calls, then parses each original
field type with the actual Host parser and the original resolved module scope.
Only an actual supported standard type selects its original Default body. Those
bodies pass through the existing ordinary parser, checker, ownership rules and
emitters. The original Option `None` body becomes the existing registered Option
constructor under the field's actual expected canonical Option type. The source
body and its unmodified parse remain in the proof.

Checked metadata uses `original-generated-container-default-ir-v1` under the
existing `router-source-generated-default-method` classification. It retains the
complete source-output proof, original plan/method identities, each original
field type and scope identity, complete pinned method selections, and parsed and
lowered bodies. These are compiler-generated methods, separate from original Rust
function and method counts. The independent draft reviewer must regenerate this
schema before accepting canonical generated output.

The focused tests execute independently specified goldens in emitted JavaScript
and separately strict-compiled TypeScript. They check fresh immutable records and
arrays, nested Option/Vec payloads without Default bounds, original caller-name
shadows, complete unchanged `ClaimFile` and `TokenUsage` sources, and copied,
mutated, rebound, shadowed, unsupported allocator and helper inputs. The actual
`DeviceErrorResponse` helper owner and AtomicU64 field route remain refused.

Allocator internals, unsafe code, whole trait translation, const execution, and
complete runtime parity remain unproved. Generic record owners, arbitrary Default
implementations, borrowed fields, custom aliases/traits/allocators and unknown
helper or namespace effects remain subject to the existing refusals. Primitive
and unit-enum Default execution retain their independent source proof paths.
