The record/control candidate interpreter can select a complete named record
declaration from a genuine pinned dependency input. Concrete values must contain
all its original fields. Record patterns require that private record and the
exact complete original inherent member body; copied schemas and changed helper
bodies cannot supply that association. This does not evaluate `Default`, resolve
field types, prove borrowing or establish a caller namespace.

The separate Host AST adapter interprets the pinned standard `matches!` rule
through the existing declarative matcher and transcriber. Original expression
and pattern captures remain private AST slots. Generated nodes have no invented
contiguous source span: their definition origins and original invocation capture
origins remain separate. Compilation is asynchronous so no Host constructor or
parser method is captured during module initialization. This route produces
candidate control only and does not resolve a package's actual macro owner.

The first original helper selected by the new tests is schemars_derive 1.2.2
`src/attr/mod.rs`, `CommonAttrs::is_default`. Its actual record pattern and guard
test every original field. Supplying a concrete documentation expression selects
the original nondefault branch. The tests do not derive that expression from
the original attributes or treat `#[schemars(with = "String")]` as a transparent
forwarding implementation.

ClientKind's complete Schemars output remains refused. Its source includes
documentation; complete doc extraction, `CommonAttrs::populate`, default and
attribute construction, `ToTokens`, `add_mutators`, complete selected quote output
and generated attribute/macro owners still need independent source joins. Its
formatting body also needs the complete original integration table initializer,
including every `service_base_path` call, plus canonical_name/integration/command
and cast/static-array proof joins. Successful ValueEnum output confinement is a
separate source output fact and supplies none of those semantic operations.
